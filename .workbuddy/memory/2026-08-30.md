## ✅ 图鉴说明两处渲染残缺定案+修复(待实测)

数据层核实:target_hex 干净(L2=15字+fe,L3=灼伤。),两处都是渲染层问题。

### 1) 行尾"灼字重影"
- **根因**:官方 AddTextPrinter 初始化写 state=1(BEGIN);慢速任务 case BEGIN
  会 Text_ClearWindow 清窗,但**快速路径(0x08002DE8 循环,图鉴说明/带边框打印)
  忽略 BEGIN 直接落打印**。上次打印残留的 tilemap 单元(行尾 col23)仍指向本次
  复用的 tile;本次"灼伤。"的灼恰好复用该 tile → 残留单元透出灼的左边像素。
- **修复**(PrintNextChar_hook.c PrintNextChar_Hook 入口):state==1 时调官方
  Text_ClearWindow 一次并转 NORMAL——补齐官方 BEGIN 语义;慢速路径已清过
  (state 已转 NORMAL)不会二次清;tm1+font4 origin 委托路径不经过此处。

### 2) 句尾句号只剩半圆("12px 经典 BUG")
- **根因**:native_via_phase 画完主列后没把**溢出列(map_tx+1)**写进 tilemap——
  startPixel≠0 时字形右半的像素写进了 VRAM 但单元格仍指空白 tile。中列后续
  字符会重映射所以只在行尾暴露;标点右半多为空白所以对话框一直没暴露。
- **修复**(FontFunc_hook.c native_via_phase chs_map_at 后):du_sp!=0 时补
  chs_map_at(map_tx+1, su, sl)。SYM 与原生 8px sp≠0 字形同路修复。

## 选项窗口「左 16px / 右 12px」机制答疑（读 bak/text-v3）

- **两边 font 都是 0（同一套 12×12 字模）**，kOptZones 四条记录的 `.font` 全为 0。
  16 与 12 的差别**不在字形，只在步进（advance）**。
- 唯一决定步进的一行 = `chs_core_ex` 的 `px += (ptr_base != 0u) ? 8u : pass2_w;`
  （pass2_w = glyphWidth-8 = 4）⇒ pass1(8) + PTR 8 = **16px**；pass1(8) + DYN 4 = **12px**。
  ⇒ PTR 每字 2 个 tilemap 列，DYN 1.5 列。
- 分区键是 **curX**：标签列 curX=4 < cx_hi=8 → PTR；候选 @15/@19/@22 → DYN
  off=0/12/22、span=12/10/10（行界 32 tile，"打到底/立体声"必须 off≤22）。
- 同步自洽性核对：`chs_sync_tilex` 与 `phase_bind` 期望式都用 `(px+adv-1)>>3`
  （adv 恒 12），PTR 下给 curTX 超前 3 列但两处同式 ⇒ 会话连续性与 tilemap
  实际落列（btx+0/+1、btx+2/+3）互不冲突。**不要动这个公式**（8-30 三次回归教训）。

### 🔎 `newline_reset` 的 `off += 2` 消费方枚举（改它之前必须先看完）
结论：**不能全局删**，它是 tm0 行间隔离。记下每种依赖：
- **A（真依赖，tm0 多行对话）**：12px pass2 的 off 推进是相位相关的
  （sp==0 → +0；sp==4 → +2）。一行以**奇数个汉字**收尾时，行末 off 比"下一
  空闲 tile"**小 2** ⇒ 下一行首字 pass1 会写进上一行末字右半所在的 tile
  （1 字行：off=2 但已用到 tile 3；3 字行：off=8 但已用到 tile 9）。+2 正好
  补这个差。偶数行时它是多余的 2 tile 间隙（无害）。
  判据与 `DrawGlyphTiles_arrow_prepare` 的 `if (chs_px & 7) off += 2` 同构——
  **半列相位才需要**。

## 18:4x 【修复完成】「类型9 → 9型9」（候选列首字被末字覆盖）

### 结论（用户实测通过）
- 16px 步进保持正常，**「类」不再被覆盖**，白边遮挡问题也随回滚消失。
- 修复只动了 2 个文件：`text_render.c`（行键延续 DYN 游标）、`text_scene.c`

### 根因（gdb 日志 25990-26075 行，判决性证据）
第 7 行「窗口」行的实际打印序列：
```
块1  InitTextPrinter(cur_x=15)  类  OFF=0x0000 curTX=0  →  型  OFF=0x0004 curTX=3   【结束时 OFF=6】
块2  InitTextPrinter(cur_x=18)  9   OFF=0x0000 curTX=0  →  0x0300 又画一次 OFF=0x0004
```
- **「类型」是 F9 汉字短语（翻译文本 `\CC050F类型`），而「9」是游戏动态生成的
  原生日文半角字符（不在翻译文本里）** → 二者是 **两个独立的 InitTextPrinter
  文本块**。
- 每个新文本块 `InitTextPrinter` 都会把 `win[0x18]`（行内 tile 偏移 off）
  **清零** ⇒ 块 2 的「9」从 `行基址 + 0` 开始画，正好是块 1「类」的 tile
  ⇒ **直接把「类」盖掉**，视觉上就成了「9型9」。
- 附带现象：`0x0300` 又画了一次（半角字符走 PcsPrint_Custom → DrawGlyphTiles，
  与全角同路径，只是没有 0x8000 标记）。

### 修法：给 DYN 游标加「行键」，跨文本块延续而不是归零
在 `text_render.c` 用 `CHS_LAST_ROW_KEY`（EWRAM `0x0203FF8C`，
`PITCH_CTRL(FF80..FF8B)` 与 `PITCH_SLOTS(FF90..FFCF)` 之间的空隙）记
**(tileBase, curY, zone_id)** 三元组：
- pitch 槽键从 `tileBase^curY<<8^curX<<4^curTY^tpl` 改成
  `tileBase^curY<<8^zone_id<<4^curTY^tpl`（`curX` 换 `zone_id`，同一 zone 内
  跨块共享同一槽）；
- 行首（chs_px==0）时：行键**未变** ⇒ 不复位 off，把 `win[0x18]` 恢复成上一块
  结束时的 `CHS_LAST_OFF`；行键**变了**（换行/换 zone）⇒ 归零重来。
- 这样块 2 的「9」从 off=6 继续，落在「型」后面，不再覆盖「类」。

## 战斗动画黑屏：首轮日志分析（20:40）

### 结论
首轮日志**没采集到放技能**——录到的是「即时存档里带过来的、已损坏的动画循环」。
证据链指向 **save state 在动画中途存/读 → EWRAM 动画状态机残留 → 脚本指针变野
→ 反复刷背景 → 黑屏**。与汉化无关（用户已确认日版即时存档也黑屏）。

### 关键证据
- `DoMoveAnim`(0x08071D98, 3 处 BL 调用点) / `LaunchBattleAnimation`(0x08071DCC, 1 处)
  **均 0 命中** ⇒ 动画在采集开始前就启动了，是存档带过来的。
- 事件时序为 142 次严格交替死循环：`loadspritegfx → waitbgfadein → loadspritegfx → changebg`
  （288 条 [ABG] 记录逐字节相同 = 状态完全冻结）。
- `sBattleAnimScriptPtr` = **0x04030201**（IO 区野指针），但 `gAnimScriptCallback` =
  0x08072048 **有效** ⇒ 状态块被**部分**踩坏，非整体未初始化。
- dump 显示 `+0x00` 与 `+0x20` 内容完全相同（都是 01 02 03 04）→ 周期性写入痕迹，
  具体来源未定位（不影响主结论）。
- 原版/汉化日志结构、比例、垃圾值完全一致。

### ★ 找到真正的脚本命令循环体：sub_08077C20
`waitbgfadein`/`changebg` 的 LR=0x08077C3E 出自这里；结构是
`取命令字节 → 查表 ldr r1,[r4] → bl 0x081B12D8(veneer: bx r1) → bne 循环`。
`0x081B12D8` 处 `4708 46C0 4710 46C0` = 编译器为函数指针表生成的 thunk，
所以全 ROM 扫不到任何 `BL ScriptCmd_changebg/waitbgfadein/setbldcnt`（均 0 处）。

### ⚠ 符号表 pokeruby_jp.sym 不可信（实证）
`08072044 l 00000040 RunAnimScriptCommand ; US=0x080759D0 UNVERIFIED(seg=RedrawMenuCursor)`
—— 段名标成 RedrawMenuCursor，给的 0x08072048 本轮 0 命中，真循环在 0x08077C20。
**验证函数地址最快法**：扫全 ROM 的 BL 调用点（有=地址对且被用；0=地址错或仅函数指针）。

### 埋点修正
- yaml 新增 `AnimScriptLoop @ 0x08077C22`（真正会命中的循环体）。
- `AnimScriptCmd` 保留 0x08072048，注释改为「符号表口径，实测常 0 命中」。
- gdb_patcher.py 新增 `_on_anim_script_loop`：三条判据
  ★野指针 / ★指针停滞×N / (软)wait=0&active=1；硬异常时 dump 0x0202F7A4+0x28。

  首命中报野指针、第 4 次报停滞；正常动画无误报。
