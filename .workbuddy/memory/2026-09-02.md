## 03:16-03:25 颜色码 BUG 治本：texts_patcher 加 IgnoredReader（源头上剥 FC 前缀）

- **权威语义澄清（bulbapedia Gen III 编码表）**：`fc 05` 是「改调色板」命令（1 参数），
  **不是颜色码**；颜色命令是 FC 0x01(文字色)/0x02(高亮)/0x03(阴影)/0x04(三色一体)。
  `fc 05 0f`(灰)/`fc 05 08`(红) 改的是调色板号。`fc 08` 是「暂停」命令。此前记忆里
  「FC=颜色码」的认知是错的。
- **IgnoredReader（texts_patcher.py）**：value 全枚举 `\CC…` 前缀，剥字节数 = 1(fc) + hex位数/2，
  不做任何命令/参数语义推断（用户明确「统一语义，都是 \CC0509 这样子，别发明第二套解析」）。
  strip 同步剥 original 文本 + original_hex 字节，保证两侧对齐；只剥行首，句中不动。
- **配置 src/util/configs/POKEMON_RUBY_AXVJ00.yaml**（⚠ 真正的导出配置源头在此，不是
  configs/translate/texts.json）：UI界面 模块 `ignored_reader` 全枚举 5 个调色板前缀
  `\CC0505`(战斗菜单)/`\CC0508`(空行占位)/`\CC0509`(设置菜单+制作表)/`\CC050E`(剧情)/`\CC050F`(选项行)。
- **YAML 坑**：单引号标量 `'\\CC0505'`（双反斜杠）会解析成 `\\CC0505`；要表示单个反斜杠须写 `'\CC0505'`。
- 验证：导出 UI界面 511 条目，行首 \CC05 前缀残留 0 条；`おそい` 的 original_hex 从

## 13:00 空格 BUG 二次修复：hook InitTextPrinter（用户拍板「还是得 hook」）
- 用户复测：`tx==0` 判据仍复现空格。根因：tx==0 是**事后间接信号**（依赖 PrintNextChar
  首字时 cursorTileX 恰为 0），在窗口复用/未重走 InitTextPrinter 场景下不可靠。用户定夺
  **必须 hook InitTextPrinter**——块边界是文本生命周期最权威的直接证据。
- **InitTextPrinter @0x08002C68 反汇编实证（capstone）**：
  - 入口 `push {r4,r5,r6,lr}` + `mov r6,sb` + `mov r5,r8` + `push {r5,r6}` = 8B 窗口。
  - 参数 r0=win, r1=text, r2=tile_base, r3=cur_x；第5参数 cur_y 在 [sp+0x18]（入口已 push
    6 寄存器后）。`strb r1,[r0,#0x1B]`(r1=0) 归零 cursorTileX；`strb r3,[r0,#0x1A]` 写 curX。
  - 0 处 BL 调用 + 0 处字地址引用 ⇒ 经 wrapper 函数指针调用（0x08002CC0/0x08002CFC 两个
    wrapper 各自 push 保 r4 后 bl 0x08002C68）。
- **hook 实现**：
  - `hooks_origin.s`：`.org InitTextPrinter` 用 `ldr r4,=InitTextPrinter_Hook; bx r4`（r4 非参数，
    破坏无碍——两个 wrapper 调用者都自 push 保 r4 且返回后重赋；⚠ armips thumb ldr **不支持
    r12** 高寄存器，报 "THUMB parameter failure"，只能 r4/r3 等低寄存器）。
  - `entry.s` InitTextPrinter_Hook 存根：重放前 8B → push {r0-r3} 保参数 → `ldr r4,[sp,#0x28]`

    重排 C 参数（thumb 禁低寄存器间 mov，须 adds）→ bl InitTextPrinter_hook_C → pop 恢复
    → `bx 0x08002C71` 跳回本体。
  - `PrintNextChar_hook.c`：新增 `chs_phase_key_from(tpl,tile_base,cur_y)`（CURSOR_TILE_Y 恒 0）
    + `chs_init_phase`（块边界复位：新 key 分配→复位；命中槽→ scene 命中且 cur_x>last_cx
    且同 zone 则续接，否则复位）+ `InitTextPrinter_hook_C`。**简化 `chs_phase_px`**：去掉 tx==0
    块首分支（上移到 hook），只留块内异常防御（cx 漂移/tx 回退）。
  - 关键：续接判据用 InitTextPrinter 的 r3(cur_x) 参数 + slot.last_cx，比 tx==0 更可靠；
