### 决策：不搬 v4 PTR 固定槽机制，复用 v7 已有的「按 curX 分字号」机制

理由：v4 的 PTR 槽表（chs_slots.inc 41 字 + scene_note_glyph per-glyph 绑定 +
两趟 refpr 落址 + RAM 传 scene_ptr_base）是侵入式大改，且「改翻译要重新生成槽表」
违背 v6 去登记化方向。当前 v7 已具备完整 16px 整格落址路径（chs_place 的
fontSize==16 分支 + V6Zone.row_tab zone 级独立行带字段），只需改数据配置即可。

   → 落址错位。加 `&& font_px==font_px` 后，字号不同 = 不同区，正确复位。

### tile 空间核算

（7×16）。标签行带 16px 每字 4 tile，最长「对话速度」4 字 = 16 tile/行。
候选 12px 相位共享 3 字（单声道/打到底/立体声）= 10 tile。

## 标题「设置」被「对话速度」覆盖 BUG 修复（2026-09-04 第二轮）

### 症状（用户截图反馈）

16+12 混排 OK 后，标题行仍撞：应显示「设置」，实际显示「对话」（= r1 标签
「对话速度」的前 2 字）。

### 根因

`v6_scene_row_index()` 把 `curY <= row_y0(3)` 一律 clamp 到行 0。标题 curY=1 与
r1 标签 curY=5（(5-3)>>1=1→行0）都映射到行 0 ⇒ 共用 `kOptLabelRowBase[0]=0x003`。
标题「设置」2 字（8 tile @0x003..0x00A）被 r1「对话速度」4 字（16 tile @0x003..0x012）
覆盖 ⇒ 标题显示成「对话」。

### 修复（v7 简单行带方案，不给标题复用 r1 行带）

1. `struct V6SceneRule` 加字段 `uint16_t title_base`（标题行专用 tile 基址，0=无标题）。
2. `kV6Scenes[0]` 设 `.title_base = 0x183u`（cb=2 空闲缝，紧跟 r6 标签带 0x173..0x182
   之后，避开全部标签/候选/引用字形/高段；标题 2 字 16px = 8 tile，0x183..0x18A 够）。
3. `v6_scene_row_base()` 顶部加：`if (cy <= r->row_y0 && r->title_base != 0u) return r->title_base;`
   （标题不再 clamp 到行 0 与 r1 撞）。

### 验证

- 反汇编确认 title_base=0x0183 已编进 kV6Scenes（.text @0x08801b50 起 `...07 00 83 01...`）。
- game.map 无 .bss/.data、无软件除法。game.bin 8052 字节（-8B：title_base 分支改了结构）。
- ⚠ 仍待实机截图确认「设置」正常显示且不与 r1 撞。

### 🔴 修正：标题/菜单行 curY 的精确值（gdb 日志实证，2026-09-04）

文档「场景特征与偏移量表.md」写「标题 curY=1、菜单行 curY=5..17 步2」是**错的**。
gdb 日志（模板@0x081BB874 段）实证 InitTextPrinter 时真实值：

| 行 | 内容 | curX | curY |
|---|---|---|---|
| 标题 | 设置 | 0 | **0** |
| r1 | 对话速度 | 4 | **1** |
| r2 | 战斗动画 | 4 | 5 |
| r3 | 对战规则 | 4 | 7 |
| r4 | 声音 | 4 | 9 |
| r5 | 按键模式 | 4 | 11 |
| r6 | 窗口 | 4 | 13 |
| r7 | 关闭 | 4 | 15 |

⚠ row_y0=3 的 clamp（cy<=3→行0）会同时吞掉标题(0)和 r1(1)——所以标题撞 r1
的根因是**两者都被 clamp 到行 0**，不是「标题=行0、r1=行1」。title_base 短路
`cy<=row_y0` 已覆盖标题；r1(curY=1) 也在 `<=row_y0` 内，但它走 label 行带而非
title_base（因为 r1 的 zone 是 label 区、title_base 只在 title 时命中——见下）。
