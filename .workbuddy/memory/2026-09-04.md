## 标题「设置」被「对话速度」覆盖 BUG 修复（2026-09-04 第二轮）

### 症状（用户截图反馈）

16+12 混排 OK 后，标题行仍撞：应显示「设置」，实际显示「对话」（= r1 标签
「对话速度」的前 2 字）。

### 根因

`v6_scene_row_index()` 把 `curY <= row_y0(3)` 一律 clamp 到行 0。标题 curY=1 与
r1 标签 curY=5（(5-3)>>1=1→行0）都映射到行 0 ⇒ 共用 `kOptLabelRowBase[0]=0x003`。

覆盖 ⇒ 标题显示成「对话」。

### 修复（v7 简单行带方案，不给标题复用 r1 行带）

1. `struct V6SceneRule` 加字段 `uint16_t title_base`（标题行专用 tile 基址，0=无标题）。
2. `kV6Scenes[0]` 设 `.title_base = 0x183u`（cb=2 空闲缝，紧跟 r6 标签带 0x173..0x182

3. `v6_scene_row_base()` 顶部加：`if (cy <= r->row_y0 && r->title_base != 0u) return r->title_base;`
   （标题不再 clamp 到行 0 与 r1 撞）。

## 动态 tile 分配器（v7）设计定稿（2026-09-04 第五轮，用户三项决策）

用户否决「避让带不该有」的旧结论，明确要**动态算法**（读 win→避让带→绕开），
三步法第 1 步「屏蔽输出」已完成。三项拍板：

1. **charBase 无直接字段**，需运行时从 REG_BGxCNT(0x04000008/0A/0C/0E) 的
   bits[3:2] 算（charBlock 号），配合 gdb_patcher 采集 + 导出避让带。且在
   PrintNextChar_Hook 加**裸透传开关**（直接 return 1 啥都不处理=连官方串都不打印）。
2. **并行**：静态表（scene_cfg）优先，未命中才走动态 v7_alloc_tile。
3. **范围**：暂只针对设置页面（自带刷新+分配紧张=理想试验田），未来推广所有窗口。

关键事实：
- 寄存器：REG_BASE=0x04000000，BG0/1/2/3CNT=+0x8/0xA/0xC/0xE，charBase=bits[3:2]<<2。
- tilemap 指针 = 窗口模板 tpl[TPL_TILEMAP]=+0x10（game.h 已有）。
- tilemap 表项存 charBase 相对号(0~1023)，物理 tile = VRAM 0x06000000 + charBase*0x4000 + tile*0x20。
- gdb_patcher：@handler 装饰器 + HANDLERS 字典 + Hook 挂断点；已有 TilesHarvester 类
  （tile 采集，导出避让带可复用）；[CFF]/[UTM] 是现有日志标记。

动态算法三条铁律：①确定性（固定起点遍历跳过占用，同输入同输出，防 v4 随机取址坑）
②权威性（避让带来自 tilemap 活引用扫描，不靠猜）③隔离性（charBase 物理分块隔离 OBJ）。
三个 v4 坑的解法：重绘幂等=确定性遍历；OBJ 精灵区=分配上界用 (REG_DISPCNT>>4)&3
截断；自画污染=打印会话开始时快照占用位图、本轮只看快照。

## 实机反馈：动态算法下 16px 失效，标题撞带未发生但标签列全 12px（2026-09-04 第八轮）

用户截图反馈：注释掉静态表强制走动态算法后，**设置页临时没有严重撞 tile**，

角缺一笔），实际是「看」字靠左相邻的 tile 已经被占、字右半部分被裁掉，但目
视是「字缺角」，本质是**16px 标签列的 tile 分配撞了**。

### 根因

注释静态表后，scene_cfg.kV6Scenes 是空表（`{ { 0 } }` + N=0）⇒ `v6_scene_lookup`
恒返 0 ⇒ `chs_print` 第 594 行 `if (rule)` 不进、字号降为默认 12px ⇒ 设置菜单所有
字符走 `print_glyph_px`（12px 相位共享路径），标签列彻底失去 16px 视觉与 16px 整
格的 tile 排序逻辑。

更深的问题：动态分配器（v7_alloc_tile）在 12px 共享路径下，按字符顺序领 tile，
每个字跨两列要领 2 tile，相邻字因相位共享可省 1 列，但**当字符多到溢出相位共享
的「3 字 10 tile」额度、phase 落到第 4 字时**就自然撞上官方/上一字。

### 修复方案

**不恢复 row_tab 静态行带，但保留 zone 配置驱动字号**：
1. 恢复 `scene_cfg.c` 的 `kV6Scenes` 规则表 + `kOptLabelRowBase`/`kOptRowBase`/
   `kOptZones` 三个数据表（zone.cx_hi/font_px 决定字号），让 `chs_print` 第 594
   行 `if (rule)` 命中 ⇒ 标签列 16px、候选列 12px。
2. **16px 整格路径解绑 `row_base`**：`chs_place` 第 545 行
   `if (fontSize == 16u && row_base != 0u)` → 改为
   `if (fontSize == 16u)`（不再绑死 row_base）；每字 `chs_place_col(win,
   tile= v7_alloc_tile(win), lower_delta=1u, ...)`，tile 号走 v7 动态分配器。
3. `chs_phase_advance(win, 16u, 0u)` —— 16px 不进入相位共享通道，cur_tile=0
   保证下一字不复用。
4. 12px（候选列）保持走 `print_glyph_px` 的相位共享 + v7_alloc_tile 动态领号，
   行为不变。

### 理论预期

- 标签列 16px 视觉恢复（每字=2 tile 独立、不跨字）。
- tile 分配压力翻倍（16px 不复用相位共享），但每字独立 tile ⇒ 不会撞 tile。
- 「字缺角」这类右侧被覆盖的视觉问题消失（独立 tile + UpdateTilemap 写每字列）。

## gdb_patcher 采集避让带工具（2026-09-04 第十轮）

用户提出两步方案：①文字打印入口加「屏蔽所有文本打印」开关；②gdb_patcher
改 handler 采集每个页面 cb 区占用 = 避让带。用于补全 v8 顺序分配器漏掉的
关闭按钮/血条/状态图标等不在文本 tilemap 扫描范围内的 UI 元素。

### 结论与改动（都在 src/util/gdb_patcher.py）

- **屏蔽开关已存在，无需新增**：`ADDR_V6_BYPASS=0x0203FEB8`（game.h），
  `PrintNextChar_Hook` 顶部 `if (*(volatile uint8_t*)ADDR_V6_BYPASS) return 1;`。
  新增 CLI `--bypass-text`：连接后写该地址=1（GDB `M` 包）。
- **采集函数 `_survey_cb_avoid`**：扫 VRAM 6 个 charblock（cb0~cb5，物理
  0x06000000 起，每 cb=0x4000=512 tile×32B 4bpp）非零 tile，输出连续占用区间。
  新增 `_cb_ranges`/`_fmt_cb_ranges` 纯函数。新增 `--cb-survey` CLI 开关。
- **触发点 = InitTextPrinter（非 UpdateTilemap）**：屏蔽开关只短路
  PrintNextChar（字符打印），不影响 InitTextPrinter 的窗口初始化 + 官方字形
  预渲染（atlas）。UpdateTilemap 在屏蔽模式下根本不命中，不能当触发点。
  `_on_init_text` 里 `if ctx.cb_survey: _survey_cb_avoid(gdb, ctx)`，内部按
  场景签名（DISPCNT+BGxCNT×4）去重，每页采一次。
- Ctx 加 `cb_survey` 参数 + `_cb_sig` 去重属性（构造点唯一 run_log）。

### 用法

```
python src/util/gdb_patcher.py log --functions InitTextPrinter --cb-survey --bypass-text
```

到目标页面（设置菜单/队伍页）操作，日志里 [CBAVOID] 段列出 cb0~cb5 占用区间。
charBase=2 主力窗的避让带 = cb2/cb3 占用区间（相对号 = 物理 tile % 512）。
