## 1. 做了什么
上一轮定死「按调用点（`lr`）作用域重做」。本轮落地为 **v20**：
- 桩依旧在 `0x081B1298`（8B 纯跳转，**吃两条蹦床**）；
- 跳板入口加一条 **`mov r2, lr`**（桩用 `bx` ⇒ lr 仍是调用者的返回地址 = 调用点）；
- C 判定 `v20_lz_ui_C(src, dst, site)`：**site 在白名单**（104 处）∩ `V18_UI_ON==0`
  ⇒ 把 `dst` 起 `size` 字节清 0（`size` 从 LZ77 头 byte1..3 解出）⇒ 返 0（不再解压）；

## 2. 归属判定怎么做的（新工具 `scripts/lz77_own.py`）
把 118 个 `bl 0x081B1298` 站点**按所属函数归组**（向前扫 `push {..,lr}` + 边界检查），
得 **40 个函数组**。这一步是必须的，因为：
- **按 dst 分不出**：`0x06000000` 上住着野外 primary tileset 与信息页美术（字节级同址）。
- **按 src 也分不出**：运行时 src = `tileset->tiles`（动态）。
  🔴 `080077DE` 与 `08008660` 静态解出**同一个假 src** `0x081BBE94`（48 砖），
  实际是 `CopyPrimary/SecondaryTilesetToVram` —— **上一轮就是被这个假 src 骗了**：
  当时数出「野外 tileset 3 处」，其实有 **7 处**
  （`080077DE`/`080077E6`、`08008660`/`08008668`、`0811039E`/`081103A6`、`0811E28A`）。

## 3. 🔴 本轮最大的认识：**文字图集不走 LZ77**（硬证据）
`MultistepLoadFont`(`0x080029E0`) 主循环只 `bl 0x08002A50`，而 `0x08002A50` 是
**按 fontNum 的跳转表**（表 @`0x08002A70`）：
font 2/3 → `0x08002AAC`（源 = ROM 常量 **`0x081B49AC`**）、
font 5 → `0x08002ACC`（源 **`0x081B51AC`**）、font 1/4 → `0x08002A8C`（用 `win[0x0C]`=tileData）。
**全程无 `bl 0x081B1298`** ⇒ 字体是 ROM 里的裸常量数组，直接交给
`0x08003830`/`0x080038A0` 绘制 ⇒ **v20 门控碰不到文字**。
（附：跳转表**项 0 从不被使用** ⇒ 日版只走 `fontNum∈{1,2,4,5}`，与 v17 的结论互证。）

## 5. 本日新增坑（**全是脚本自身**，跳板本身一直是错的判据在报假）
- 🔴 **objdump 一行的字段是 `地址: <tab> 机器码 <tab> 助记符 <tab> 操作数`**
  ⇒ `split('\t')` 后 **[0] 是机器码**，助记符在 **[1]**。首跑把 [0] 当助记符
  ⇒ 14 项判据全假 FAIL（而跳板反汇编肉眼可见是对的）。
- 🔴 **字节序**：`svc 0x12` 的半字是 `0xDF12` ⇒ 字节流是 `12 df`。
  判据写成 `tk[i]==0xDF and tk[i+1]==0x12` ⇒ 永远 0 次。
- 🔴 **`thunk_span` 不能「遇到第一个 `pop {..,pc}` 就停」**：v20 跳板有**三条出口**，
  第一条在正中间。也不能对齐到 4（多读 2 字节就吃进下一个函数的对齐填充 —— v17.2 同类）。
  正解 = 扫到**第 3 个** `pop {..,pc}`，且**不对齐**。
- 🔴 **桩字节必须从打包后的 ROM 读**：`game.bin` 只是**注入区镜像**（`0x08800000` 起），
  **不含代码区的桩**（桩由 armips patch 写到 `0x081B1298`）。
- ⚠ `apply_v20.py` 的 bat 锚点必须带 `%CC%`：`build.bat` 第 63 行的
  `echo === Compiling text\win_alloc.c` 也含 `win_alloc.c` ⇒ 裸锚点不唯一。

```

common=6931  identical=6931  differ=0      ← 前 6931 项逐字节相同
汉字段(≥0x100): common=6765 identical=6765 differ=0
```

⇒ **我们的 charmap 是 Wokann 的严格超集，零冲突，不需要任何搬移。**

## 7. Step B 架构决策（反汇编锁死）
钩点从 `PrintNextChar` **下移到 `DrawGlyphTiles+2`**：
- `InitWindowTileData` 的 fontNum 跳转表实证 `DrawGlyphTiles` 是**日版唯一变宽字形落砖入口**，
  tm0/tm1/tm2 三路都过它 ⇒ 钩点**完备**。
- `GetCursorTileNum`(`0x08003708`) 返回的是 **tilemap 项地址**（不是砖号）：
  `&tilemap[((CY+TY)<<5)+(CX+TX)]`；砖号 = `*(u16*)` 该地址。
  🔴 这正是「引擎不会和自己撞」的机制 —— 砖号是引擎**自己已写好**的值。
