## 结构：小补丁的归属（用户定的原则）

「能进主流程作为算法的进 plan，没办法的进 patches」。已落地：

- `plan["tables"][].insns` / `.literals`：由 plan 函数**算**出来（改 stride 立即数、
  改读点指令、改基址字面量）
- `plan["patches"]`：配置里声明的字节补丁（`texts["patches"]` 或
  `modules[X]["patches"]`），rows_writer 与 insns 走同一条 `.org/.byte` 通道
- 结果：`struct_trampoline.py` 里硬编码的 `0xF22CA` / `0xF22CE` 已撤掉

## 修复的 bug（都有实测证据）

1. **insns 字节序反了**：旧实现写 `bytes="68 61"`，writer 是 `.byte 0x68,0x61`
   → 半字 0x6168 = `str r0,[r5,#0x14]`，不是 `ldr`。上一版「657 条全部写入」
   的读点其实被改坏，只是场景没覆盖。现在由编码函数生成（`61 68`）。
2. **`_find_name_copy_sites`**：literal → 函数 → 精确解码 BL 找 StringCopyN
   → 回溯 `adds rX,rY,#name_off`。**不能拿 `_name_cap` 当长度判据**（它推的是
   名字+填充宽度 16，代码硬编码 5）。
3. **池头保护误伤**：`_packed_scan_pool_heads` 无条件把 range 起点当池头，
   地点名 0x3BECB7 / 道具说明 0x3984DC 自己就是要翻的文本却被拒。
   改为用 `find_ldrs` 验证「真被代码当基址加载」才保护。
4. **扫描器把串切在中间**：`FD xx xx 00 FD xx xx` 里那个 `00`（空格）被当
   串结尾，于是战斗模板 address 偏 6~10 字节 → 永无指针。手工修了 7 条。

## 新增的编码协议

`_script_cmd_ptr_ok`：非对齐脚本指针的另两种形态
- 形态 A：`<u16 命令字> 00 00 <u32 ptr>`（相位 1/2）
- 形态 B：`... 02 67 <u32 ptr>`（相位 3，命令字高字节 0x67）
条件：非对齐 + 上述结构 + **不在已登记正文 span 内**（原来非对齐分支不做 in_body 检查）
