### 用 VRAM/RAM dump 定位并修掉红块（关键）

最终验收时 `grid_verdict.py` 报 dex `neon 26441 / outside 4832`，放大看到
「妙蛙种子」后两字被纯红方块盖住、列表数字 004→012。没有靠猜常量，做了：

1. bot 的 `shot` 会落 `NNN.vram.bin / .pal.bin / .ram.bin`；解析 BG2
   （charBase=2, mapBase=14）tilemap 与 tile nibble 直方图：
   - origin 字形 tile 主色 `{0,8,1}`（透明底 + 白主墨 + 深灰阴影）
   - translated 名字前两列 `{0,1}`，后四列 **`{2,1}`** —— 整片铺了 nibble 2
   - palette bank15 index 2 = `#F80000`，确认是「整列铺 bg=2」而非 VRAM 污染
2. 给 `PrintNextChar_hook.c` 加 `-DGRID_DIAG` 环形日志（`0x0203E000`，
   128×16B，写指针 `+0x800`），`build.bat` 加 `%EXTRA_CFLAGS%` 注入口；
   `meowth build` 快路径重打包 → bot 采集 → 从 `ram.bin +0x3E000` 解码。
3. 日志结论：六场景常态 `win[0x0D] == tpl[6] == bg`（对话/选项/导航/开始菜单
   = 0x0F 白，背包/图鉴 = 0x00 透明）；只有图鉴名字后补打 PCS `0x20/0x80`
   填充字时被 FC 临时把 `win[0x0D]` 改成 **2（红）**。
   → `grid_bg()` 改为**只认 `tpl[6]`**（模板固定背景），`win[0x0D]` 仅作瞬时绘制色。
4. 再加「无墨迹字形只推进游标、不重绘 tile」：原版 tm1 空格只把表项指到预载
   空白 tile，从不改 VRAM；本引擎整列铺背景会擦掉 phase=4 共享列里汉字右半。

### P24 反汇编实证（推翻「推理直接编进 ROM」的做法）

`CreateMonName @0x0808AD44` 循环 `0808AD94~ADB8` **先写** `buf[r4]=src[r4]`、
`r4++`，再检查 `src[r4]==FF`，`0808ADB2 beq end` 见 FF 直接 break，
**FF 没被写进 buf**。原版靠 `buf[5]=FF` 兜底，中文 4 字 16B 覆盖后名字流
失去终止符 → 读穿栈垃圾 → `FC/FC/FB` + `D=2` 红填充字。
流水线已扩 `sub sp,#0x20`、两处 `cmp r4,#0x17`、stride `*24`，唯独没修 beq。
5 个调用点（AA04/AA28/AB36/ABDE/AC02）`bl` 后全部丢弃 r0，改 nop 让循环
跑满到 `r4=0x18` 无害；破折号分支 `0808ADC0` 不经过循环，不受影响。
P24：`patches/pokedex.asm` `.org 0x0808ADB2 / .dh 0x46C0`。
产物字节实测 `0x0808ADB2 = 46C0`（`.prepage.gba` 仍是 `D00F`）。
