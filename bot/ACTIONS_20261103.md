## 1. `burst` — 多帧连续采集

**问题**：旧场景基本只截 1-2 帧。单帧只能证明「某个定型帧长这样」，
证明不了**过程连续**：转场有没有错位、逐字打印有没有覆盖、菜单高亮过渡有没有残影，
这些都必须看连续帧。

**用法**：

```lua
api.burst("bt_menu", 20, 8)   -- 前缀、张数、每张间隔帧数
```

落盘名 `bt_menu_01.png … bt_menu_20.png`，进 index.csv 时按序号递增。

**为什么只出 PNG（不出 vram/ram 五件套）**：
全量 dump 每帧约 385KB（vram 96K + ram 288K + pal/io/oam），
连续 20 帧就是 7.7MB。burst 的用途是看画面演进，不是逐帧做 tile 级分析。
需要 dump 的关键帧仍旧单用 `shot`。

**实测收益**：

| 场景 | 改前 | 改后 |
|---|---|---|
| `pokemon_menu` | 17 帧 | **95 帧** |
| `bag` | 24 帧 | **144 帧** |
| `dialogue` | ~8 帧 | **87 帧** |
| `battle_full`（新增） | — | **127 帧** |

## 2. `poke` — 金手指（写实时内存）

**问题**：有些场景在现有 4 份存档里到不了（战斗/大赛/道馆），
而**换地图靠改存档是不成立的**（见 §4 实测）。

**用法**：

```lua
api.poke{ { addr = 0x03004818, width = 4, value = 0x0000AAAA, note = "钉 RNG" } }
api.poke{ { sb1 = 0x00, width = 2, value = 68, note = "pos.x" } }   -- SaveBlock1 内偏移
```

- `addr`：绝对地址；`sb1`：SaveBlock1 内偏移（推荐，跟着存档走，由 prove 定位）
- `width`：1 / 2 / 4，写后**自动复核读回值**，不一致立刻失败

### ⚠⚠ 顺序铁律（用户口径）

> 「最好是先加载 .sav 后再用金手指，否则我怕类似跟即时缓存一样
> 不会加载实时 ROM 导致汉化看不出效果。」

这条约束做成了**三道门槛**：

| # | 位置 | 条件 | 后果 |
|---|---|---|---|
| 1 | `_lib.poke()`（准备期） | 此前必须有 `prove` 步骤 | 顺序写错，**开跑前**就 assert 失败 |
| 2 | `bot.lua do_poke()`（运行时） | `SB2_RUNTIME ~= nil` | 即「存档身份字节已在 EWRAM 命中」 |
| 3 | `bot.lua do_poke()`（运行时） | `DISPCNT ∉ {0x1741, 0x3140}` | 还在标题/继续游戏菜单就拒绝 |

**为什么门槛 3 必须存在**：Gen3 在**标题画面**就已经把存档读进内存
（用于画「继续游戏」摘要），所以只看 `SB2_RUNTIME` 拦不住「还在标题就写内存」。
写早了改的是尚未被存档初始化的 EWRAM，读档时会被整个覆盖 ——
表现成「按了没反应」，更糟会写坏别的结构，让人误判成汉化有问题。

## 3. `hunt` — 遇敌搜捕

**问题**：野外遇敌是 RNG，而两侧文本打印耗时不同 ⇒ 按键落在不同帧
⇒ 遇敌判定分岔。历史上这直接把对照废掉过。

**做法**：逐格走，每帧看 `DISPCNT` 是否离开野外值 `0x7F60`；
一离开立刻停手并 `advance`，后面的采集**从战斗画面开始**。

```lua
api.hunt{ dir = "DOWN", x = 68, y = 7, steps = 40, timeout = 120 }
```

- 撞墙/走出草丛会自动**掉头**（实测只朝一个方向走 30 格全程不遇敌）
- 走满还没遇到会记 `[HUNT] gave-up`，由后续 `await` 判定是否真的进战斗

**确定性遇敌的最终配方**（实测 6 轮定下来，勿再改）：

```
prove → poke 钉 gRngValue(0x03004818) → hunt → await{any_of={0x0000,0xBF40}}
```

| 试过 | 结果 |
|---|---|
| 只钉 RNG（逐格递增） | 两侧遇敌格差 1（origin 第7格 / translated 第6格） |
| 只 hunt | translated 侧 30 格没遇到，纯随机 |
| **钉一次 RNG + hunt** | **两侧都在第 5 格（另一次第 7 格）遇敌，完全一致** ✅ |

> 为什么「差 1 格」治不掉：实测两侧写入的 RNG 值序列**逐值相同**、
> 走位坐标**逐格相同**，说明还有与帧号相关的判定参与遇敌。
> `hunt` 把这 1 格差异吸收在内部，保证后面从同一画面对齐。

## 4. 这些路试过但**不成立**（省下一轮）

| 尝试 | 结果 |
|---|---|
| 改 .sav 的 `location` 换地图 | **无效**。改完 prove 读到 `loc=10:7` 与真商店存档一模一样，画面仍是 Route118 且主角消失。原因：SaveBlock1 `+0x34` 起还有 226+ 字节「当前地图运行时数据」，地图是读档流程加载的，不是 `location` 一个字段驱动 |
| 把 `continueGameWarp` 一起改 | **更糟**：读档直接失效（那是读档落点） |
| `gWildEncountersDisabled` / `sWildEncounterImmunitySteps` | **无效**，游戏每帧重算，poke 进去立刻被覆盖 |
| 调 ROM 函数（如 `SweetScentWildEncounter`） | **做不到**。mGBA 的 Lua 绑定只有 `read8/16/32`、`readRange`、`write8/16/32`，**没有函数调用接口**；跳板改 PC 无法安全接管 |
| 改 `gWildMonHeaders` 遇敌率表 | **放弃**。实测它不是简单 (mapGroup,mapNum) 索引表：28 字节表项混着地形行为表（`0xA1A8..0xA6A2`）和指向别处的指针，结构未定死，改 ROM 有污染产物风险 |

## 4.5 ★ 金手指能做到什么、不能做到什么（2026-11-03 实测边界）

这条边界一开始没分清，导致我一度以为「图内也能瞬移」，白试了三轮。

| 操作 | 是否有效 | 实测证据 |
|---|---|---|
| 改数量/旗标/等级/道具这类**普通字段** | ✅ 有效 | 队伍、金钱、gRngValue 都写入成功且被游戏采用 |
| 写 `SaveBlock1.pos`（`sb1+0x00/0x02`） | ⚠️ **值生效，但画面不跟随** | 见下 |
| **跨图改 `mapGroup/mapNum`** | ❌ 无效 | 值改对了、`[POS]` 读对了，画面仍是旧地图、主角消失。地图要读档流程加载 |
| 调 ROM 函数 | ❌ 无接口 | mGBA Lua 只有 `read8/16/32`、`readRange`、`write8/16/32` |

### 「图内瞬移」为什么不行（这轮最重要的负面结论）

实测三步，每步都有据可查：

1. **poke 写 pos 后，值确实变了且保持住**
   `[POS] shot=px_y10 grid=(23,10)`、`pw_poke_only grid=(5,12)`、`pw_poke2_step grid=(30,12)`
   —— 日志一路跟着变，游戏没有把值改回去。

2. **但画面不动**
   `pw_poke_only`（poke 到 (5,12)）与 `pw_out`（原来 (23,17)）截图几乎逐像素相同；
   补按一次方向键后只挪了一格。角色 sprite 和相机都没跳到新位置。

3. **全 RAM 只有一处存这个坐标**
   `scripts/find_real_pos.py` 在两帧里搜 `(23,17)` 与 `(5,12)`，
   288KB 内存里**唯一共同命中**的是 `0x02025494` = `SaveBlock1+0x00`。
   ⇒ 坐标系只有一份，我改的没错；问题在于**渲染不读它**，而读某个每帧由
   走位逻辑重算的缓存。`gCamera`(0x0202E844) 实测两帧完全相同、数值也不像坐标
   —— 符号表在这块同样不可靠。

**⇒ 结论**：`poke` 能改**游戏逻辑会自己读取**的字段（数量/旗标/RNG），
但**不能瞬移**。位置移动只能靠走位。

### 那「跳场景」到底怎么做

```
换图：走位（出门/进城/进建筑）—— 实测 DOWN 穿门就能 map 10:7 → 0:2
图内定位：也只能走位
```

图内走位用 `roam`（见 §4.6），它只按方向推进、撞墙自动换向，
不依赖绝对坐标 —— 这是本轮唯一走通的方式。

## 4.6 `roam` 动作（跨图与图内走位）

```lua
api.roam{ seq = { "DOWN", "DOWN" }, steps = 8 }
```

- 只按**方向**推进，不依赖绝对格坐标 —— 因为换图会把坐标重置
  （实测 `10:7 → 0:2` 时坐标从 `(3,7)` 变成 `(23,14)`）。
- 每格读 `SaveBlock1` 坐标判断是否真的挪动；40 帧没挪 = 撞墙，自动换下一方向。
- 换图时会在日志里打 `[ROAM] map 10:7 -> 0:2 (坐标重置为 23,14)`。

> 局限：只会「撞墙换向」，不会规划绕路。遇到花坛这类障碍需要
> 手工把 `seq` 写成「先退、再侧移、再前进」的形状。

## 4.7 ⚠ 一个很贵的坑：Lua 结构错会**静默卡死**

改 `bot.lua` 时我曾误删了 `else` 分支和两个 `end`，
结果是**语法合法、模拟器不报错**，但 `stop()` 与后面几个顶层
`if` 被卷进了 `for` 循环体里 —— 表现是「mGBA 跑满超时、输出目录空空如也、
连 scene.log 都没有」，看起来像场景逻辑卡住，实际是引擎坏了。

对策：`scripts/lint_lua.py`。它除了查括号/`function-end`，还点名检查
`bot.lua` 必须存在的顶层语句（`if shots == 0 then stop(...)`、
`callbacks:add("keysRead"` 等）。改完 bot.lua 先跑它。

```powershell
python scripts/lint_lua.py bot\bot.lua bot\scenes\POKEMON_RUBY_AXVJ00\_lib.lua
```
