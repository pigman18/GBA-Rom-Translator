# 扩表与重定向算法（可直接并入流水线）

> 2026-11-04
> 目标：把「原版定长表 → 扩展区变长表 + 改访问指令」这套逻辑整理成流水线算法。
> 对应火红做法（见 `docs/research/FIRERED_SPECIES_SAVE.md`、`FIRERED_SHORT_STRINGS.md`）。
>
> 用户要求：**新区扩表、新区排列、指针修改** 三段要清晰，脚本可以零散实现但结构不能乱。

---

## 零、总体三段式

```
┌──────────────────────────────────────────────────────────────┐
│ 阶段 1：新区扩表（EXPAND）                                    │
│   输入：原表基址 + 元素数 + 旧 stride                          │
│   输出：新表布局（每项变长） + 总字节数                        │
│   约束：stride 可变，但访问指令必须同步改                      │
├──────────────────────────────────────────────────────────────┤
│ 阶段 2：新区排列（LAYOUT）                                    │
│   输入：新表布局 + 扩展区空闲起点                              │
│   输出：具体写入地址 + 每项的最终字节                          │
│   约束：4 字节对齐、不覆盖已占用区                             │
├──────────────────────────────────────────────────────────────┤
│ 阶段 3：指针修改（RELINK）                                    │
│   输入：原表基址 → 新表基址                                    │
│   输出：需要 patch 的字节位置与值                              │
│   两种形态：                                                   │
│     A. 改字面量（ldr rX,[pc,#n] 指向的 u32）                   │
│     B. 改访问指令（index×stride 的乘法常量）                   │
└──────────────────────────────────────────────────────────────┘
```

## 一、阶段 1：新区扩表（EXPAND）

### 1.1 输入

| 参数 | 说明 | 来源 |
|---|---|---|
| `base` | 原表基址（文件偏移） | ROM 实测 |
| `stride` | 旧步长 | ROM 实测（代码里 `index×stride` 的常量） |
| `n` | 元素数 | ROM 实测 |
| `name_off` | 名称字段在元素内的偏移 | ROM 实测 |
| `entries` | 每项的新译文（中文，已编码） | build.json |

### 1.2 输出布局

**两种可选布局**：

#### 布局 A：定长表（保持 stride 不变）
```
新表 = 每项固定 stride 字节，不足补 0x00
约束：中文编码长度 ≤ stride
适用：stride 够大（如 stride 16+）
```

#### 布局 B：变长表 + 指针数组（火红做法）
```
新表区 = [ 变长串区 ][ 指针数组 ]

变长串区：
  每项 = <中文编码字节> + 0xFF
  项与项首尾相接

指针数组：
  每项 = u32 指向该串在新表区内的地址
```

**布局 B 是本节重点**，因为它不受 stride 限制。

### 1.3 字节计算

```python
def expand_varlen(entries: list[bytes]) -> tuple[bytes, list[int]]:
    """把变长串拼成一块，返回 (串区字节, 每项偏移列表)。"""
    blob = b""
    offsets = []
    for body in entries:
        # body 已含 0xFF 结尾
        offsets.append(len(blob))
        blob += body
    # 4 字节对齐
    pad = (-len(blob)) % 4
    blob += b"\x00" * pad
    return blob, offsets
```

指针数组的值 = `新区基址 + len(blob) + i*4`（数组紧跟串区之后）。

### 1.4 与原版的差异对照

| 项 | 原版 | 新版 |
|---|---|---|
| 项长 | 固定 stride | 变长 |
| 项分隔 | 补 0x00 到 stride | 0xFF 结尾 |
| 访问方式 | `base + i*stride + name_off` | `ptrarr[i]` |
| 代码改动 | 无 | 必须改 |

## 二、阶段 2：新区排列（LAYOUT）

### 2.1 扩展区可用范围

```
允许区间：0x08800000 以上（armips 会把 ROM 撑到 32MB）
已占用：
  PhraseOffsets  0x08810000   （F980 移除后释放）
  PhraseTable    0x08820000   （F980 移除后释放）
  FontChsNormal  0x09000000
  SlotTable      0x09EA0000   （SLT2 移除后释放）
  game.bin       0x08800000 起，不超过 0x08810000
```

**分配策略**：
1. 从最高的已知占用点之后开始（如 `0x09F00000`）
2. 或从释放的空间开始（PhraseTable 不再用后可回收 `0x08820000`）
3. 每次分配记录到分配表，避免重叠

### 2.2 对齐规则

| 对象 | 对齐 |
|---|---|
| 变长串区 | 1 字节（无要求） |
| 指针数组 | **4 字节**（必须是 u32 数组） |
| 整体基址 | 4 字节 |

### 2.3 输出

```python
@dataclass
class ExpandedTable:
    name: str
    orig_base: int        # 原表文件偏移
    orig_stride: int
    n_items: int
    new_blob: bytes       # 串区
    new_offsets: list[int]
    ptrarr_off: int       # 指针数组相对 blob 起点的偏移
    new_base: int         # 新区基址（文件偏移），阶段 2 填
```

## 三、阶段 3：指针修改（RELINK）

### 3.1 形态 A：改字面量

**适用**：代码用 `ldr rX,[pc,#n]` 加载表基址。

```python
def patch_literal(rom: bytearray, lit_off: int, new_gba_addr: int) -> None:
    """把字面量槽改成新地址（GBA 地址，含 0x08000000）。"""
    struct.pack_into("<I", rom, lit_off, new_gba_addr)
```

**定位**：`find_ldr_refs(base_gba)` → 每个 ldr 指令的 `pc+imm` 即字面量位置。

### 3.2 形态 B：改访问指令

**适用**：代码用 `index×stride` 硬算（如 `lsls #3 / subs / lsls #2` = ×28）。

**必须做两件事**：
1. 改「乘法常量」→ 改成 `×4`（因为新表是指针数组，每项 4 字节）
2. 改「加基址的常量」→ 改成新指针数组地址

但等等——**更简单的做法**是：**保留原乘法逻辑，把新的定长表直接替换**，不改代码。

#### 决策：是否改代码？

| 情况 | 做法 | 是否改代码 |
|---|---|---|
| 新表能保持 stride（中文塞得下） | **原地换基址** | ✅ 只改字面量 |
| 新表必须变长 | 改成「读指针数组」 | ❌ 要改乘法逻辑 |

**优先选前者**：先试「保持 stride」，塞不下才升级到变长。

### 3.3 stride 塞得下吗？—— 实测答案

| 表 | stride | 中文 2 字需 | 3 字需 | 判定 |
|---|---|---|---|---|
| 招式名 | 8 | `F9 00 hi lo`×2+FF = 9B | 13B | ❌ 塞不下 2 字 |
| 特性名 | 8 | 9B | 13B | ❌ 塞不下 |
| 属性名 | 5 | 9B | 13B | ❌ 塞不下 2 字 |
| 图鉴分类名 | 28（字段 6） | 名称字段只有 6B | — | ❌ 塞不下 |
| 道具名 | 40（字段 24） | 名称字段 24B | — | ✅ 2 字 9B 塞得下 |
| 秘密基地装饰名 | 28（字段 13） | 名称字段 13B | — | ✅ 2 字 9B 塞得下 |
| 树果名 | 56（字段 56） | 56B | — | ✅ 塞得下 |

**结论**：
- `道具名`、`秘密基地装饰名`、`树果名` → **保持 stride，只改字面量**（简单）
- `招式名`、`特性名`、`属性名`、`图鉴分类名` → **必须变长 + 改代码**

## 四、可并入流水线的模块设计

```
src/meowth/
  table_expand.py      阶段 1 + 2：扩表与排列
    ├─ expand_fixed(...)      保持 stride
    ├─ expand_varlen(...)     变长 + 指针数组
    ├─ Allocator              扩展区分配器
    └─ ExpandedTable          数据结构

  table_relink.py      阶段 3：指针修改
    ├─ patch_literal(...)     改字面量
    ├─ find_ldr_refs(...)     定位字面量槽
    └─ patch_index_arith(...) 改乘法常量（变长时才用）
```

**接口约定**：
```python
# 阶段 1+2
plan = expand_varlen(name="招式名", orig_base=0x1CACFC, stride=8,
                     n=354, entries=encoded_bodies, alloc=allocator)
# 阶段 3
patches = relink(rom, plan, mode="literal")
for off, data in patches:
    rom[off:off+len(data)] = data
```
