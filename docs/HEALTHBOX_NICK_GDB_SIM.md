# 血条昵称：原理（先读懂再改）

> 配套：`pokeruby` `battle_interface.c` `sub_80451A0`  
> 日版真昵称路径：Alt2 `@0x08042408`  
> **产品补丁：P03 + P03h**（chrome 24B；OBJ 前封空列/透明）。P03c–g 已弃。

脚本 / gdb：`src/util/sim_healthbox_nick*.py`、`docs` 旧节仍可用；本文只讲**附近在干什么**。

---

## 1. 一列是什么

昵称区不是「一串字贴在窗上」，而是 **7 列 × 每列 0x40 字节** 的像素缓冲，再拷进血条 OBJ：

| 半列 | 字节 | 像素行（8×8 tile，4bpp） |
|------|------|---------------------------|
| 上半 | `col+0x00..0x1F` | row **0..7** |
| 下半 | `col+0x20..0x3F` | row **8..15** |

中文 12px 墨水主要在 **row6 起往下**；假名/符号更靠上。

缓冲基址（日版实测）：`0x02000000 + 0x520 + position*0x180`（如我方单打常见 `0x02000520`）。

---

## 2. 官方三步（顺序不能脑补反）

```
① RenderTextHandleBold(buf, str)     ← 先把整串字（含性别符）画进 7 列
② chrome：按「非控制字符」往每列上半盖 0x2B/2C/2D（CpuCopy/CpuSet）
③ （美版）pad：不足 7 列再盖 0x2B
④ 每列上/下各拷 32B → OBJ VRAM
```

要点：

- **chrome 不是「底」**，是 Render **之后**盖上去的装饰条（血条名槽顶边那一抹）。
- 盖的是 **上半 tile 的前 N 字节**，不是整列 0x40。
- 元素表：`0x0868EBE0 + id*32`。空白条 **0x2B** 实测：

```
row0..1: 全 0     → OBJ 透明（能「镂空」看见下层）
row2..4: 66/77/33 → 装饰横条（米色/青绿边）
row5..7: 底色 2   → 名槽填充
```

所以：**不会「把字全部盖掉」**——它只动上半里被拷到的那几行。  
P03 把长度从 32B（8 行）改成 **24B（6 行）**：只盖 row0..5，**故意留下 row6..7 给汉字顶**。这就是「只盖上面一小截」的物理原因，不是 chrome 失效。

---

## 3. 屏上三种「怪」各自是什么

对照你截图（直冲熊 / 火焰鸡旁的青绿块、细 `-`）：

| 现象 | 原理 |
|------|------|
| 汉字顶被压一点 / 顶上细米色线 | chrome 的 row2..4 装饰条仍在；P03 已不盖 row6..7，但装饰条本身还在名槽上方 |
| 名后大块**青绿镂空** | 该列上半有 **nibble=0（透明）**，OBJ 透出下层（草地/框底色），看起来像青绿色块 |
| 镂空里一点 **黑短横 `-`** | 多半是 **0x2B 的 row2..3 装饰横条**（`66…/77…`）残留，或性别符被 chrome 削顶后的残墨，**不是**独立「减号字符」 |
| ♂/♀ 变成糊块 / 青块 | 性别是 **Render 画的字模**；随后 chrome 按「一个字符一列」盖上半 → 符身被削/透空，只剩残片 |

镂空 ≠「chrome 没盖住字」。更常见是：

1. **该列根本没被 pad 成实心 0x2B**（见下节日版差异），上半大量 0；或  
2. **0x2B 自带透明顶两行**，即便盖了 chrome，顶上仍透。

## 4. 日版 Alt2 和美版关键差异（镂空根因候选）

美版 `sub_80451A0`：chrome 后有

```c
for (; i < 7; i++)
    CpuCopy32(GetHealthboxElementGfxPtr(0x2B), ptr + 64 * i, 32);
```

日版 Alt2（`@0x08042536` 起）反汇编：**chrome 循环次数跟字符串计量 `r8` 走，chrome 结束后直接进 OBJ 分支，没有「补满 7 列」的 pad 循环**。

后果：

- 译名变短 / F9 多字节 / 控制码计量和「列」不一致时，**右边几列可能从未盖 0x2B**；
- Render 没写到的列保持 0 → 整列透明 → 你看到的名后青绿块；
- 性别列往往仍会走 chrome（当普通 1 字节字符），于是「字还在、符右侧却是洞」。

因此：**修镂空 ≠ 再缩短 chrome**；要动的是「空列用什么填、透明 nibble 要不要封成底色 2」，且必须在 **不破坏 P03「汉字顶」** 的前提下做。此前 pad veneer / 改字库顶行 / 中途跳 OBJ 都是在没把这条链走通时硬拧，已弃。

---

## 5. P03 在链上的真实位置（保留）

| 步骤 | 原版 | P03 |
|------|------|-----|
| chrome CpuSet 长度 | 池 `0x04000008` → 32B | 池改 `06` → **24B** |
| OBJ 半列拷贝 | **同一池** 也会变 24B（BUG） | OBJ 的 LDR **改指别的仍为 08 的字面量** → 仍 32B |

只改池、不旁路 OBJ → 汉字顶永远上不了精灵（白/空条），与「chrome 盖字」不是同一现象。

---

## 6. 现网修法（P03h）

日志 `NickObjCopy`：有字列顶 `00`+`66/77`；空列（col4/5）下半全 `00` → 镂空；`66/77` → 短横。

| 列类型 | 处理 |
|--------|------|
| 下半无墨水 | 整列填 `0x22`（补洞 + 去掉短横） |
| 下半有墨水 | 仅 nibble `0→2`（封透明，保留汉字） |

挂点：Alt2 `@0x080425CC` / `@0x0804264A` → `UpdateNickInHealthbox_Hook` / `_Hook_Other`（OBJ 拷前，不搅 Render）。
