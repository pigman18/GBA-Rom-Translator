## 0. 一句话

tm1/tm3 汉字步进 12→16（整列对齐）+ 按字形共享槽（原生 `base+2×字符码` 模型的
LRU 化）+ 扩带（cb2+cb3 实测空闲区）+ 构建期逐场景字形预算 + 引用感知淘汰。

## 1. 替换 bug 的根因链（全部有日志实证，勿再推测）

1. **逐格分配在数学上装不下**：详情页 155 可见格 × ≥2 tile = 310 > 旧带 224。
   实测 3254 条 UTM：112 个 tile **全部**被多格复用（3046 次），111/112 跨行。
2. **复用从带耗尽点开始**：unique-tile 曲线在 ~110 次写入处到顶（=带容量），
   之后每个新字形必然复用还被指着的 tile → 旧格显示新字形。
3. **零清理累积**：游戏切页/重渲染从不调 Text_ClearWindow（两轮采集 0 次命中）。
   旧页表项滞留 → 扫描可用面逐页收缩 → 越切越乱。
4. **首次进来正常的原因**：进场景时 tilemap 被场景初始化重写（带清空）+
   首屏"新 tile 写像素 + 新表项"同步落地；早期复用多为设计内 t-2 spill 合成
   （相邻格共享、像素同步合成），视觉正确。
5. **方向不对称是感知问题**：机制上中文踩占 91%（12px 字形 4 tile 写入面积大），
   但 8px 踩中文格 = 完整可读假名/数字（被识别为"日文替换中文"）；12px 踩数字格
   = 半字碎片（被识别为"花屏"）。另 font4 直通窗/原生渲染窗（如 win=0x03004170
   的 u=0xD5 base+212 写入）像素在原生图集 [0,0x100)，**结构上免疫**。
6. **官方不替换的本质**：槽位 = `base+2×字符码` 直接寻址数组，容量=全字符集，
   窗口创建时一次性预留——没有查找/淘汰/溢出。文本自产自销、字符集已知。

## 2. 已验证的 VRAM 占用图（27 次场景勘验，gdb_patcher --vram-survey）

cb2（charBase=2，0x06008000-0x0600BFFF）：

| 区间 | 占用 |
|---|---|
| [0x000,0x100) | 场景自加载字库（原生表项指向） |
| [0x100,0x1C8] | **自由带 201 tile**（0x1C9-0x1DF 与场景映射重叠，旧 hi=0x1DF 是错的） |
| [0x1C9,0x1F7] | 场景映射（详情页等） |
| [0x1E0,0x1FF] | ▶/UI 图标章（0x1E0/0x1E1 = 菜单游标对） |
| [0x1F8,0x1FF] | 勘验全零，未计入 |

cb3（0x0600C000-0x0600FFFF，charBase=2 窗口的 index 0x200-0x3FF 可达）：

| 区块 | 字节 | 状态 |
|---|---|---|
| 块 0-3（tiles 0x200-0x27F） | 0x0600C000-0x0600CFFF | **部分占用**：菜单图形 refs 到 0x263；详情页仅 refs 0x200-0x207（4 tile） |
| **块 4-7（tiles 0x280-0x2FF）** | 0x0600D000-0x0600DFFF | **全部 27 次勘验恒零、零引用——硬空带 128 tile** |
| 块 8-15（0x0600E000-0x0600FFFF） | — | **tilemap 本体**（多场景 screenBase 28-31 落在此），禁用 |

其他勘验结论：所有已测场景**无任何层用 charBase=3**；全部 mode 0。
详情页上块 1-3（tiles 0x220-0x27F，96 tile）额外空闲。

**扩带方案**：保守集 = [0x100,0x1C8] ∪ [0x280,0x2FF] = **329 tile**（跨场景安全）；
详情页宽集 = +[0x220,0x27F] = **425 tile**。

## 3. 12px 与字形缓存的几何不相容（勿再尝试 12px 缓存）

- 12px 步进 + 16px 容器 ⇒ 相邻汉字重叠 4px ⇒ 相位 4 的列 = [前一字 px8-11 |
  后一字 px0-3] **混合列**，内容取决于相邻两字形组合，**不可按单字形缓存**。
- 已否决的方案（勿重推）：相位变体槽（削前字右缘=间距 bug）、6-tile 三变体槽
  （L/R0/R4 ≈ 380 tile > 329，且混合列仍无解）、边沿预合成、混合列挂前字槽位。
- **结论：按字形共享必须整列步进（8 的倍数）**。密度换可缓存性是数学对立：
  12px 省的那一列正是共享列，共享列进不了缓存。

## 4. 路线 B 设计（B1：tm1/tm3 步进 16px）

### 4.1 步进
- tm1/tm3 的 CHS 步进 12→16：每字恰好 2 整列（现成 phase-0 渲染形态，字模不改）。
  JP 保持 8px（1 列）。全流整列对齐 ⇒ **相位恒 0**。
- tm0（对话/战斗线性光栅）保持 12px 不动——替换场景全在 tm1/tm3，tm0 无此病。
- 退役：ChsPhase/PhaseBind/PhaseKey/spill 链/t-2 链/0x0203FF90 表。游标直接用
  win[0x1B] 整数列推进（CHS +2、JP +1），与原生 writer 完全同构。
- 产品代价：tm1/tm3 每行汉字容量 -25%，**逐字段需验证溢出**（菜单项/字段名短，
  风险集中在背包物品名等长字段）。

### 4.2 字形槽
- 槽 = [meta][g0..g3]（CHS 5 tile）/ [meta][g0,g1]（JP 3 tile）；meta = {u16 id,
  u16 gen} 存 VRAM 自证；id：CHS=0x8000|gidx，JP=(fontNum<<8)|code。
- 16px 下无相位 ⇒ id 不需相位位（旧设计的 bit14 相位位作废）。
- 查找：扫 meta（VRAM u16 读）；未命中 = 栈上合成整槽写入 + meta 最后写；
  LRU 按 gen（计数器 @0x0203FF82，u16，pitch 安全区）。
- 表项：colA ← slot+1/+2，colB ← slot+3/+4（JP 只写 colA）——列公式即原生
  win[0x1B] 整数推进，无 tx0/px 折算。

### 4.3 构建期逐场景字形预算（硬保证，官方"内容出厂即知"的等价物）
- 译文静态（meowth 产出）⇒ 每场景显示的字形集合可计算。
- 打包前统计逐场景译文去重字形数，对照槽池容量验证；超标场景改用字（同义替换）。
- 实测量级：菜单 ~15、详情页 ~70、背包 ~40-60 不同字形；
  槽池：保守带 (201+128)/5 ≈ 65 槽、详情页宽集 425/5 = 85 槽。

### 4.4 引用感知淘汰（运行时保险丝）
- 淘汰前扫 tilemap（全层扫描代码已在 2026-08-26 版写就，可复用）：只淘汰
  **无可见引用**的槽；全部被引用才 LRU 强制。
- 效果：场景字形数在预算内时，淘汰永不碰可见格；真超容时优先踩不可见格。

### 4.5 容量总账（详情页最坏场景）
- 工作集实测 ~70 字形：CHS 50×5 + JP 20×3 = 310 ≤ 保守 329（紧）/ 宽集 425（余 115）。
- 建议：详情页族用宽集，其余场景保守集；或统一宽集 + 战斗补勘验后放开。

## 5. 已否决路线（防绕回头路）

| 路线 | 死因 |
|---|---|
| 12px + 相位变体缓存 | 混合列削前字右缘（间距 bug），几何不可缓存 |
| 12px + 6-tile 三变体 | ~380 > 329 且混合列仍无解 |
| 8px 半宽 CHS（B2） | 字库重做 + 可读性差（保留为备选，未否决） |
| 逐格分配 + 扩带（路线 A） | 单页 310 ≤ 329 可行但余量 19，滞留累积侵蚀，不根治（可作为 B1 前的临时验证步） |
| 全局游标 / 扫描定隙各版 | 时间差断链窗口不可消除（六轮实证） |
| cb3 全开 | 块 0-3 菜单图形、块 8-15 tilemap 本体，必须避开 |
