# POKEMON_RUBY_AXVJ00 · 总览

> 日版红宝石 3.0（AXVJ00）汉化工程。构建/打包/调试的通用命令见 `../通用/00-工程手册.md`。

## 1. 一句话现状

- **引擎**：`F7 00` 双字节汉字 + 12px 自绘，全 ROM 只有一个文本入口——`PrintNextChar@0x080032F8` 整函数接管。
- **渲染**：`textMode 0` 已线性落址（战斗/菜单/招式正常）；`textMode 3` 的存档框数字乱码（BUG-9）**已修**（回绕行存储列改按需折半区）。
- **数据**：`translate/texts.json` **27 模块 / 12,193 条**；注入 8,141 条。
- **产物**：32MB，静态验收 19 PASS / 1 FAIL（`Small ink 8x8`，非运行故障）。

## 3. 未修 / 待办

1. ~~**BUG-10**：出招画面撕裂/底部黑带~~ → **已修（11-23）**。
   真根因是**两侧遭遇的不是同一只宝可梦**（origin enemy=338 / translated enemy=288，
   等级都是 26），所有战斗帧不可比。修法：金手指写死敌方 `species`，
   `gBattleMons` 实测地址 `0x020247E0`（符号表的 `0x02024A80` 差 `0x2A0`，不可用），
   `species` 在 `+0x00`、`level` 在 `+0x2A`，结构 `0x58` B/battler。
   **必须写两次**（转场中那次会被初始化覆盖，进菜单后那次才生效）。
   验收：4/4 帧物种一致，敌方名字区逐像素 diff = 0。
2. ~~**BUG-11**：存档确认句第一行右侧多出残字~~ → **已修（11-23）**。
   行尾 5 格旧表项未清 + 「现」字的拆分 tile 落在那批槽上。
   修法：`grid_clear_row_tail()` 在 `0xFE` 时清「光标右侧连续指向公式区」的表项。
   8 场景回归零变化。
3. **BUG-12**（新，未修）：汉化版**敌方血条的名字栏**是破碎日文残字 + 绿色涂块，
   而对话框里名字正确。⇒ 血条名走的是与对话框**不同的表**。
   已用写死 species 前后两版采集交叉验证，与 BUG-10 无关。
4. **BUG-13**（未修）：队伍列表 5 只宝可梦名全是日文（`fontNum=4`/Small）。
   已实测定位链路（GDB `InitTextPrinter`，win=`0x03004170`：fontNum=4、textMode=1、
   charBase=1、文本在 IWRAM 栈缓冲），但**三条路线都失败**：
   取源函数 `0x0803B11C` 命中 0 次；字符流换源致输入停摆；入口改 r1 致崩溃
   （`0x464E` 是 `mov r6,r9`，我误读成 `mov r9,r1`）。详见 `30-问题与验证.md`。
5. **BUG-14**（未修，方案已调研）：名字写进存档导致串档乱码。
   Gen3 名字字段定长（`nickname[10]`/`playerName[8]`），中文 3 字 = 12B 塞不下。
   火红式解法：显示与存档解耦（改指针不改原表，存档永远写原版编码）。
   见 `docs/通用/名字存档兼容调研.md`。
6. **BUG-6 日文残留**：玩家名（存档内，主菜单显示 `1?4`）、领航员标题/底部——用户已定「暂缓」。
7. **摘要页状态行**：显示「在 101号状态遇到」，「道路」二字缺失（运行时拼接串，`\FD` 占位换地名）。
8. **领航员训练家之眼右列**：名字前有残留笔画（与 BUG-6 同源，暂缓）。
9. 地点名/训练家名扫描边界各漏 1 条尾巴（低危）。
10. `Small ink 8x8` 验收项：需确认 8px 小字库本征高 8 是否符合设计。
