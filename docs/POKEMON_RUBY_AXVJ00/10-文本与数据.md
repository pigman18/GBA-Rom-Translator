## 2. 注入模型

| 模型 | 何时 | 做法 |
|---|---|---|
| `replace` | 原槽装得下 | 就地覆写，补 `FF` |
| `relocate` | 装不下 | 串搬进扩展区（产品尾部 `0x0941xxxx`），**改掉所有指向它的指针** |
| 定长名表 | 名表 | 按 stride 逐槽覆写 |
| 结构表 | 道具名/图鉴分类名/训练家个人名 | 名字槽就地折成 u32 指针（`struct_trampoline`），**不扩 stride** |
| 指针表 | 性格名/华丽大赛名/UI-详情页 | 改指针 → 新串 |

**硬约束**：① 指针改写要覆盖全部指向点，漏一处即一处日文；② 定长 `memcpy` 调用点必须与串长一起扩，否则 F7 串被截断、无 `FF`、打印跑飞。

## 4. 结构体表：为什么是「折指针」不是「扩 stride」

- 道具名行 `entry_size=40`，名字 `@0`，**`+0x1C` 起是图标/属性字节**；图鉴分类名行 `28`，名字 `@6`，后面也有非文本字段。
- 扩 stride 会压到这些字段 → 数据写坏、图形异常（A2.8 事故）。
- 现行：`struct_trampoline` 在原名字槽写 u32 指针，把**读点**改成 `ldr+跳板`
  （`_mov_reg_after()` 处理「`adds rD,rLit,rIdx` 后还有 `adds rX,rD,#0`」的站点，避免把寄存器改成字符串指针）。
- 整表搬走时改基址字面量，必须遍历**全部**乘法站点；符号执行器 `thumb_symexec` 覆盖率仅 ~45%，不能作唯一依据。

实测（本次打包）14 张表重写：属性名 5→17、宝可梦名 6→24、招式名 8→32、训练家名 11→44、
训练家个人名（名槽 4..8 存 u32，拷贝 5B→21B）、秘密基地 28→48、道具名 redirect、招式说明 56→112、
图鉴分类名 redirect + 名字折址、对战塔 64、属性わざ 7→33。

## 5. 物种名：昵称槽 6B 是硬限

- Gen3 结构 `nickname[10]` 定长，中文 3 字 = 12B 塞不下；第 3 字写半个 → 残字。
- 把上限 5→13 只会把残渣也搬进来（实测「落雷 ゝ乱」）。
- 正确做法：**显示与存档解耦**——存档仍写 nickname，显示时按 species 查新表。

| 位置 | 实现 |
|---|---|
| 战斗血条名 | `GetMonData(mon,11)` → `0x09EB0AF4 + species*24`（`NickFullName_entry.s`，P10） |
| 遭遇「野生的XXX」 | 替换 `0x0811C7AA` 的 `GetMonData(mon,2,sp)`（`NickSlot_entry.s`，P12，tramp `0x081B504C`） |

## 6. 背包列表

- 日版算法本身不闪；中文网格下行与行共享公式空间会互相覆盖。
- 现行：仅背包列表模板 `0x081BB544` 启用「Y≥18 / col≥26 不写」裁切；12px 本征 tile 被占时只推进不写。
- 禁止：全局 `clear_cols`、缩短译文、Linear 硬套背包。
