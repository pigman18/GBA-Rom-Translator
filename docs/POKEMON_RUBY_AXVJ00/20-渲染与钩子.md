# POKEMON_RUBY_AXVJ00 · 渲染与钩子

> 引擎：`hook/src/text/PrintNextChar_hook.c` + `include/game.h`、`include/text_grid.h`。
> 原理层（tile 归属、12px 为什么占 4 tile）见 `../通用/10-GBA文本渲染原理.md`。

---

## 1. 接管（P01）

```asm
.org PrintNextChar            ; 0x080032F8
    ldr r1, =(JP2CHS_Entry | 1)
    bx  r1
.pool
```

只覆盖 8 字节；`0x08003300` 起保持原样。返回契约：可印=1 / `FF`=0 / `FA·FB·FD·FE`=2 / `FC`=子结果。
**全 ROM 只有这一处文本 hook**。

## 2. TextPrinter 字段（`win`）

| 偏移 | 宏 | 含义 |
|---|---|---|
| 0x00 | `WIN_TEMPLATE` | 模板指针 |
| 0x04 | `WIN_STATE` | 状态机 |
| 0x09 | `WIN_DELAY` | `FC 08` 节拍 |
| 0x0A | `WIN_TEXTMODE` | **落址分派键** |
| 0x0B | `WIN_FONTNUM_REAL` | 字号（2/4 → 8px，其余 12px） |
| 0x0C/0D/0E | `WIN_COLOR_C/D/E` | 三色（D = 背景） |
| 0x10 | `WIN_TEXT_PTR` | 字符流指针 |
| 0x14 | `WIN_TEXT_INDEX` | 已消费字节 |
| 0x16 | `WIN_TILE_BASE` | tile 基号 |
| 0x18 | `WIN_TILE_OFFSET` | 线性偏移 |
| 0x1A/1B | `CURSOR_X` / `CURSOR_TILE_X` | 列 |
| 0x1C/1D | `CURSOR_Y` / `CURSOR_TILE_Y` | 行（tile 单位） |
| 0x20 | `WIN_TILE_DATA` | 缓冲直绘（tm2） |

模板：`+0x0C` = tileData，`+0x10` = tilemap（NULL = 缓冲直绘）。

## 3. textMode 分派

| tm | 行为 | 落址 | 现状 |
|---|---|---|---|
| 0 | 自绘 | `TB + TILE_OFFSET`，每字 +2 | ✅ 已修 |

| 3 | 自绘 | 同网格 | ❌ BUG-9 |

## 6. 已证伪（不要重试）

| 方案 | 原因 |
|---|---|
| 换 charBase / 文本私有 block | 游戏按绝对 `0x06008000` 解压图形；`BG2CNT` 全程只写 6 次 |
| 只改模板 `tileData` | 三要素必须一致 |
| 按字符 glyph 缓存 | 与纯函数网格互斥，容量也不够 |
| 段模型抬水位 / 改段宽 | row 是累计行号，16~18 行×31 列装不下 |
| 8+4 / 4+8 双遍渲染 | 单遍已够；用户明确「复刻落址不复刻渲染」 |
| 全局 `clear_cols` / 全局 `bg=0` | 清别的窗、tip 透底 |

## 7. 构建侧注意

- `build.bat` 前跑 evidence gate；`findstr` 需要 PATH 含 `System32`。
- `SummaryScreen_PrintTrainerMemo_hook.c`、`PokeNav_TrainerEye_FormatListLine_hook.c` 必须 `-O1`（`-O2` 会把循环证成死循环）。
- `out/game_syms.asm` 正常应为 16 行（15 符号）；只有表头说明 `findstr` 挂了。
