### BUG-9 已知事实

- 窗参数 origin/translated 一致（`textMode=3 fontNum=3 TILE_BASE=1 tilemap=0x0600F800`）。
- 字节流正确、字模取对，但屏幕 tile 是汉字笔画；诊断显示 `grid_pair_store` 写的是纯背景，**之后被另一条路径改写**。
- `2*col` 是行间隔离机制，不是 bug（改 `step=1` 会撞行，已实测回滚）。

**三条候选**：① 给 8px 单独 band；② 查 `grid_pair_store` 之后的第二条写入路径；③ **数字也走 F7（10 个槽位）**——代价最小。

## 2. 验收铁律

1. 逐字读出内容；墨量/像素统计/ASCII 降采样不算。
2. 修复前后绑 ROM SHA256，旧截图作废。
3. 用户说「不算修好」就是没修好，不用统计反驳。

## 3. 采集流程（`bot/run.py`）

```powershell
python bot\run.py POKEMON_RUBY_AXVJ00 start_menu `
  --save bot\scenes\POKEMON_RUBY_AXVJ00\saves\Route118_68-7.sav `
  --gdb InitTextPrinter --timeout 120
```

1. 两侧同一 `.sav`（自动 131088→131072 对齐）。
2. **读档证明**：两侧 `pos` 一致才继续。
3. 逐帧截图 + VRAM/tilemap dump，帧对齐后写 `manifest.json`（含 ROM SHA）。

**本次实测（2026-11-23，新产物）**：`start_menu` 56 帧对、两侧 GDB 各 47 命中、
`[PROVE] pos=(68,7)` 一致。逐字读图：主菜单 8 项对 7 项（图鉴/宝可梦/背包/领航员/`1?4`/▶保存/设置/退出），
第 5 项玩家名仍是 BUG-6 残字，字形清晰不撞框。

## 5. 回归清单与判据

每次改引擎至少跑：`start_menu`、`dex`、`bag`、`options`、`navigator`、`battle_dialog`、`save`。

| 判据 | 阈值 |
|---|---|
| 战斗对话正文行（BG0 y=3..4）表项数 | 12±2 |
| 图鉴跨行重复 tile | 只允许 `0x1FC/0x1FD` |
| 存档框 info 区像素 md5 | origin == translated（**仍需逐字读图**） |
| HP 区 `x168..172` md5 | 与 origin 全等 |
