## 1. 编号规则（实测确认，别再搞错）

**`species = lexicon/图鉴.json 里该名字的索引 + 1`**

用哨兵法验证（把遇敌表 12 槽全改成 species=1，游戏里显示「妙蛙种子」）：

| 中文名 | 图鉴.json 索引 | species 值 | 实测显示 |
|---|---|---|---|
| 妙蛙种子 | 0 | **1** | ✅ 妙蛙种子 |
| 多刺菊石兽 | 138 | **139** | ✅ 多刺菊石兽 |
| 咕咕 | 162 | **163** | ✅ 咕咕 |

**不是 +25！** 之前误用 `索引+25` 的算法，测「负电拍拍」时用的是 314，那测的根本不是目标物种，导致整批结论作废。

## 3. 中文名长度分布（决定血条占几格）

血条名字区 7 格 × 8px = 56px，汉字 pitch 10px，性别符号 8px：

| 字数 | 只数 | 占用 | 是否够用 |
|---|---|---|---|
| 2 字 | 61 | 20+8=28px | ✅ |
| 3 字 | 648 | 30+8=38px | ✅ |
| 4 字 | 270 | 40+8=48px | ✅ |
| 5 字 | 46 | 50+8=58px | ⚠ 超 2px，靠补满 7 格 + 抹预载 Lv 解决 |

**1..386 内共有 9 只 5 字名**（最高风险，必须逐个看）：
```
082 三合一磁怪   139 多刺菊石兽   214 赫拉克罗斯   306 波士可多拉
329 超音波幼虫   331 刺球仙人掌   332 梦歌仙人掌   379 雷吉斯奇鲁
386 代欧奇希斯
```

## 4. 固定遇敌的正确做法（踩过坑，别再重写）

**不要自己 pack 遇敌表**，直接调官方工具：

```bash
python scripts/encounter/fix_encounter.py apply --species <N> --rom <ps1> <ps2>
```

槽结构（`scripts/encounter/fix_encounter.py:38` 权威定义）：
```c
struct WildPokemon { u8 minLevel; u8 maxLevel; u16 species; };  // 4B
```
- `+0` minLevel、`+1` maxLevel、`+2..3` species

**踩过的坑**：我曾按 `struct '<HH'` 读，把 species 写到 `+0`，结果产物里 species 变成 3084，
采集出来的 40 张图全是存档里原有的几种野生（走路草/蛇纹熊…），被误判为「字体错乱」。
官方工具自带写后读回校验，不会犯这个错。

**配套场景**：`battle_scent`（香甜气息强制遇敌）。其头注写明原理：
12 槽同物种 ⇒ `ChooseWildMonIndex_Land()` 无论 RNG 落哪 12 档都一样，随机性被消灭。

**两侧都要打**：origin 与 translated 必须打同一份补丁，否则对照不成立。

## 5. 采集与验收流程

```bash
# ① 建编号表（幂等，随时可重跑）
python scripts/verify/build_species_index.py

# ② 全量采集（自动调 fix_encounter + battle_scent，逐只记录）
python scripts/verify/sweep_species.py --start 1 --end 386

# ③ 自动审查（墨迹率 + 边框完整性）
python scripts/verify/audit_sweep.py --report work/_audit.json

# ④ 子代理逐字读图（铁律：墨迹统计证明不了字对）
python scripts/verify/prep_review_batches.py --size 40
#    然后把 work/_review/bNN/ 逐批交给子代理

# ⑤ 拼总览大图
python scripts/verify/make_pokedex_sheet.py --cols 10 --end 386
```

产出：`work/POKEMON_RUBY_AXVJ00/sweep/<sid>/{origin,translated}.png` + `index.json`

## 6. 血条「Lv」显示规格（2026-11-26 定案）

用户方案：去掉冒号，让 Lv 顶上冒号位置，原本 Lv 那格显示空白。

| 实现 | 位置 |
|---|---|
| 冒号元素换成 Lv 图案 | `hook/patches/lv_healthbox.asm`，ROM `0x0868F120` 32B |
| 抹我方预载 Lv | `NickFullName_entry.s` hook C，刷 VRAM `0x06010900`（tile 72） |
| 抹敌方预载 Lv | `NickFullName_entry.s` hook D，刷 VRAM `0x060111E0`（tile 143） |

**关键实测**：tile72/143 从不出现于 `CpuSetObj` 日志 ⇒ 是血条精灵 LZ 预载图，
ROM 里按 32B/20B 各种切分搜不到 ⇒ 纯数据补丁改不到，只能运行时刷 VRAM。

**踩过的坑**：往「名字缓冲 cell6 的 up 片」写 0x22 会盖掉 row0/1 应有的透明，
导致框线上边框被顶出缺口（用户实测「蘑菇状凸起 + 横向断层」）。
正确做法是直接刷目标格 VRAM，绝不碰名字缓冲与装饰。
