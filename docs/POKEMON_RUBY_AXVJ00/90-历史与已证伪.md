## 3. AXVJ 特有的踩坑（方法教训）

| 案例 | 错在哪 | 正确做法 |
|---|---|---|
| 图鉴分类名后缀 `？？？？？ポケモン` | 没看 origin 就给译文加「宝可梦」、去 nop 占位串打印——两样都是改协议/改原版流程 | 先认清「后半截是占位符的尾巴」再决定是否加 hook |
| BUG-C 第一版「墨量 605>561 判 PASS」 | 墨量证明不了字对（用户截图「战消/背筐/羽跑」） | 逐字读图 |
| BUG-C 连改 3 轮推进逻辑 | 没先查清 `TILE_OFFSET` 语义（与 cursorTileX 关系、换行、多 Init 重置、空格占位） | 先答四问，一次性改 |
| A2.8 改 stride 只改第一个 `ldr` | 黑屏 | 遍历全部乘法站点；`thumb_symexec` 45% 覆盖不可靠 |
| 函数名当事实 | `0x080EC2E0` 旧名 PrintLeftStats 实为地点打印；`0x080EB9C0` 叫 PrintLocation 却 flag=2 空转 | 反汇编 + RAM 实测 |
| 信符号表 `DISPROVED` | `0x08004290` 被标 GetExtCtrlCodeLength，反汇编是 `StringCopyN(上限5)` | 反汇编复核 |
