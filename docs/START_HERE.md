# START_HERE — 每次会话启动必读

> 目的：一页判断树 + 自检，防止重演 2026-08-18 红框 BUG 的教训
> （连续两晚在符号表/反汇编/指针表上绕 4 小时，用户一句话 + 字节搜索几分钟就定案）。
> 上游文档：`docs/复盘_20260818_红框调试过程与问题.md`、`docs/DONT.md`、`AGENTS.md`。

## 0. 先回答三个问题再动手

1. **用户刚才/上一条指令说了什么路径？** 复述给用户确认，一字不改地照做。
2. **这个任务属于哪一类？**（见下方判断树）—— 选错类 = 选错第一动作 = 重演失败。
3. **我现在的动作是用户在要求的，还是我自己的惯性？** 惯性（翻符号表、抓 GDB、
   反汇编猜函数）出现时，停下来先问一句。

## 1. 任务分类判断树（第一动作，没有之一）

```
任务来了
├─ 用户明确给了路径？ ────────────────→ 直接照做，先复述确认
│   例：「直接搜字节」「先读源码」「先查符号表」「跑一下打包命令」
│
├─ 「数据被写坏 / 图形异常」类？ ──────→ 第一动作 = origin-vs-output 逐字节比对 + 特征字节搜索
│   （红框残、花屏、精灵图被译文盖掉、某区域字节和原版不同）
│   · 用 `src/util/tiles_patcher.py` 的 `probe_data`（支持直接/LZ77 解压后搜特征字节）
│   · 用 `python` 逐字节 diff 定位**到底哪些字节、哪个地址带被改**
│   · ⛔ 符号表/反汇编在这里是补充，不是替代；先搜字节再谈函数
│
├─ 「改游戏内函数/常量地址」类？ ──────→ 第一动作 = 查权威符号表 pokeruby.sym（见 AGENTS.md 定位纪律）
│
├─ 「文本/UI 行为」类？ ───────────────→ 第一动作 = 读 hook/src + tools/pokeruby/src 源码
│   ⛔ 禁止上来就 grep 符号表/反汇编
│
└─ 其他（打包、构建、测试） ───────────→ 按 AGENTS.md Build Rules
```

## 2. 自检清单（动手前过一遍）

- [ ] 我已复述用户要求的路径，用户没异议？
- [ ] 我是否又要打开符号表/反汇编？—— 若是，问：这是"函数/常量定位"任务吗？不是就关掉。
- [ ] 我是否又要抓 GDB/dump？—— 若是，问：用户允许了吗？我能说出函数名+写入路径+可证伪假设了吗？
- [ ] 数据被写坏类：我是否已做过 origin vs output 逐字节比对？没有就先做这个。
- [ ] 我是否在死循环同一个点超过 ~15 分钟？是 → 停下来，把已知事实和矛盾点列给用户，
      让用户指方向，而不是继续自转。

## 3. 红框 BUG 最终结论（不要再花时间）

- 根因：红框是**精灵图**（OAM sprite），不是文字渲染也不是按坐标画色。
  - 精灵图数据：GBA `0x087EF4B8`，4bpp 64×32 ×1，lz77_swap（249→1024B）
  - 调色板：`0x087EF450`（3 banks）
  - 指针源：`0x08397534`（嵌在误提取区 `0x083973xx–0x083975xx` 内）
- 修复：误提取的 9 条「剧情」文本加入 `config.json` reject 后红框正常（用户已实测）。
- 详情见 `docs/复盘_20260818_红框调试过程与问题.md` 七/八/九节。

## 4. 两个活生生的反面教材（本仓库真实发生）

1. 用户说「直接搜 ROM」→ 我 grep 符号表找 `gMenuSummaryGfx`、拿超 ROM 范围的地址做
   LZ 解压、分析指针表变量。用户自己 `probe_data` 一把命中。**搜字节 ≠ 找符号。**
2. 用户说「先读源码」→ 我上来就翻 pokeruby.sym。**读源码 ≠ 查符号表。**

## 5. 失败模式速查（如果我又开始犯）

| 症状 | 真问题 | 纠正 |
|------|--------|------|
| 一直在 grep/反汇编，没碰字节 | 把「定位纪律」误套到数据类任务 | 回判断树：数据写坏 → 先比对/搜字节 |
| 抓 GDB/dump 抓出一坨数据 | 把「抓数据」当推进 | 先读源码锁死一条写入路径再抓（DONT#10） |
| 死循环同一矛盾点多次提问 | 没顺用户指引 | 复述已知事实给用户，让用户指方向 |
| 用户明确给了路径还改方案 | 把用户路径当「可选项」 | 一字不改照做，先复述确认 |
