## 二、为什么这 4 张表改不动

### 2.1 它们是结构体，不是纯名字表

`scripts/research/ruby/audit_table_meta.py` 按 ROM 字节独立核实：

| 表 | stride | meta 字节 | 类型 |
|---|---|---|---|
| 图鉴分类名 | 28 | 16 | STRUCT_META（含指针） |
| 道具名 | 40 | 31 | STRUCT_META（9 项含指针） |
| 秘密基地装饰名 | 28 | 5 | STRUCT_META |
| 树果名 | 28 | 18 | STRUCT_META（42 项含指针） |

### 2.2 名字放不下的实测数字

| 表 | 名字区容量 | 能放下的译文 | 中位长度 | 最长 |
|---|---|---|---|---|
| 道具名 | 9 B | **13 / 281** | 17 B | 29 B |
| 图鉴分类名 | 6 B | **43 / 386** | 9 B | 17 B |
| 秘密基地装饰名 | 10 B | **11 / 120** | 17 B | 29 B |
| 树果名 | 10 B | 9 / 21 | 13 B | 13 B |

中文 2 字 = `f7 00 hi lo` ×2 + FF = 9 B，刚好等于道具名槽宽；但 281 条译文里只有 13 条是 2 字。

### 2.3 扩 stride 会砸坏字段偏移（背包卡死的根因）

道具表原 entry 40 B：

```
+00..+08  名字 8B + FF        (usable = 9)
+0A       u16                 ← 080A53B4 ldrh r0,[r1,#0xa]
+0C       u16                 ← 080A53D8 ldrh r0,[r1,#0xc]
+0E       u8                  ← 080A53FC ldrb r0,[r1,#0xe]
+0F       u8                  ← 080A5420 ldrb r0,[r1,#0xf]
+10       ▸ 说明文本指针       ← 080A5432 adds r4,#0x10
+14..+17  u8 ×4               ← 080A546C/5490/54B4/54D8
+18       ▸ 指针              ← 080A54EA adds r4,#0x18
+1C       u16                 ← 080A5524 ldrb r0,[r1,#0x1c]
+20       u32                 ← 080A5536 adds r4,#0x20
```

**14 个访问函数全部使用硬编码偏移。** 早期版本把 stride 从 40 扩到 80，
元数据整体后移 40 B，游戏按老偏移读 `+0x10` 得到 `FF FF FF FF` 当指针用
⇒ 背包直接卡死（实测 `[ERR] 输入回调停摆 fr=7946 last_tick=4945`）。

### 2.4 stride 40→48 的可行性核查

`scripts/research/ruby/check_item_offsets.py` 逐点验证：

| 访问点 | 原偏移 | 新偏移 | 改法 |
|---|---|---|---|
| 080A53B4 ldrh | 0x0A | 0x12 | 改立即数 ✓ |
| 080A53D8 ldrh | 0x0C | 0x14 | 改立即数 ✓ |
| 080A53FC ldrb | 0x0E | 0x16 | 改立即数 ✓ |
| 080A5420 ldrb | 0x0F | 0x17 | 改立即数 ✓ |
| 080A5432 adds r4 | 0x10 | 0x18 | 改立即数 ✓ |
| 080A546C ldrb | 0x14 | 0x1C | 改立即数 ✓ |
| 080A5490 ldrb | 0x15 | 0x1D | 改立即数 ✓ |
| 080A54B4 ldrb | 0x16 | 0x1E | 改立即数 ✓ |
| 080A54D8 ldrb | 0x17 | 0x1F | 改立即数 ✓ |
| 080A54EA adds r4 | 0x18 | 0x20 | 改立即数 ✓ |
| **080A5524 ldrb** | **0x1C** | **0x24** | **✗ 超 Thumb ldrb 5 位上限 31** |
| 080A5536 adds r4 | 0x20 | 0x28 | 改立即数 ✓ |

**12 处里 11 处可以原地改，只剩 1 处卡住。**

### 2.5 为什么这一处没有干净解法

- `ldrb` 的 5 位立即数上限是 31，`0x24 = 36` 放不下；
- `0x080A5524` 前后是 `adds r1,r1,r4`（2B）和 `pop {r4}`（2B），没有 2 字节空隙插 `adds r1,#8`；
- 代码段内找不到 ≥16 B 的空洞放 trampoline 桩（扫描 `0x0A5000..0x0A6000` 无连续空区）；
- `ldr rX,[pc,#imm]` 的 reach 只有 ±1 KB，桩必须落在 `0x080A5200..0x080A5600`，该段全是满的；
- `bl` 的 ±16 MB reach 也够不到 `0x09F00000`（距离约 31.8 MB）。

### 2.6 `CopyItemName` 不是道具名的读取函数（已排除）

`CopyItemName @ 0x080A5798` 一度被我当作「EWRAM 副本」的证据，实测**不成立**：

```
080A57AE  ldr  r1, [pc, #0x44]      ; → 0x0A56E0 = 0x03004A50
080A57B0  lsls r0, r4, #2
080A57B2  adds r0, r0, r4
080A57B4  lsls r0, r0, #3           ; ×40
080A57B6  adds r1, #0x12
080A57BA  mov  r0, sp               ; ┐
080A57BE  ldrh r0, [r2]             ; │ 循环 3 次
080A57C0  strb r0, [r1]             ; │ 每次读 2B、存 1B
080A57C6  cmp  r3, #3               ; │ 共取 6 字节
080A57C8  ble  0x80a57ba            ; ┘
```

- 读的是 `+0x12` 起的 **6 字节**（3 × u16 各取低字节），不是道具名字段（`+0x00..+0x08`）；
- 结构上不是「取名字字符串」，而是「取一份 6 字节的短标识」；
- `0x03004A50` **不是**道具表在 EWRAM 的副本基址。

⇒ **「道具表 EWRAM 副本」这条退路不存在**，必须正面解决 stride 问题。

### 2.7 `+0x1C` 字段有 3 个访问点，不是 1 个

`0x080A56B0` 附近还有第二组 ×40，**写**的就是那个卡住的字段：

```
080A56B4  ldr  r2, [pc, #0x28]      ; → 0x0A56E0
080A56B6  lsls r1, r0, #2
080A56B8  adds r1, r1, r0
080A56BA  lsls r1, r1, #3           ; ×40
080A56BC  adds r1, r1, r2
080A56BE  strh r4, [r1, #0x1c]      ; ★ 写 +0x1C
080A56C0  lsls r1, r4, #2           ; ★ 第二组
080A56C2  adds r1, r1, r4
080A56C4  lsls r1, r1, #3           ; ×40
080A56C6  adds r1, r1, r2
080A56C8  strh r0, [r1, #0x1c]      ; ★ 再写 +0x1C
```

⇒ `+0x1C` 是 u16，有 **1 读 + 2 写**共 3 个访问点，全部要一起改。

## 三、路线判定

| 路线 | 可行性 | 结论 |
|---|---|---|
| A. 扩 stride 40→48 + 改偏移 | 11 处可直接改；`+0x1C` 字段 3 个访问点需一起解决 | **最有希望，卡在 `+0x1C`** |
| B. 整表换「指针数组 + 变长串」（火红做法） | 每个访问点都要加一层解引用，改动面比 A 更大 | 不优于 A |
| C. hook 拦截名字读取 | 名字没有独立 getter，也没有名字指针 | 需自建映射 |
| D. 改 EWRAM 副本 | **已排除**（§2.6 `CopyItemName` 读的不是道具名） | ✗ |

**下一步**：集中解决 `+0x1C` 的 3 个访问点，其余 11 处直接改。
一旦 `+0x1C` 有解，道具名这条路就通了，同样的方法可套用到另外 3 张结构体表。
