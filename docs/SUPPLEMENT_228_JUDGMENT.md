## 二、Q_C：音效标签（Ｃ类）会不会显示？

**会显示，但玩家正常流程看不到。**

这是决定性证据（`texts_67`/`texts_68`）。`0x3A575B` 起的整片内容：

```
0x3A575B  '… サウンドチェック'              ← 标题：Sound Check（音效检查）
0x3A57A5  'ＢＧＭ'   0x3A57A9  'ＳＥ '
0x3A57AD  'Ａ‥さいせい Ｂ‥おわり'          ← 操作提示：A=播放 B=结束
0x3A57BA  'Ｌ‥ＵＰ Ｒ‥ＤＯＷＮ'
0x3A57C6  'Ｒ‥ＤＲＩＶＥＲーＴＥＳＴ'
0x3A57FB  'ＶＯＩＣＥ‥‥‥‥'
0x3A5805  'ＶＯＬＵＭＥ‥‥‥'
0x3A580F  'ＰＡＮＰＯＴ‥‥‥'
0x3A5819  'ＰＩＴＣＨ‥‥‥‥'
0x3A5823  'ＬＥＮＧＴＨ‥‥‥'
0x3A5837  'ＰＲＯＧＲＥＳＳ‥'
0x3A5841  'ＣＨＯＲＵＳ‥‥‥'
0x3A584B  'ＰＲＩＯＲＩＴＹ‥'
0x3A5855  'さいせいちゆう‥'
0x3A585E  'はんてん‥‥‥‥'   ← 反転
0x3A5867  'すてれお‥‥‥‥'   ← ステレオ
```

后面跟着的 `ＴＥＴＳＵＪＩ`/`ＦＩＥＬＤ１３`/`ＫＡＣＨＩ２２`/`ＤＯＯＲＯーＸ１`/`ＦＡＮＦＡ１`
全是**音频资源名**（音轨/音效文件名）。

**判定**：这是宝可梦系列经典的 **Sound Check 调试菜单**（标题画面特定按键组合进入的隐藏功能）。
- 它会**显示在屏幕上**（是菜单）
- 但**玩家正常流程走不到**
- 参数名是音频工程术语（`ＰＡＮＰＯＴ` = 声像电位器、`ＣＨＯＲＵＳ` = 合唱效果器）

**我的建议**：**C 类 17 条不翻译，也不建模块**，理由：
1. 玩家不可达，翻了没人看到
2. 术语翻译成本高、易错（把 `ＰＡＮＰＯＴ` 翻成「声像罐」就闹笑话）
3. 留着不影响任何可见文本

若你的目标是「完整汉化连调试菜单都翻」，那需要单独建 `调试-SoundCheck` 模块，
**但那不该和 UI-符号单位混在一起**。

> 补充：`texts_66` 曾试图用「指针是否成片」判它是否上屏，**这个判据无效**——
> 战斗台词（确定上屏）的指针也在连续数组里。已作废，正确判据是「看那片内容的语义标题」。

## 三、Q_B：B 类 76 条该并进哪里？

### 3.1 与 `训练家个人名` 的关系

**地址零重叠**（`texts_65`）：

```
训练家个人名 地址: 0x081C5058..0x081CA338
B 类地址:         0x083E93B5..0x083EAF9C
```

完全不同的 ROM 区段，不是同一个表。

### 3.2 内容有 12 条重复

```
0x083E9640 'ユウキ'   → 训练家个人名 + 训练家名
0x083E9658 'ハルカ'   → 训练家个人名 + 训练家名
0x083EAA72 'ヒロミ'   → 训练家个人名
0x083EABC7 'ミクリ'   → 训练家个人名
0x083EABCB 'ダイゴ'   → 训练家个人名
0x083EABCF 'トウキ'   → 训练家个人名
0x083EABD3 'ナギ'     → 训练家个人名
0x083EABD6 'フヨウ'   → 训练家个人名
0x083EABDA 'プリム'   → 训练家个人名
0x083EADFE 'どく'     → 属性名
0x083EAE0C 'こおり'   → 属性名
0x083EAE93 'キモリ'   → 宝可梦名
```

12/76 会变成重复条目。**但其余 64 条是独有的**。

### 3.3 B 类的语义构成（不是「人名」一类）

| 子类 | 条数 | 样本 |
|---|---:|---|
| 人名 | 32 | `ルビー` `アクア` `マグマ` `ユウキ` `ヒトシ` `ハルカ` `アイコ` `マキコ` |
| 其它 | 31 | `なし` `Ｎｏ．` `Ｌｖ` `おりる` `のみ` `かたさ` `かたい` `からい` |
| 颜色 | 7 | `あか` `あお` `きいろ` `みどり` `くろ` `しろ` `ピンク` |
| 称呼后缀 | 3 | `さま` `くん` `ちゃん` |
| 动作词 | 3 | `つかう` `すてる` `みる` |

**「其它」31 条最多**，里面混着「なし/Ｎｏ．/Ｌｖ」这类 UI 词和「かたさ/かたい/からい」这类
**风味描述词**（宝可梦华丽大赛/树果口味系统用的）。

### 3.4 我的判断：**不建议并进 `训练家个人名`**

理由：
1. `0x3E9xxx` 这片是**混合词库**（人名 + 颜色 + 口味 + UI 词），不是训练家名表
2. 并进去会造成 12 条重复，且语义混乱——`かたい`（硬）混在训练家名里没有道理
3. `训练家个人名` 是 `struct` 定长表（`entry_size=32`），B 类是松散 scan 条目，
   **塞进去会破坏表的几何假设**

**建议**：建 `UI-通用词` 模块，收 B 类 76 条 + E 类 8 条 + F 类 4 条 + G 类里适合的部分。
若你真想让人名也翻，那 32 条人名可以**单独**并进 `训练家个人名`（接受 9 条重复），
但颜色/口味/称呼后缀不该进去。

## 四、A 类：比你说的更复杂

你说 A 类 64 条是「完整战斗台词」。实测 69 条里：

**真战斗台词（约 55 条）**，格式完整、有控制码、有标点：
```
0x083DA6E5  '\10の \17で\n\0Eは ねむってしまった！'
0x083DA94A  '\0Cは\n\10に メロメロだ！'
0x083DAC99  'しかし \10が\nさわいでいて ねむれなかった！'
0x083DB2AB  '\0Cの \11は\nマジックコートに はねかえされた！'
```

**非战斗台词（约 14 条）**：
```
0x083D4441  '\CC0101\CC020F\CC0308'   ← 纯控制码
0x083D75B8  'さばく'                   ← 地名
0x083DA4E6  'は\n'                     ← 碎片
0x083DB351  '\13は \10には\n\00'       ← 截断
```

**建议**：A 类进 `战斗提示` 模块，但**先把那 14 条非台词剔除**，
或者交给审查员单独判一次。
