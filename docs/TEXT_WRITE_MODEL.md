# 文本写入模型（唯一模型，2026-11-11 定稿）

## 0. 一条禁语：不许再说「放不下」

ROM 已按 **32MB** 补齐（`rom_writer`），表区 `0x1EB0000 – 0x1F00000` = **320KB**，
当前 13 张表只占 **127KB**（cursor `0x1ECF2E8`）。
所以「放不下」这句话本身没有信息量，必须改写成下面两条之一：

| 真实约束 | 必须给出的实数 |
|---|---|
| **读端常量不接受** | 常量所在地址 + 原值 + 语义（拷贝长度 / 栈缓冲 / 循环上限） |
| **RAM 结构守恒** | 结构体 RAM 基址 + 元素大小 + 引用该基址的字面量处数 |

两条都不是「空间」问题，而是「补丁点数」问题。

## 1. 三种布局 + 固定写入规则

| 布局 | 定义 | 写入规则 | 读端 |
|---|---|---|---|
| **等长** `fixed` | 子块定长，不足补 `00` | `new_stride = max(编码长度) + pad`；逐条写；尾部 `00` 填满 | 按 `base + i*stride` 取址 |
| **等距** `delimited` | 子块变长，块间固定 **N** 个分隔字节 | 逐条写；每条后补固定 N 字节的分隔符 | 顺序扫描到分隔符 |
| **混合** `mixed` | 数据块中间夹代码块 / 别的数据结构 | **先剥离**：把代码块原样搬到新区尾部，数据塌成等长或等距；再按前三列规则写 | 同前 + 搬走的代码块要重定向其入口 |

三者可以互相转换：

```
mixed --剥离--> fixed | delimited
delimited --最长的补齐到 max--> fixed
fixed --去掉填充--> delimited（不推荐，反而多一次约定）
```

**结论：只要能算出 `max(编码长度)`，任何表都能用等长布局写。**
「等距」只在**不能动 stride**（读端索引常量只出现一次、或者根本不是乘法）
而又需要变长时才有价值。实际项目里 13 张表全是等长，一条 `delimited` 都没用到。

## 2. 「改读取方式」只有 4 个动作

| # | 动作 | 形态 | 适用 |
|---|---|---|---|
| ① | 索引常量 | `lsls #n` / `movs #n + muls` | 等长表，stride 变了必改 |
| ② | 栈窗口 | `sub sp` / `strb 0xFF,[sp+#k]` / 拷贝上限 `cmp` | 名字先拷到栈再打印的函数 |
| ③ | 字段偏移 | `field_map` 重排克隆 | 名字在结构体中间、后面还跟着字段 |
| ④ | 间接层 | 名槽存 u32 指针，读点 `adds`→`ldr` 或 8B 跳板 | **RAM 结构不能变大**、或 stride 改不动 |

①②③ 是「把新区按老办法读，只是尺子变长」；④ 是「换一种读法」。
④ 的代价最低时优先：它让**数据布局与 RAM 结构解耦**。

## 3. 现有产出归属

| 产物 | 条数 | 布局 | 读端 |
|---|---|---|---|
| `tables[]`（13 张表） | 13 | 等长（含 2 张 ③ 重排） | ①②③④ |
| `rows[]` | 6924 | 等长（单条字符串，长度由 `FF` 定界） | — |
| `redirects[]` cluster | 733 | 等距（`FF` 分隔的串簇） | — |
| `redirects[]` inplace | 4 | 等长（原地，不超原槽） | — |

`rows` / `redirects` 之所以「不需要补丁」，是因为它们的读端本来就是
**按指针取 + 扫到 `FF`**，长度天然可变 —— 这正是「等距」布局的通用读法。
**所有定长表之所以要补丁，只是因为它们的读端被写成了「按 stride 取」。**

## 4. 对战塔训练家表：按模型走，只有两条路

事实：`0x39DF50`，60 条 × 64B，名槽 `+2` 共 11B，后面还有第二个短名和队伍数据。
`0x080A9DF8` 处 `movs r2,#64 / bl memcpy` 把整条 64B 拷进 RAM `0x0203826C`，
该 RAM 基址有 **66 处**字面量引用。

| 方案 | 布局 | 代价 | 判定 |
|---|---|---|---|
| A. stride 64→128 | 等长 | RAM 结构也要 128B → 66 处引用 + 所有 `+k` 偏移全改 | ❌ 不划算 |
| B. 名槽改 u32 指针 | 等长（stride 不动）+ ④ | RAM 仍 64B，66 处引用 **0 改动**；只需改「读 RAM+2 当字符串」的那一处 | ✅ 选它 |

B 的具体步骤（未做）：
1. 定位打印点：谁把 `RAM+2` 当字符串读（`0x0203826C` 的 66 个引用里筛 `+2`/`+0x42`…）。
2. 该点若连续可写 ≥8 字节 → 写 `ldr r3,[pc]; bx r3` + 字面量，跳板到 table 区，
   跳板内 `ldr r0,[r0]` 解引用后回原流程。
3. 若 <8 字节 → 找同函数内可搬迁的等长窗口（等长布局的「滑移」），把 8 字节挪过去再跳回。
4. ROM 侧：新表 stride 仍 64，名槽 4B 存指针，名字进字符串池（等距）。

之前反复卡住的真因：**一直想走 A**（在 ROM 侧扩 stride），A 撞 RAM 守恒是必然的，
不是 ROM 空间不够。B 一直没做，是因为把「原地 2 字节改」当成了唯一补丁形态。

## 5. 教训（写下来免得再犯）

1. 先问「这块数据的读取契约是什么」（stride / 分隔符 / 指针），再决定布局；
   不要一上来就想「扩 stride」。
2. 结构体后面跟着别的数据时，**默认走 ④**，而不是拆字段（③ 只用于字段少、
   且读点集中在一处的偶发情况）。
3. 任何「不行 / 放不下 / 装不下」的结论，必须附上 §0 的两条实数之一，
   否则不算结论。
