# 常规 UI 装载点全表（`bl LZ77UnCompVram` / `LZ77UnCompWram`）

> 生成：`python scripts/gen_ui_lz_sites_doc.py`（数据现算，不手抄）
> 背景：用户实测 v18 后判定「接管的 UI 目前好像只有对话框那种 UI，常规 UI 都没接管到」，
> 并指出「不需要单一 hook 点啊，本来就是多个点申请 tile」。
> 本文是该判断的**机器级答复**：把「多个申请点」一个不漏地列出来。

## 0. 三条硬结论

1. **收敛层确实存在**：`LZ77UnCompVram`(0x081B1298, `svc 0x12; bx lr`) 与
   `LZ77UnCompWram`(0x081B129C, `svc 0x11; bx lr`) 是全游戏「LZ77→内存」的唯一一对蹦床。
   原盘实测：`bl 0x081B1298` **118** 处、`bl 0x081B129C` **42** 处，其中
   目标落在 VRAM 的有 **103** 处（下表）。
2. 🔴 **但收敛层不能当总闸**：`0x06000000` 上**同时**住着野外 primary tileset 与信息页美术 ——
   `0811E28A src=0x087F9D0C(512砖) → 0x06000000`（野外）与
   `080791BA src=0x0836D268(312砖) → 0x06000000`（信息页）**落点字节级同一地址**。
   ⇒ 「按 dst 落 VRAM 就清 0」必然连地图一起清。这也正是 `docs/UI_HOOK_SURVEY.md`
   §4 方案② 被预先判死的理由（v19 违反此判，已撤，见 §4）。
3. ⇒ **只能按「调用点」作用域**（桩用 `bx` 不改 `lr`，进跳板时 `lr` = 调用者的返回地址）。
   也就是：一个桩架在 `0x081B1298`，配一张**已逐个核对过函数归属的站点白名单**。
   ✅ **已实施为 v20**（2026-09-12）：104 处纳入 / 14 处排除 —— 见 §5。
4. 🔴 **野外 tileset 的装载点有 7 处，不是 3 处**：`080077DE`/`080077E6`/`08008660`/`08008668`
   这 4 处的 src 静态解出的是**假值**（运行时换成 `tileset->tiles`）⇒ 按 src 找会漏掉它们。
   ⇒ 必须用 `scripts/lz77_own.py` **按函数归组**排除（118 站点 → 40 个函数组）。

## 4. v19 的撤销记录（2026-09-12）

v19 把总闸架在 `0x081B1298`，判据 = 「dst 落 VRAM 就清 0」。静态复核 24 项全过，
**但判据本身错**：本表 §1 已证明它会清掉野外 tileset。已用 `scripts/revert_v19.py`
精确撤销，`game.bin` 回到 **11548 B**、`verify_v17_static.py` 全过、
`_translated.gba` 注入区与 build 逐字节相同（sha1 `1f6b26460fe3`）。

教训（与 v17 的 `v8_frame_room` 同源）：**判据「能自证」≠ 判据「对」**。
静态复核只能证明「我实现了我想实现的」，证明不了「我想实现的是对的」。

## 5. ✅ 已实施：v20（2026-09-12）

§5 原来写的是「下一步」。**已落地**，做法与当时的计划一致：

1. **跳板改造**：入口加 `mov r2, lr`（`bx` 进桩 ⇒ `lr` 未被改写 = 调用者返回地址），
   转交 `v20_lz_ui_C(src, dst, site)`。三态返回：`0`=已清空 / `1`=`svc 0x12` / `2`=`svc 0x11`。
2. **白名单逐个核过函数归属**后写入 —— 由 `scripts/gen_lz_ui_sites.py` 生成
   `hook/include/lz_ui_sites.h`，**104 处纳入 / 14 处排除**，排除表带理由。
3. `0x06008000/0x0600C000`（cb2/cb3）那组**不是假名图集**：查证见下。

| `0x0813E020` | 1 | 孤立函数、src/dst 均解不出 ⇒ 无法判定归属，保守排除 |

### 5.2 🔴 「误伤 cb2/cb3 会让文字消失」这个担心**不成立**（实证）

`MultistepLoadFont`(`0x080029E0`) 的主循环只 `bl 0x08002A50`，而 `0x08002A50` 是
**按 fontNum 的跳转表**（表 @`0x08002A70`；**项 0 从不被使用** ⇒ 日版只走 `fontNum∈{1,2,4,5}`）：

| fontNum | 分支 | 图集源 |
|---|---|---|
| 2, 3 | `0x08002AAC` | **`0x081B49AC`**（ROM 裸常量） |
| 5 | `0x08002ACC` | **`0x081B51AC`**（ROM 裸常量） |
| 1, 4 | `0x08002A8C` | `win[0x0C]` = tileData |

**全程没有 `bl 0x081B1298`** ⇒ 字体图集**不走 LZ77**，是 ROM 里的裸常量数组直接交给
`0x08003830`/`0x080038A0` 绘制 ⇒ **门控 LZ 站点碰不到文字**。
