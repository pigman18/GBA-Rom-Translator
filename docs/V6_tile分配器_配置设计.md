# V6 tile 分配器：配置设计

> 2026-09-01。总结 v4 方案在设置界面的验证结论，收敛成一套「场景规则表」配置。
> 本文回答「为什么引入 tile 分配器」+「配置长什么样」，是后续实现与调整的规格书。

---

## 1. 为什么引入 tile 分配器

**来源：设置界面（选项菜单，模板 `0x081BB874`）。**

这个页面有两个特征，逼着必须有一个「tile 分配器」：

1. **高频刷新**：选项页稳态是「每数帧重绘同一 7 格行」，gdb 实测 297 轮不停
   （`场景特征与偏移量表.md` §五）。每轮都重新走一遍「写 tile data + 写 tilemap」。
2. **几乎排满的 tile**：cb=2 自由带只有 `[0x100, 0x1C8]` 约 200 tile，设置菜单
   7 行 key + value 就要几十个字（16px 字 4 tile / 12px 字 2 tile）。

官方引擎没有「分配 → 回收」机制（它假设字模预渲染常驻 VRAM），`TILE_OFFSET`
每行清零 ⇒ 所有行复用同一批 tile ⇒ 行间替换。所以必须自己引入一个分配器来
决定「这个字写进哪个 tile 号」，这就是 tile 分配器的由来。

> 更完整的根因见 `结论_替换BUG真正难点_空闲tile不可知.md`：病灶不是「写屏幕
> 位置」，而是「tile 号从哪来」——而「哪块 tile 空着」在日版引擎里物理上不可知。

---

## 2. v4 已验证结论

设置界面经 v4 实现后，**「16px key + 12px value 混排 + 自定义 tile 号」能刚好
满足页面正常显示**。这是本文配置结构的唯一事实依据，不是猜测：

| 要素 | v4 做法 | 效果 |
|---|---|---|
| 分字号 | key 标签 16px / value 候选 12px | 省 tile（value 用 12px） |
| 自定义 tile 号 | `kOptRows[7]` 每行固定基址（0x33/0x8D/…） | 每行独占一段，行间不互覆 |
| 行内偏移 | `(px>>3)*2`（px 是行内像素游标） | 同字同位置同 tile → 重绘幂等、不闪 |
| 每行上限 | `kOptRowSpans[7]`（32；关闭按钮 0） | 行内不越界 |
| 行内分区 | `kOptZones[]` 按 curX 分段（off+span） | 同行的 key/多个候选互不覆盖 |

**关键：`row_base + (px>>3)*2` 这个「确定性排列」才是核心**——它让同一个字符
每次重绘都落到同一个 tile，官方高亮代码才能覆盖到正确的 tile，闪烁和替换才消失。
「自定义 tile 号」就是 row_base，只是它是写死的常量（gdb 实测挑的空闲区间）。

## 3. 三步流程（配置的推导）

把 v4 的实践抽象成三步，每一步对应一个配置字段：

1. **查 cb1/cb2/cb3 的已有占用内容** —— 用 gdb 测出官方在哪个 charBase 上、
   哪些 tile 区间已经被引用（字形/场景映射/UI 图标）。这些是「雷区」，
   分配器绝不能碰。
2. **安排空闲的 tile 存放** —— 在避开占用区的前提下，给每行指定一段 tile
   区间作为行基址（或让算法自动找）。
3. **中间留距离支持颜色码** —— 相邻候选（选中态/未选中态、不同 PCS 颜色码）
   之间要有 tile 间距，避免不同颜色的字共享同一 tile 导致上色互相污染。

---

## 4. 配置结构

一个窗口（win 模板）一条配置：

```
win地址    窗口模板地址（tpl，唯一键）
避让带    gdb 测出的「官方已占用」tile 区间，分配器跳过，防止误用
间距      行内候选之间 / 每行之间的 tile 间距（有默认值）
tile号    每行 tile 号；为空 → 算法自动计算；非空 → 领取指定 tile
样式      curX < 8  → fontSize = 16px
          curX >= 8 → fontSize = 12px
```

字段语义展开：

| 字段 | 类型 | 语义 | 备注 |
|---|---|---|---|
| `win地址` | u32 | 窗口模板地址 = 唯一键 | 同 `tpl` |
| `避让带` | 区间数组 | 官方占用的 tile 段（`[lo,hi)`） | gdb 测出记录；默认空 |
| `间距` | u8 | 每行/行内候选间隔的 tile 数 | **有默认值**（如 32） |
| `tile号` | u16 数组 | 每行 tile 号 | **空 → 算法算；非空 → 直接领** |
| `样式` | 分区数组 | `curX` → 字号（16/12） | `<8 → 16px；>=8 → 12px` |

### 4.1 避让带（第 1 步的产物）

gdb 测出的官方占用区间，硬编码进配置，分配器（高水位/算法）分配时跳过这些段。
当前已知（`场景特征与偏移量表.md` §四，cb=2）：

```
[0x000,0x100)  场景自加载字库
[0x100,0x1C8]  自由带（可分配）
[0x1C9,0x1F7]  场景映射（避开）
[0x1E0,0x1FF]  ▶/UI 图标章（避开）
```

cb=1 / cb=0 也有各自的占用带（队伍窗 / 弹窗），见 `场景特征与偏移量表.md` §四。
**新窗口接入时，先用 gdb 采一次占用，补进避让带。**

### 4.2 tile号（第 2 步的产物）

- **非空**：写死值（v4 `kOptRows` 实测），直接领取——这是当前已验证的路径。
- **空**：算法自动算（基于避让带找空闲区间）——这是后续目标，先把「非空」
  路径跑通、底层分配稳定，再实现「空」路径。

### 4.3 间距 / 颜色码（第 3 步）

「颜色码」在 tile 分配语境下指：**同一行的不同候选可能以不同前景色渲染**
（选中态红 `OPT_FG_SELECTED` / 未选中态黑 `OPT_FG_UNSELECTED`，以及 PCS 流内
`\CC05xx` 颜色指令）。不同颜色的字若共享同一 tile，重上色会污染相邻字。
所以行内候选之间要留 tile 间距（v4 用 `kOptZones[]` 的 `off+span` 分段实现），
默认值给一个足够容纳「选中态镜像」的间隔。

> ⚠ 「颜色码」的具体语义（是「选中态红色镜像槽」还是「PCS \CC 指令」，
> 还是两者都要）**待与用户对齐后再细化**。当前先把「间距有默认值」这个
> 接口定下来。

## 5. 可行性 + 当前实现对照

**结论：可行。** 配置结构能 1:1 覆盖 v4 `kOptWindow` 的语义，且 v4 已在设置
界面实测验证。当前代码（`PrintNextChar_hook.c` 的 `V6SceneRule`）已实现大部分：

| 配置字段 | 当前实现 | 差距 |
|---|---|---|
| `win地址` | `tpl` | ✅ 已实现 |
| `避让带` | `avoid` / `avoid_n` | ✅ 已加（默认空） |
| `间距` | `row_span_tab` | ⚠ 每行写死，缺「默认值」语义 |
| `tile号` | `row_tab` | ⚠ 写死，缺「空→算法计算」分支 |
| `样式` | `zones`（`cx_hi` + `font_px`） | ✅ 已实现 |

**当前落在「非空 tile 号」阶段**：`kOptRowBase[7]` 用 v4 实测值，
`row_span_tab` 用 v4 的 32/…/0。目标是先把这条路径验证稳定，再补
「空 tile 号 → 算法自动算」（算法 = 在避让带之外找连续空闲区间）。

---

## 6. 后续步骤

1. **底层验证**：当前「非空 tile 号」路径在设置界面是否稳定（不闪屏、不串字、
   颜色正常）——等用户实测。
2. **算法自动算 tile 号**：`tile号` 留空时，基于 `避让带` 找空闲区间分配。
3. **间距默认值**：定义 `间距` 的默认值（如 32），把 `row_span_tab` 从「每行
   写死」改成「缺省用默认值」。
4. **颜色码语义对齐**：确认「颜色码」= 选中态镜像槽 / PCS 指令 / 两者，细化
   `间距` 的取值规则。
