## B09 — 全角标点渲染畸形（2026-11-03）

### 现象

战斗开场台词「啊！野生的雷电球跳出来了！」里，
**两个「！」都渲染成畸形叠字**，且把后面相邻的字推开/重叠；
行尾还能看到 3px 的碎片段。

复现帧：

```
work/POKEMON_RUBY_AXVJ00/bot/battle_full/20261103T152705_380680/
  ├─ translated/040.png   ← 译文（畸形）
  └─ origin/040.png       ← 原版（正常，半角「!」）
```

### 量化证据

用 `scripts/measure_text_row.py` 量同一帧的文字行（y=122..136）：

| 侧 | 字形段宽度序列（px） |
|---|---|
| **origin** | 12, **8**, 5, 8, 32 |
| **translated** | 12, **11**, **19**, 11, 11, 11, 11, 11, **7**, **3**, 9, 11, 9, 8, 7 |

判读：
- 原版「！」占 **8px**（半角槽），汉字占 12px；
- 译文里出现 **19px** 与 **11px** 的异常段，以及 3px 碎片；
- ⇒ 标点被按**全角 12px** 排，而字形本身只有 8px 宽 ⇒ 挤压 + 与邻字重叠。

复现命令：

```powershell
python scripts/measure_text_row.py <png> --y0 122 --y1 136
```

### 根因（代码依据，三段都能对上）

**① charmap 把标点映射到日文单字节 PCS**

`configs/POKEMON_RUBY_AXVJ00/charmap.txt`：

```
 84: B0=…
161: 37=。
164: 3A=、
165: 3B=，
166: 3C=！
167: 3D=？
168: 3E=：
6960: @ Sentence punct / space / … use JP PCS single-bytes (00,37,3A-3D,3E,B0,AE…)
6961: @ — do NOT map ，。！？、：… here as 1E5x (that became F9 00 + Normal blur).
```

设计意图是对的（走原版单字节路径，避免 `F9 00` 走中文路径糊掉），
但**这几个码位在原版字库里是半角 8px**（上面实测）。

**② 渲染侧不按字符区分步进**

`configs/POKEMON_RUBY_AXVJ00/hook/src/text/text_render.c:85-112`：

```c
uint8_t GetChineseFontWidthFunc(uint16_t ChineseChar, uint8_t fontId)
{
    (void)ChineseChar;          /* ← 字符参数被丢弃 */
    switch (fontId) {
    case 4u:  return 8u;        /* Small */
    default:  return 12u;       /* Normal / Middle */
    }
}
```

函数**完全不看字符**，一律按 fontId 给固定步进。
于是 8px 宽的标点被当成 12px 字排。

**③ 中文 BDF 里也没有这些标点可退**

实测三套 BDF（`normal.bdf` / `middle.bdf` / `small.bdf`）覆盖 6807 个码位：

| 类别 | 字符 | 是否覆盖 |
|---|---|---|
| 全角括号/引号 | `（）「」『』—～·` | ✅ 有 |
| 全角标点 | `！？。，、：；…` | ❌ **全部缺失** |

（`…` U+2026 在词表里，但 `。，、：；！？` 一个都没有。）

### 影响面

`configs/POKEMON_RUBY_AXVJ00/translate/texts_translated.json`：

```
含全角「！」的条目：3316 / 14572
```

这些原文大多以「！」结尾（战斗提示、商店对话、记录写入确认），
即**主线流程里随机可见**，不是边角情形。

### 三个候选修法（都未实施，**待决策**）

| 方案 | 做法 | 风险 / 前提 |
|---|---|---|
| **A** 改步进函数 | `GetChineseFontWidthFunc()` 对这几个单字节标点返回 8 | ⚠ 单字节字符走的是**原版字体路径**，可能根本不进这个函数（它只处理中文双字节字形）。需先确认调用链，否则改了不生效 |
| **B** 补全角字模 | 给 BDF 补 `！？。，、：；` 的全角（12px）字形，并把 charmap 改到 `1E5x` 段 | ✅ 方案最"正"；⚠ 但 charmap 第 6961 行明确记着「1E5x 会变成 F9 00 + Normal 糊掉」，历史上踩过，必须先解决那条路径 |
| **C** 译文换半角 | 把译文里的全角标点批量换成原版使用的半角 | ✅ 改动最小、最安全；⚠ 中文排版习惯上半角不好看，且要动 3316 条译文缓存 |

**倾向**：先做 C 验证「半角就不畸形」这个假设，再决定要不要上 A/B。
但 C 会改译文，**必须你点头**才做。
