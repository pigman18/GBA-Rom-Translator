## 三、「蛋」bug：**改前就存在，不是本次引入**

### 现象

队伍列表（`pokemon_menu/010.png`）：

| | origin | translated |
|---|---|---|
| 1 | ラグラウェ | 蛋 |
| 2 | ジュカイン | 蛋 |
| 3 | サナギラス | 蛋 |
| 4 | キノココ | 蛋 |
| 5 | タマゴ | 蛋 |

**但战斗界面完全正常**（`battle/006.png` 显示「长翅鸥」和
「啊，野生的长翅鸥跳出来了！」）。

### 排查过程（全部排除数据层）

| 检查 | 结果 |
|---|---|
| build.json 宝可梦名译文 | ✅ 正确（巨沼怪/蜥蜴王/蘑蘑菇，0 处重复） |
| SLT2 表内数据 | ✅ 正确（4 个不同日文名 → 4 组不同码位） |
| SLT2 表完整性 | ✅ magic 完好，未被新表覆盖 |
| F9 00 码位越界（46,129 个） | ✅ **0 处越界** |
| **首字 gidx 唯一性** | ✅ **各不相同**：巨0x058E 蜥0x1958 沙0x0991 蘑0x0798（蛋=0x01EE） |

### 决定性证据：历史产物对比

| 时间 | 产物 hash | 显示 |
|---|---|---|
| 11-03 22:22 | `55581970...` | **蛋 ×5** |
| 11-04 04:06 | `8a9d5e82...` | **蛋 ×5** |
| 11-04 20:24（本次） | `55581970...` | **蛋 ×5** |

**BUG 在 11-03 就存在，本次产物与 11-03 的 hash 完全相同。**

⇒ **不是本次 6 张表重构引入的问题。**

### 根因仍在渲染层（老问题）

数据层全对（build.json ✅ SLT2 ✅ gidx 唯一 ✅），但队伍列表显示错：
- 战斗界面正常 → 说明 SLT2 查表和字库本身没问题
- 只有队伍列表错 → 说明**该界面的字形 tile 分配有冲突**

「蛋」的 gidx = 0x01EE = 494，是字库里靠前的字。
四个正确首字的 gidx 是 0x058E / 0x1958 / 0x0991 / 0x0798，都比 494 大。
⇒ 大概率是队伍列表的 charBase 区被「蛋」占用，或 tile 分配越界落到同一位置。

这属于**阶段 C（12px 渲染 / charBase 分配）** 的范围，不在 A2 验收内。
