# A2.8：火红怎么改 stride（已实测确认用户判断正确）

> 2026-11-04 20:45
> 用户提问：「火红那边是怎么做的？我的理解应该是按原本的结构等长或等距改好，
> 再改一个常量，旧的长或距应该能直接从编码里推算出来的吧」

---

## 一、用户判断完全正确

火红实测（`firered_stride_all.py`，招式名表 28 个共同站点）：

| ldr 站点 | 原版 | 汉化 | 变化 |
|---|---|---|---|
| 0x02FFDC | `lsls#24 lsrs#24 lsls#3` | `lsls#24 lsrs#24 lsls#4` | **净 3→4 (+1)** |
| 0x04E790 | `lsls#1 lsls#3` | `lsls#1 lsls#4` | **净 4→5 (+1)** |
| 0x06B66C | `... lsls#2 lsrs#13` | `... lsls#2 lsrs#12` | **净 -11→-10 (+1)** |
| 0x09AEDE | `... lsls#16 lsrs#13` | `... lsls#16 lsrs#12` | **净 3→4 (+1)** |
| 0x0D954C | `lsls#8 lsls#3` | `lsls#8 lsls#4` | **净 11→12 (+1)** |
| 0x11CDCE | `lsls#3` | `lsls#4` | **净 3→4 (+1)** |

**24 处改动，其中 16 处是净移位 +1，一处不漏。**

净移位 +1 = stride ×2（从 8 变 16）。

### 火红的具体做法

1. **表结构照抄原样**：中文名表仍是 `[名字][填充][元数据]` 的定长结构
2. **stride 从 8 放大到 16**（×2，净移位 +1）
3. **改的「一个常量」= `2 的幂因子」那条移位指令的立即数**
4. **形态多样但规律一致**：
   - `lsls r1,r1,#3` → `#4`
   - `lsrs r1,r1,#0xd` → `#0xc`（因为 `lsls#16 + lsrs#13` 净 3，改成 `lsrs#12` 净 4）
   - `lsls#2 + lsrs#13` → `lsls#2 + lsrs#12`

**核心：不管乘法怎么展开（`i*4+i` 还是 `i*8-i`），
那个「2 的幂因子」总是单独一条移位指令，改它即可。**

这也正是用户说的「旧的长或距应该能直接从编码里推算」——
净移位就是 2 的幂指数，`stride = A × 2^net`，A 不用管。

## 二、但我按这个思路实现，仍有 40/92 站点识别不出

我的假设是「乘法在 ldr **之前**」，但实测发现：

### 形态 1：乘法在 ldr 之前（我的算法能处理）

```
特性名 0x09C6C2: lsls r0, r4, #3   ← 乘法
       0x09C6C4: ldr r1, [pc, #0x38]  ← 基址
       0x09C6C6: adds r0, r0, r1
```

### 形态 2：乘法在 ldr 之前，但被别的移位干扰

```
装饰名 0x0AF2C4: lsls r0, r7, #0x19   ← 无关（截断）
       0x0AF2C6: lsls r0, r0, #0xc    ← 无关
       0x0AF2C8: ldr r2, [pc, #0x1c]  ← 基址
       0x0AF2CC: lsls r0, r3, #1      ← ★ 真正的乘法在 ldr 之后！
       0x0AF2CE: adds r0, r0, r1
```

### 形态 3：index 计算在很前面，中间夹着 ldrh/ldrb

```
属性名 0x02B6AC: lsls r1, r0, #2    ← 乘法（ldr 前 4 字节）
       0x02B6AE: adds r1, r1, r0     ← i*4 + i = i*5
       0x02B6B0: ldr r0, [pc, #0x3c] ← 基址
       0x02B6B2: adds r1, r1, r0
```

形态 3 我的算法应该能处理（`lsls #2` 在 ldr 前 4 字节内），
但 `old_stride % (1 << net)` 判据失败：属性名 stride=5，
而 `lsls #2` 的 net=2，`5 % 4 != 0`。

**这里就是关键盲区**：`stride = A × 2^net`，
属性名 `5 = 5 × 2^0`，A=5（来自 `i*4+i`），net 应该是 **0**。
但 `lsls #2` 贡献的 net=2，A=1.25，不整除。

⇒ **「净移位」不能简单累加所有移位**，必须还原
「哪条移位作用于 index、哪条作用于结果」的语义链。

这就是我卡住的地方。

## 四、建议改用「不猜语义」的方案

### 方案 A：指针数组（stride 恒为 4）

把表的访问方式从「`base + idx×stride`」改成「`base + idx×4` + 解引用」。
- 优点：**stride 恒为 4，所有站点改动完全一致**，不存在形态差异
- 缺点：要改访问逻辑（`ldr [base + idx*4]` 再取值），改动更大

### 方案 B：不放大 stride，改用「压缩名字」

保持 stride 不变，把中文压缩到原宽度内（如 2 字 → 1 字）。
- 优点：**零机器码改动**
- 缺点：牺牲翻译质量（用户明确不接受优先用缩写）

### 方案 C：保持 stride，改用「名字指针字段」

很多表的结构里有空闲字段（如道具名 stride=40，名字只占 9B，剩 31B）。
- 若能把名字改成「存一个小指针/偏移」，就不用改 stride
- 需要确认表的元数据结构允许

### 方案 D：让用户提供「改哪条指令」的清单

火红的做法说明**改动点是可以人工确认的**。28 个站点逐个看，
人工标注「哪个是 stride 乘法」比算法猜更可靠。
