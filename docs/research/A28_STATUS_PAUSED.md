## 一、事故：stride 改动漏改乘法站点

### 现象（用户实测）

- 华丽大赛技能界面：**技能名空白**
- 背包：**黑屏**

### 根因

我改了 6 张表的 stride，但**每张表只改了 1 处乘法指令**，
实际每张表有多处引用站点，每处都有自己的 `index×stride` 乘法。

| 表 | 字面量站点 | 需改乘法站点 | 我改了几处 |
|---|---|---|---|
| 招式名 | 43 | **40** | **1** |
| 道具名 | 14 | **14** | **1** |
| 秘密基地装饰名 | 22 | **22** | **1** |
| 图鉴分类名 | 7 | **5** | **1** |
| 属性名 | 4 | **3** | **1** |
| 特性名 | 3 | **3** | **1** |
| **合计** | | **87** | **6** |

**漏改 81 处。** 未改站点仍按旧 stride 算地址 → 读到新表中间 → 空白/黑屏。

### 为什么会漏

不是算法有分支。查找引用站点本来就是固定算法：

```python
for lit in find_literal_sites(rom, base):        # 全 ROM 扫 u32
    for ldr in find_ldr_for(lit):                # 找 ldr 引用
        for ins in find_shift_before(ldr):       # 找乘法
            patch(ins)
```

**我在写 `a2_gen_final_patch.py` 时，把 `a2_base_refs.py` 打印的「第一个站点」
手抄成了常量**，而不是让脚本自己遍历。这是我图快写死了数据。

而且验证时也只验证了那 6 个硬编码地址，自然全过。

## 三、当前进展：自动注入算法（`src/meowth/table_stride.py`）

按用户指示「不该交给 patch，应该交给自动注入」，写了动态扫描算法。

### 已实现

```
步骤 1: find_literal_sites    扫全 ROM 找 u32 == base+0x08000000
步骤 2: find_ldr_for_literal  对每个字面量找 ldr [pc,#imm] 引用
步骤 3: find_stride_shift     对每条 ldr 找决定 stride 的移位指令
自检 A: 每个站点的 shift 必须能整除旧 stride
自检 B: 改写后重扫，站点数必须一致
自检 C: 站点数必须 >= 预期
```

## 四、教训

1. **改动前必须确认「所有生效点」**，不能只改一处就以为改完
2. **字面量有几处，乘法就有几处** —— 必须同数
3. **不要把扫描结果手抄成常量**，让脚本自己遍历
4. **验证必须覆盖「未改的站点是否也改了」**，不能只验证改过的
5. **bot 场景必须覆盖出问题的界面**（这次漏了 `contest_*` 和 `bag`）
