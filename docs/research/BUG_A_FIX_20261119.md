## 二、详情内切换训练家地点 stale —— 已定位并修复（用户提醒项）

### 现象
详情页按 DOWN 切到下一个训练家：红条标题/立绘/正文都跟着变（如「香薰姐姐 弥生」→「遗迹迷 信夫」），**唯独地点框停在「118号道路」不更新**。origin 同操作地点变为「111ばん どうろ」/「109ばん すいどう」。

### 修正后的根因（推翻前一版「数据源失效」结论）
前一版误判「重打数据源 `blk[0x8942+sel*4]` 恒为 0 ⇒ 无法重打」。实际是**找错了函数**：

| 事实 | 证据 |
|---|---|
| `PrintLocation@0x080EB9C0` 在 PokeNav **全程 flag=blk[0x87CE]=2**，打印分支从未执行 | RAM 实测 f113/f131/f173 flag 恒 2；GDB 每次命中 `r0=2` |
| `blk[0x8942+sel*4]` 恒 0 **不影响地点显示**，因为 origin 根本不走这条分支 | 同上；该表是另一套（未启用）路径 |
| **真正的地点打印函数是 `0x080EC2E0`**（被误命名为 PrintLeftStats） | 反汇编见下 |
| 训练家记录 `blk+0xCEE8+sel*8`：`+0 trainerId / +2 地点名索引 / +4 slot / +5 flags` | RAM dump f131/f173/f180 |
| `0x080F6F1C` = `GetMapNameString(dest, nameIndex, 0)`，查 `0x083BEF70+idx*8` 指针表 | 反汇编 + translated ROM 表项验证 |

`0x080EC2E0` 反汇编（关键 8 行）：
```
r5 = blk;  r2 = blk + 0x878C                ; 临时串缓冲
r0 = (sel << 24) >> 21                      ; sel * 8
r1 = ldrh [blk + 0xCEEA + sel*8]            ; ← 地点名索引
bl  0x080F6F1C                              ; GetMapNameString(blk+0x878C, idx, 0)
... 清 blk+0xD138 到 9B，拼上结果 ...
movs r0,#0x25 ; bl InitMenuWindow
Menu_PrintText(blk+0xD138, 0, 5)            ; ← 地点打印，走 grid 渲染
```

索引与译文完全对得上（translated ROM 指针表实测）：
| sel | `blk[0xCEEA+sel*8]` | 指针表指向 | 显示 |
|---|---|---|---|
| 0 | 33 (0x21) | `a2 a2 a9 f7 00 04 eb 00 03 07 00 08 e8 ff` | 118号道路 |
| 1 | 26 (0x1a) | `a2 a2 a2 f7 …` | 111号道路 |
| 2 | 24 (0x18) | `a2 a1 aa f7 00 04 eb 00 0c 51 00 08 e8 ff` | **109号水路**（水路，非道路） |

**结论**：汉化 DetailEnter hook 只调了空转的 `PrintLocation`，从没调过真正的 `0x080EC2E0` ⇒ 地点永不重打，靠 live-ref 保住的旧字模一直停在 118。这就是 stale 的完整原因，**不是数据源缺失**。

### 补丁（左栏接入自定义渲染）
`PokeNav_TrainerEye_DetailEnter_hook.c`：
1. 把 `PrintLocation(0x080EB9C0)` 换成 `0x080EC2E0(sel)` —— 它内部走 `Menu_PrintText`，即与右栏同一套 PrintNextChar grid 自定义渲染。
2. 新增 `clear_location_tiles()`：重打前把地点带 (y5-6, x1..11) tilemap 引用的 tile 内容清 0。原因：grid 对 0x00 只推进不改表，短地点名（如「未白镇」）不会覆盖长名（「118号道路」）尾部 ⇒ 残墨。x=0 是窗边框，不动。
3. `sel` 读取提到 `init(LEFT_WIN)` 之前（重打需要）。
4. 保留 `scrub_list_arena()` 的 live-ref 保护（保护标签/统计旧字模；地点带随后由 2+1 主动重写）。

`PokeNav_TrainerEye_ListRedraw_hook.c` 不改：`restore_left_panel()` 本来就调 `print_stats(sel)` 即 `0x080EC2E0`，退回列表地点一直正常。

## 三、方法论教训
1. **函数名不可信**：`0x080EC2E0` 在旧文档/注释里叫 PrintLeftStats，实际是地点打印；`0x080EB9C0` 叫 PrintLocation 却在 PokeNav 全程空转。一律以反汇编 + 实机数据为准。
2. **"数据源失效"结论要先验证函数是否真被执行**。本轮用 RAM dump 证明 `flag` 恒 2、打印分支从未跑过，才推翻前一版误判——此前两次补丁失败都是因为拿了一个不会执行的函数去"重打"。
3. 索引→译文表要**按指针表实读**验证（`0x083BEF70+idx*8`），比在 RAM 里盲搜数值序列可靠得多（前者一次命中 118/111/109，后者全 RAM 搜不到）。
4. 判据要看**语义**：109 是 `すいどう`「水路」而非「道路」，译文区分正确才是真 PASS。
