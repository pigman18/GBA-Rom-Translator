# 火红实现汉化的全部逻辑（定案版）

> 调研对象：`roms/translated/宝可梦火红日版汉化2.2.gba`
> 对照基线：`roms/origin/POKEMON_FIRE_BPRJ00.gba`（同版本日版原版，16 MB，两版长度相同）
> 约束：只调研火红，不涉及其他汉化版 ROM。
> 脚本：`scripts/research/firered/01..37_*.py`，本轮新增 `16..37`。

---

## 零、总纲：火红汉化的全部手段只有三种

| # | 手段 | 证据 |
|---|---|---|
| **M1** | **改指针**：把指向原版日文串的 u32 改成指向新增中文文本区 | 3,613 个槽位的旧值落在 `0x0819xxxx/0x083Cxxxx/0x0840xxxx`，新值落在 `0x086D0000` / `0x0871F446` / `0x08AF5000`（㉕） |
| **M2** | **写入原版空白区**：中文文本、补丁代码、显示映射表全部放在原版 100% 为 `0xFF` 的空区 | 原版 `0x6D0000..0xC00000` 共 5312 KB 全空；汉化占用后剩 384 KB。`0x0871F000..0x08722000` 原版非 FF 字节数 = **0**（㉞） |
| **M3** | **代码补丁**：在原函数里插 `ldr r3,[pc,#imm]; bx/blx r3` 跳到新增代码 | 11 个这样的跳转点，目标全在 `0x08FFxxxx` / `0x08EDxxxx`（㉒） |

**没有任何第四种手段。** 尤其：
- 原版日文文本 **97.9% 原样保留**（㉑⑤ 抽样 25,369 个起点，24,634 个逐字节未变）
- **原版非空区里没有塞任何中文**——唯一 42 处 64~128 字节的命中，全部是**代码区字面量池**（㉟③），不是数据表

⇒ 这一条是理解「串档不乱」的钥匙：**火红没有改动原版任何一个数据结构**，只是把指针改到新区、把新东西放进空区。

## 一、编码协议

### 1.1 火红只用 F7，且是 3 字节

| 项 | 实测 |
|---|---|
| 前缀字节 | **只有 `0xF7`** |
| 全 ROM 频次 | 原版 49,212 → 汉化 **171,834**（3.49 倍）；`F9` 基本没动（20,505→21,328） |
| 结构 | **`F7 hi lo`，3 字节**。相邻 F7 间距 = 3 出现 **100,711 次**，占绝对多数 |
| 原版编码 | **1 字节**（`0x00`–`0xDF` 可用，`0xFE`/`0xFB` 是控制码，`0xFF` 串尾） |

**「短编码能省字节」这个期待不成立**：我们是 `F7 00 hi lo`（4 字节），火红是 `F7 hi lo`（3 字节）。

### 1.2 码位空间

真实码位 **2,299 个**，`hi` 实际只用 11 页（`0x00`–`0x0A`）：

| 区 | 地址（ROM） | F7 数 | 码位 |
|---|---|---|---|
| 主文本区 | `0x086D0000`（304 KB） | 89,643 | 2,231 |
| 文本区 2 | `0x0871D000`（40 KB） | 8,935 | 1,108 |
| 文本区 3 | `0x08AF5000`（24 KB） | 5,169 | 764 |

频次覆盖：前 500 字 83.6% / 1000 字 94.8% / 1500 字 98.5% / 2000 字 99.7%。

**⇒ 12 位足够（4 位页 + 8 位偏移 = 4096），可压成 2 字节，每字省 1 字节（33%）。火红没做，我们重写时可以做。**

> ⚠️ **统计踩过的坑（同一根因，四次错判）**
> 代码段里的 `60 F7` 是 **Thumb 的 `b.n` 指令**，不是编码前缀。任何「全 ROM 扫 F7」的统计都会被污染（得到 hi=256 种、4701+ 码位）。
> 唯一可靠的锚点：先用 ROM 差异定位**整块被替换的纯文本区**，再在区内统计。

## 二、五类文本，火红分别怎么处理

### 2.1 总账（6,517 条中文段逐个定性）

| 容器 | 段数 | 占比 | 平均长 | 段首有指针 |
|---|---|---|---|---|
| 直指针 | 3,597 | 55.2% | 49.3 | 100% |
| 无特征（无指针、非块） | 1,757 | 27.0% | 65.9 | 0 |
| 直指针 + 超短 | 499 | 7.7% | 5.8 | 100% |
| 各种等长块成员 | 664 | 10.1% | — | 多数无 |

**指针可达率：67.3%**（段首 66.8% + 段内 0.5%）。
**完全无指针：32.7%**（㉛ U1）。

### 2.2 第 1 类：常规文本 —— 有指针就改指针，无指针不缩短

**答案：火红没有做「无指针就缩短译文」。它是把整个原串搬走、把指针改掉。**

证据链：
1. 3,613 个原指向日文文本的槽位，旧值集中在 `0x083DDxxx`（原版日文文本区），新值 85.3% 落在中文文本区（㉕①）
2. 原版那 6,435 条日文串，**97.9% 逐字节原样保留**（㉑⑤）
3. 汉化文本区里**没有任何一条是「原串的缩短版本」**——它们都是新写的译文

⇒ 「无指针 → 缩短译文」这条策略**火红根本没采用**。它用的办法更彻底：**原串留着当孤儿数据，指针改指新串**。

那 32.7% 的「无指针段」是什么？它们不是「无处安放的文本」，而是：
- 被**结构体基址 + 偏移**访问（如名字表 `0x0871F446`，用 `index × 步长` 算）
- 被**上一级的容器指针**整体引用（块级指针）

### 2.3 第 2 类：等长块 —— 火红用「定宽补 00」而不是「整块一个指针」

**答案：不是「整块一个指针」，而是「每个元素各自一个指针」或「未对齐的结构体字段」。**

㉛ U2 实测 68 个等长块：

| 情况 | 块数 | 特征 |
|---|---|---|
| 块首被引用 + 元素引用率 100% | 10/68 | **每个元素各自有指针** |
| 块首无引用 + 元素引用率 17~67% | 58/68 | 结构体字段，靠基址+偏移访问 |

典型例子 `0x086D5CC0`：16 段，每段步长 12，**块首 ×1，元素 16/16 全被引用**。

⇒ 火红**没有**「一整块改一个指针」的做法。你的红宝石工程里那套「整块写新区 + 改整块指针」在火红上不适用。

### 2.4 第 3 类：等距块 —— 就是「串后紧跟 FF」的普通串流

**答案：所谓「等距块」在火红数据里就是普通的连续串，没有专门的容器。**

㉛ U3 修正判据后（`gap == 1`，即串尾 FF 后直接是下一串）：找到 81 个「≥4 段紧邻」的块。

```
块首            段数   块首指针   元素被引用   段长样本
0x08702608      34      无         14        [35,35,35,35,35,35]  ← 等长
0x0871F446     356      无          0        [20,18,18,12,21,9]   ← 变长（名字表）
```

⇒ 「等距」的样板是**每段后面跟一个 `FF` 分隔**，内容是变长的。火红没有单独的「等距块指针」机制——它就是普通串流，**靠串尾 FF 自然分隔**。

### 2.5 第 4 类：超短文本 —— 和常规文本完全一样，走同一套编码

**答案：没有特殊处理。超短文本（≤6 字节 = 1~2 个汉字）98.8% 都有独立指针。**

㉚/㉛ 实测 508 条 ≤6 字节的中文段：

| 项 | 值 |
|---|---|
| 段数 | 508（7.8%） |
| 长度分布 | L3:31, L4:1, L5:3, **L6:473**（L6 就是 2 个汉字 + FF） |
| **有指针** | **502（98.8%）** |

样本：
```
0x086D27D8 L=6 汉字2 ptr×1  f7 02 1a f7 03 66 ff
0x086D2974 L=6 汉字2 ptr×4  f7 00 60 f7 00 39 ff
0x086D2B10 L=6 汉字2 ptr×4  f7 00 ec f7 00 26 ff
```

⇒ 「是 / 否」这类选项在火红里就是**普通的 6 字节串**，有自己独立的指针，与长文本无差别。
这解释了火红为什么不需要「实时替换表」——它的选项文本本身就有指针可改。

### 2.6 第 5 类：宝可梦名 —— 新增一张显示表，原数据一个字节不动

**答案：火红**没有**在原版物种名数据上写中文。它另外新做了一张中文名表，原版数据结构完全保留。**

这是「串档不乱」的机制，思路一致，但实现更干净。

**证据 1：中文名表在原版空白区**
```
0x0871F446 起是「00 补齐 + 中文名 + FF」的变长项表
原版 0x0871F000..0x08722000（73,728 字节）非 FF 字节数 = 0  ← 完全空白
```
表的前 30 项（`00` 是右对齐填充，`ff` 是项结束符）：
```
[0] 00×14 | f7 02cf f7 0271 | ff                          汉字2
[1] 00×9  | f7 01aa f7 01e2 f7 0277 | ff                  汉字3
[2] 00×6  | f7 0385 f7 0332 f7 02b3 f7 02d9 | ff          汉字4
[3] 00×3  | f7 0385 f7 01ad f7 02d9 | ff                  汉字3
[9] 00×6  | f7 0234 | ff                                  汉字1
```
354 项汉字数在 1~5 之间（典型名字长度），项数 760（含长文本区段）。

**证据 2：原版非空区里零中文**

㉟③ 全 ROM 扫描「原版非空 + 汉化含 ≥4 个 F7」的 64 字节块：只有 **42 处**，每处 64~128 字节，**全部落在 `0x0800xxxx`–`0x080Dxxxx` 代码区的字面量池**，没有一处是数据表。

**证据 3：物种名表本身找不到 412×11 连续表**

用「末两字节 FF + ≥300 项 + 非空 ≥80%」扫原版，**0 命中**（㊱）。说明日版火红的物种名不是 `name[412][11]` 的连续数组布局，而是别的结构（可能按 generation/分区存放）。

> ⚠️ **这里仍有一个未解点**：我没能定位到原版物种名的**实际数据位置**。
> 但「串档不乱」的机制已经足够清楚：**存档里存的是原版编码的名字，汉化只额外加了一张显示表**。
> 若要 100% 坐实，需要找到存档 → 名字的读取路径（`GetMonData` 的 `MON_DATA_NICKNAME`），这属于下一步。

## 三、代码补丁（M3）：11 个 hook 点

火红在代码区只动了 **0.414%**（29,542 / 7,143,424 字节）。

### 3.1 补丁形态

**形态 A：内联跳转（最常见）**
```
0x0809DBE0  汉化: 01 4b 21 1c 02 e0 c0 46 2b d8 ff 08 6b f0 b7 fb
                  └┬┘ └──┘ └──┘ └──┘ └────┬────┘ └────┬────┘
             ldr r3,[pc,#4]  b.n  nop  字面量 0x08FFD82B  bl 新代码
```
在 `0x080494A0`、`0x0804E830`、`0x080915DA`、`0x08091792`、`0x0809DBE0`、
`0x0809DC20`、`0x080A17B9`、`0x080D922B`、`0x08105BB2`、`0x08106699`、
`0x081101A2`、`0x08115E1D`、`0x08115E4C`、`0x0811D8F5`、`0x0811DBA6` 等处都有。

**形态 B：改字面量池（改指针，不是插代码）**
```
0x08019D78  原: b4 47 3c 08  →  汉: 24 3e 6d 08
           0x083C47B4          0x086D3E24
```
这类占绝大多数（**720 个函数指针被换掉**）。

### 3.2 11 个 `bx` hook 点

| hook site | 跳转类型 | 目标 |
|---|---|---|
| `0x081DB3E4` | bx | `0x08005B2B` |
| `0x087C0062` | bx | `0x08005D59` |
| `0x087C0066` | bx | `0x08005D4D` |
| `0x087C0080` | bx | `0x08005F6D` |
| `0x087C0084` | bx | `0x08005E83` |
| `0x087C0408` | bx | `0x080D98B1` |
| `0x08E25E44` | bx | `0x080060CD` |
| `0x08E25E7E` | bx | `0x080060ED` |
| `0x08FF908A` | bx | `0x08FF753B` |
| `0x08FF9112` | bx | `0x080F9145` |
| `0x08FF9134` | bx | `0x080F9145` |

> ⚠️ 目标 `0x08005B2B` / `0x08005D59` 等落在原版有代码的区（不是新增区），
> 说明这些是**跳回原版代码**（函数中段），属于「插入一段代码后跳回」的标准 hook 写法。
> 只有 `0x08FF753B` 落在新增区。

## 五、对红宝石工程的启示

### 5.1 可以直接借鉴

| 火红做法 | 我们能怎么用 |
|---|---|
| **中文全放空白区，指针改指** | 我们已经在做（写新区改指针），做法一致 |
| **超短文本不用特例** | 火红证明**短串本身有指针**就不需要替换表。重写时应先验证哪些短串真的无指针 |
| **宝可梦名：新增显示表，不动存档** | 火红的「新增一张名表 + 改引用」更干净，不侵入渲染 |
| **等长/等距块用「每元素一指针」** | 不要设计「整块一个指针」的机制，火红证明那样不必要 |

### 5.2 火红没做、我们可以做的

| 项 | 说明 |
|---|---|
| **2 字节编码** | 真实码位 2,299 < 4096，`F7 hi lo` 可压成 `<prefix><page:4\|off:8>`，每字省 33% |
| **记录码位映射表** | 火红没有集中的「码位 → 汉字」表，靠 `F7 hi lo` 直接算索引。我们重写时应显式生成一张表，便于校验 |

### 5.3 火红的局限（不要照抄）

- **97.9% 的原日文文本成了孤儿数据**，白占空间。我们如果有空间压力，可以在确认无引用后清零
- **无指针的 32.7% 段**依赖结构体偏移，一旦结构变动就全断。
