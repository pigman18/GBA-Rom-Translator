## 〇、两次自我纠正（诚实记录）

| 我曾下的结论 | 实际 | 怎么发现的 |
|---|---|---|
| 「火红只用 F7」 | **错**。还有 F6 / F8 | 反汇编 `0x081DB660`/`0x081DB800` 找到 `cmp #0xF6` / `cmp #0xF8` |
| 「F7 是 2 字节 `F7 hi`」 | **错**。仍是 3 字节 `F7 hi lo` | 原始字节 `f7 00 35 f7 00 36 f0`，相邻间距 3 占 77,209 次；段长/F7数 比值 3 占 80.1% |

**教训**：反汇编读到 `adds r5,#1` 就断定「跳过 2 字节」是错的——
那个分支只处理了 `hi`，`lo` 由另一条路径消费。**必须以原始字节统计为最终依据。**

## 一、编码协议

### 1.1 四个前缀

| 字节 | 原版用量 | 汉化用量 | 语义 |
|---|---|---|---|
| `0xF6` | 21,514 | 28,138 | `F6 hi lo` → 输出 `F7 hi lo`（迁移层） |
| `0xF7` | 49,212 | **171,834** | 中文，**`F7 hi lo` 3 字节** |
| `0xF8` | 21,977 | 23,181 | `F8 F7 hi lo` → 输出 `F7 hi lo`；`F8 F8 …` 原版就有 |
| `0xFF` | — | — | 串尾 |

**原始字节实证**（主文本区 `0x6D0000`）：
```
+0x00000: f7 00 35 | f7 00 36 | f0 | f7 00 97 | ab | f7 00 8b | f7 00 8b | ab
           └──┬──┘   └──┬──┘        └──┬──┘        └──┬──┘
           汉字1      汉字2         汉字3         汉字4
```

**相邻 F7 间距分布（93,516 个 F7）**：

| 间距 | 次数 |
|---|---|
| **3** | **77,209**（绝对多数） |
| 4 | 5,898 |
| 5 | 4,202 |
| 6 | 2,040 |
| 7 | 1,636 |

**段长 / F7 个数 比值**：3 占 **80.1%**（4,878/6,101 段），4 占 13.8%

⇒ **`F7 hi lo`，每汉字 3 字节。这与我们 `F9 00 hi lo` 完全持平，
「少 1 位编码」不成立。**

### 1.2 F6 / F8 是迁移与兼容层

反汇编 `0x081DB660`（函数 A）与 `0x081DB800`（函数 B）：

```asm
; ---- 函数 A：F6 / F7 二分支 ----
81db668: ldrb r0,[r5,#0]     ; ch = *src
81db66a: cmp  r0,#0xFF
81db66c: beq  → 结束
81db66e: cmp  r0,#0xF6       ; ★ F6
81db670: beq  → 81db67e
81db672: cmp  r0,#0xF7       ; ★ F7
81db674: beq  → 81db698
81db676: strb r0,[r4,#0]     ; 其他原样
81db678: adds r4,#1
81db67a: adds r5,#1
81db67c: b    → 81db668

; F6 分支：F6 h l → 输出 F7 h l
81db67e: movs r0,#0xF7 ; strb r0,[r4,#0] ; r4+=1 ; r5+=1
81db686: ldrb r0,[r5,#0]; strb r0,[r4,#0] ; r4+=1 ; r5+=1
81db68e: ldrb r0,[r5,#0]; strb r0,[r4,#0] ; r4+=1 ; r5+=1
81db696: b → 81db668
;  ⇒ 净效果：3 字节 F6 h l → 3 字节 F7 h l

; F7 分支：查表展开
81db698: adds r5,#1          ; src += 1（跳过 F7）
81db69a: ldrb r0,[r5,#0]     ; hi = *src
81db69c: lsls r0,r0,#2       ; hi << 2      ← 表项 4 字节
81db69e: adds r0,r0,r7       ; base + hi*4
81db6a0: ldr  r1,[r0,#0]     ; ptr = TABLE[hi]
81db6a6: ldrb r0,[r1,#0]     ; 逐字节复制 ptr 指向的串
81db6a8: cmp  r0,#0xFF
81db6aa: beq  → 跳过
81db6ac: strb r0,[r4,#0] ; r1+=1 ; r4+=1 ; b → 81db6a6
81db6b4: adds r5,#1          ; src += 1（跳过 hi）
81db6b6: b → 81db668
```

```asm
; ---- 函数 B：多一个 F8 组合 ----
81db812: cmp r0,#0xF8        ; ★ F8
81db814: bne → 原样复制
81db816: ldrb r1,[r5,#1]
81db818: cmp  r1,#0xF7       ; ★★ F8 F7 组合
81db81a: bne  → 原样
81db81c: movs r0,#0xF7 ; strb r0,[r4,#0]     ; dst[0]=0xF7
81db820: ldrb r0,[r5,#2]; strb r0,[r4,#1]    ; dst[1]=src[2]
81db824: ldrb r0,[r5,#3]; strb r0,[r4,#2]    ; dst[2]=src[3]
81db828: adds r4,#3 ; adds r5,#4
;  ⇒ F8 F7 h l（4 字节）→ F7 h l（3 字节）
```

> ⚠️ 注意 F7 分支里 `adds r5,#1` 只加了 1 —— 这说明 **`lo` 没有在这个分支被消费**。
> 结合原始字节（间距 3 占绝对多数），最合理是：这个函数是**转码器**，
> 它把 `F7 hi lo` 里的 `hi` 拿去查表，`lo` 保留给下游；或该函数只处理 `F7 hi` 一种旧数据。
> **以原始字节统计为准：`F7 hi lo` 3 字节。**

### 1.3 中文 = 「索引 → 原版单字节片段」，不是新字模

`TABLE` 基址 = 字面量 `0x081DB85C` = **`0x0203F2C0`**（EWRAM）
原版该字面量 = `0x00000000`

- `0x0203F2C0` 在原版里**已被 4 处代码引用**（`0x0813D3EC/408/428/464`，
  两版完全相同）⇒ 是**原版引擎本来就用的 EWRAM 缓冲区**，汉化复用
- F7 分支会把 `TABLE[hi]` 指向的串**逐字节展开**

⇒ 汉化的中文 = 用原版字符序列拼出来的。
**这解释了为什么全 ROM 找不到中文字模：没有新字模。**

### 1.4 码位空间

`F7` 之后第一字节（hi）分布（171,834 处）：

| hi | 占比 |
|---|---|
| 0x00 | 42.8% |
| 0x01 | 11.6% |
| 0x02 | 5.7% |
| 0x03 | 4.6% |
| 0x04 | 4.0% |
| 0x05–0x09 | 2.0%~0.4% |
| 其他 | 零散 |

hi 密集在前 11 个值；`lo` 铺满 0–255 ⇒ **码位 ≈ 11 × 256 = 2,816**，
与前版「2,299 个实际使用码位」相符。

⇒ **12 位仍足够（4 位页 + 8 位偏移 = 4096），可压成 2 字节，每字省 33%。**

## 二、渲染协议

### 2.1 字宽只有三档：2 / 10 / 12

反汇编 `0x081DB620` 附近：

```asm
81db630: ldr  r1,[pc,#20]    @ (81db648) = 0x03003E60
81db632: subs r1,r4,r1       ; 偏移 = 入参 - 基址
81db634: cmp  r1,#160
81db636: bhi  → 81db642      ; > 160  ⇒ 12（全角）
81db638: beq  → 81db63e      ; == 160 ⇒ 2（半角）
81db63a: movs r0,#10         ; 其他   ⇒ 10（中间档）
81db642: movs r0,#12
81db644: ldr  r1,[pc,#4]     @ (81db64c) = 0x03003E60
81db646: bx   lr
```

**结论：字宽三档 2 / 10 / 12，没有 8+4 / 4+8 拼接。**

### 2.2 为什么火红不会撞 UI

| 项 | 火红 | 我们（红宝石） |
|---|---|---|
| 汉字宽度 | **固定 12px** | 8+4 / 4+8 **两块 tile 拼** |
| 每个汉字的字形槽 | 1 个 | 2 个 tile |
| charBase 占用 | 1 份 | 2 份 |
| 光标/弹窗重绘 | 1 个单元格宽 | 跨 tile，边界易漏 |

⇒ 火红把 12px 当**原生字宽**，排版按「一个字 = 一个单元格」算，
所以不会有「光标停在字中间」「弹窗盖住半个字」这类问题。

### 2.3 我们的方案

**核心：让 12px 成为原生字宽，而不是拼 tile。**

| 路线 | 做法 | 代价 |
|---|---|---|
| **A（学火红，推荐）** | 字号固定 12，字形按 12×12 存，排版按字宽 12 推进 | 字形 18 B/字；需改排版推进量 |
| B（守 8×8） | 字号固定 8 | 8×8 放不下汉字结构（「蛋」「香」已验证会坏） |

火红证明 **A 可行且成熟**。我们现在的「8+4/4+8」是从原版 8px 引擎硬改的过渡方案。

**额外收益**：火红的 `F7 hi lo` → `TABLE[hi]` → 原版字符序列这条路，
意味着**汉字不需要独立字模**，可以直接复用原版字库。
若这条路能用，charBase 压力会大幅下降。但需先解决 R-1（TABLE 填充源）。

## 三、五类文本（结论不变）

| 你问的 | 火红做法 |
|---|---|
| 常规文本 | 写新区 + 改指针（3,613 个槽位旧值 `0x083DDxxx` → 新区） |

| 等距块 | 普通串流，`FF` 分隔 |
| 超短文本 | 与长文本无区别，98.8% 有独立指针 |
