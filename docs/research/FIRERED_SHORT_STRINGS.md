# 火红超短项（是/否等）的处理方式 — 实测定案

> 2026-11-04。对照 `roms/origin/POKEMON_FIRE_BPRJ00.gba` 与
> `roms/translated/宝可梦火红日版汉化2.2.gba`。
> 脚本：`probe_short_strings.py`、`probe_short_strings2.py`、`probe_short_noptr.py`、`probe_yes_no.py`

---

## 一、直接回答

**用户的判断是对的：火红的超短项是「写死地址重定向」，不是替换表。**

实测证据：

| 检查项 | 数据 |
|---|---|
| 中文文本区内 ≤6 字节中文串 | 3,125 个 |
| 其中有指针指向 | 557 个（17.8%） |
| **有指针的里面，指针被改成指中文** | **555 个（99.6%）** |
| 单字串（「是」「否」这类） | 2,980 个 |
| 其中 46 个有指针，**43 个（93.5%）指针已改指中文** |

**火红没有任何形式的替换表。它就是把指针值改成指向新中文串。**

---

## 二、三种典型情况

### A. 原版已有指针 → 改指针值

```
0x6D2BF0  f7 01 f0   （1 个汉字 + FF）
  @0x136B38: 原版 0x083DD826 → 汉化 0x086D2BF0    [已改指中文]

0x6D3E5C  f7 00 4a
  5 处指针，其中代码段 3 处
  @0x12AE34: 原版 0x083DE89B → 汉化 0x086D3E5C    [已改指中文]
```

### B. 原版是指针数组（元素指向未使用区）→ 填新值

```
0x6D3ED7  f7 04 b7
  @0x7B8614: 原版 0xFFFFFFFF → 汉化 0x086D3ED7    [新填]
0x6D3EF5  f7 04 b7
  @0x7B861C: 原版 0xFFFFFFFF → 汉化 0x086D3EF5    [新填]
```

**原版这些槽位是 `0xFFFFFFFF`（空）**，汉化把指针填进去。这印证了
「整表换指针表」的做法——原版预留了指针槽但没用。

### C. 无指针的 2,568 条 —— 不是独立项

**关键澄清**：这 2,568 条不是「无处安放的短文本」，而是**长串被 `FD xx`
分段指令切开后的片段**。

```
0x6D0166  f7 00 59 f7 00 b4   前字节 0x58
  before: ...f7 00 02 f7 00 03 f7 00 04 f7 00 58
  after : ff ff ff fd 01 f7 00 30 ...
                  ↑ FD 01 = 分段/换行指令
```

抽样 600 条，**前字节是 FF 的 0 条**（若真是独立串，前一个串必然以 FF 结尾）。
全是 `FD` 指令隔开的长文本内部片段。

⇒ **不是需要单独处理的短项，它们随所属长文本一起搬走。**

---

## 三、火红为什么不需要替换表

对照 `FIRERED_FULL_LOGIC.md` §2.5：

> 「是 / 否」这类选项在火红里就是**普通的 6 字节串，有自己独立的指针**，
> 与长文本无差别。这解释了火红为什么不需要 `slt2` 那种「实时替换表」。

本轮的补充证据：

1. **短 ≠ 无指针**。557 个短串里 555 个有指针且被改（99.6%）。
2. **无指针的短串不是独立项**，是长文本内部片段。
3. **原版预留了空指针槽**（`0xFFFFFFFF`），汉化直接填入。

---

## 四、对 ruby 的结论

**ruby 的 SLT2 里，「是/否」这类超短项完全不需要走替换表。**

按优先级：

| 情况 | 数量 | 做法 |
|---|---|---|
| 原版有指针 | 待查（对应火红 555 条） | 直接改指针指向中文（A0 修指针识别后自动覆盖） |
| 原版是空指针槽 | 待查（对应火红那批 `0xFFFFFFFF`） | 填入新指针 |
| 长文本内部片段 | 对应火红 2,568 条 | 随所属长文本一起搬走 |

**⇒ 超短项（选项「是/否」等）不需要独立的 SLT2 通道。**

现在 ruby 的 SLT2 里 `性格名 6 条`、`树果名 21 条` 这类，大概率都能改成指针重定向。

---

## 五、SLT2 退场后的最终形态

```
F980  →  删除（A 阶段：改指针 / 换指针表 / 缩句）
SLT2  →  删除（B 阶段：
            · 宝可梦名/训练家名 → 火红式静态中文表 + 改读取路径
            · 超短项           → 指针重定向，随 A0 一起解决）
```

**最终只剩一套机制：F900 编码 + 指针重定向 + 静态数据表。**
与火红完全一致，零运行时查表。
