## 2. 窗与 VRAM（origin ROM 表实测）

`0x081BB9E0` 起 `{id, tpl*}`：

| id | tpl | tileData | tilemap | 备注 |
|----|-----|----------|---------|------|
| **0x24** | `0x081BB7B4` | **`0x06000000`** | `0x0600F800` | P31 认的左侧 tpl |
| **0x25** | `0x081BB7CC` | **`0x06000000`** | `0x0600F000` | bg2；**与左栏同 charblock 0** |
| **0x2F** | `0x081BB574` | **`0x06008000`** | `0x0600F800` | ListRedraw 内 `movs r0,#0x2F` |

要点：

- 左栏与 id `0x25` **共享 charblock 0** → 任一方按 grid 写字都会覆盖另一方仍挂在 tilemap 上的字模。
- 列表 `0x2F` 在 charblock 2；P36 `scrub_*` 在 `Init(0x2F)` 后应只打 `0x06008000`，**解释不了左栏被清**（除非运行时 `gMenuWindowPtr` 仍指错窗——待 GDB 一锤）。
- 现 hook：`DetailEnter` / 注释把「左栏」写成 `LEFT_WIN 0x25`，与表里「P31 tpl = id 0x24」不一致 → **进详情 Blank 可能 Blank 了错误窗的 tilemap，却通过共享 VRAM 误伤真左栏字模**。

## 5. 根因判断（待 GDB 最终钉死的只剩窗指针）

**主因（高置信）**：详情路径与左栏抢 **charblock 0**；`DetailEnter` 按 `0x25` Blank/绘制后，左栏 tilemap（更像 `0x24`/`081BB7B4`）仍指向已被改写的字模 → 地点/标签「像被随机清」。换项时 origin 只重打部分左栏串，于是出现「注册人数在、对战次数没了」这种半截状态。

**次因（中）**：退回后缺少「强制完整左栏重绘」（只靠 NEED_BLANK 清右栏），与 P35b 进详情跳过左重绘对称，退回侧没有补回来。

**列表红 0/6（中低，bot 未复现）**：仍归详情 `\CC0505` / 红条路径在 `0x06008000` 的残 tile；P36 定型帧已压到 0，用户路径可能更贴滚动/半帧，或 gutter 在 Blank `x=13` 左侧。扩 bot 已含加压；动手前可再抓 `B*_back_f_*` 过渡帧。

## 6. 拟修复方案（确认后再改）

只动训练家之眼窄钩，不改全局 `0x00`、不改短语。

1. **核对窗 id（必做）**  
   GDB/`Menu_PrintText` 前：地点与「注册人数」到底 `Init` 的是 `0x24` 还是 `0x25`。以实测为准改 `DetailEnter` 的 Blank 目标。

2. **退回列表强制左栏全量重印**  
   在 `NEED_BLANK` 分支（或 ListRedraw 首次满页后）：`Init(真左窗)` → Blank 统计矩形（保地点策略与现注释对齐）→ 调 origin 左栏打印（原 `EC2E0` 一类），保证地点+两标签+两数字一次齐。

3. **收窄 P36 scrub**  
   保留每行 **tilemap Blank**；`scrub_list_row_band` / 全 arena 改为「只清右栏 tilemap 当前引用的 tile」或详情退回时一次、滚动时不 scrub——避免任何误指窗时的误伤。若 GDB 证明 scrub 基址永远是 `0x06008000`，左栏修复可不依赖删 scrub，但仍建议滚动路径去掉过重 scrub。

4. **列表红**  
   左栏修好后，用同 bot 再跑；若用户路径仍见红 `0`/`6`，再对详情红标签占用的 list 窗格做退回时额外 Blank（可含 `x=12` gutter），仍禁止全局清屏。

验收：同 `_probe_te_cycle` 下 `B*_back` 地点白墨≈origin、`C_sel_up` lab2 白墨≈origin、列表定型饱和红保持 0；再交用户手测来回。
