## BUG1：左侧底色

### 像素对照（帧 077）

| 区域 | origin 白字邻域主色 | translated 白字邻域主色 |
|------|---------------------|-------------------------|
| 左侧统计/地点 | 面板粉 `(255,181,165)` + 阴影 | **错粉** `(255,156,156)` 为主 |
| 右侧列表同一帧 | 面板粉 | 面板粉（正常） |
| tip / start_menu | — | 无错粉块 |

计数：`nav_trainer_left_stats` translated `wrong_pink=771`，origin `0`；`nav_list_right` translated `wrong_pink=0`。

### 机制

- 中文网格对非墨像素铺 `tpl[6]`（`DESIGN_TEXT_12PX_GRID.md` §3 / `AXVJ_UI_ISSUES` 定案）。
- 左侧经 `0x080EBA40` → `BasicInitMenuWindow(0x25)` 再 `Menu_PrintText`；`tpl[6]` 映成浅粉，**不等于** BG 图画的面板粉 → 可见「字块底」。
- 右侧列表另一模板；`tpl[6]` 与列表粉底一致 → 同引擎无块感。
- origin 日文邻域直接是面板粉（无错粉），不是「中文独有全局填底」，而是**这一侧模板色与底图不一致被 12px 放大块暴露**。

### 为何不是全局 hook / 全局改 bg

历史三选一已否掉全局 `bg=0`（dex 好但 tip 透点阵）。当前全局 `tpl[6]` 对 tip/菜单/列表仍正确。  
只动左侧窗：打印前强制该窗 `bg=0`（或换匹配色），用场景锁，避免波及 tip。

## BUG2：右侧空格

### 原版契约（JP `0x080F228C`）

```
dest[0] = 0x00;                    // 前导空格
StringCopyPad(dest+1, class, fill=0x00, width=10);  // 职业固定 10 字节
StringCopyPad(..., name, fill=0x00, width=5);       // 名 5 字节（汉化盘已打成指针+width=0x15）
```

日文 1 字节 ≈ 1 格：短职业靠尾部 `0x00` 垫出与名字的列缝。

### 汉化盘上的补丁（patch-table，函数体内）

| 项 | origin | translated |
|----|--------|------------|
| 职业 stride | `×0x0B` | `×0x2C`（44） |
| 名 | `r4+4` 内联 | `ldr [r4,#4]` 指针 |
| 名 width | 5 | `0x15`（21） |
| **职业 width** | **10** | **仍为 10** |

### 为何「少爷」有空、「香氛姐姐」没有

`StringCopyPad` 按**字节**计数。F7 一字 4 字节：

- 短职业（如「少爷」）≤10B → 仍有尾 `0x00` → 屏上有缝  
- 长职业（「香氛姐姐」等）>10B → 拷满串后 `r3` 耗尽，**不再垫空格**，名字紧接 → 粘连  

同屏已证明：不是名字表丢了空格字符，是**列宽算法仍按日文 10 字节**。

### 调用面（origin 全 ROM `BL 0x08004724` 共 16 处）

含 width=8/5/10/15/16 等；**唯一「职业 10B + 名」拼成一行再 `Menu_PrintText(…,13,y)` 的是 `0x080F228C`**。  
改 `StringCopyPad` 本体会牵全部 16 点；列布局问题应留在拼接函数（或该行的打印点）。

### 与旧台账关系

`AXVJ_UI_ISSUES` §1–3 记过同一函数缓冲 17B / 越界；现网盘已扩名宽与指针，**列缝问题仍在**，属同一站点的布局债，不是新的全局渲染回归。
