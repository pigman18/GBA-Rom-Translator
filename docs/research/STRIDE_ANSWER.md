### 疑问 1：数目是不定的吗？

这个数字来自固定扫描：扫 `= table_base + 0x08000000` 的 u32 → 找引用它的
`ldr [pc,#imm]` → 去重。**纯机械，没有不确定性。**

我之前说「不定数目」是被自己算法结果波动（52→74→38）误导了。
**波动的不是站点数，是我的识别率。**

### 疑问 2：能不能静态查出来？

**能，而且必须能。** 你的理解链完全正确：

```
找到所有引用点 → 改基址字面量 → 读取方式（stride 常量）跟着改
```

「这个站点乘的是多少」是一个**编译期常量**，藏在指令里。
用符号执行必然能算出来：

```
把 index 当符号 i → 追踪寄存器里 a*i+b 的表达式 → 遇到 base+i 时读出 a
a 就是 stride，确定值，不是猜
```

### 疑问 3：那我为什么做成"猜"的样子？

**因为我用模式匹配代替了数据流分析。**

| 我做的（错） | 应该做的（对） |
|---|---|
| 窗口内找"看起来像乘法"的 `lsls` | 符号执行算 `i × K` |
| 猜哪条是 stride | K 算出来就是答案 |
| 报"覆盖率 74%" | 报"每站点 K=多少 或 不按 stride 访问" |

## 三、剩余失败的具体原因（已定位）

### 原因 A：`bl` 返回值处理太粗糙

我把 `bl` 的返回值一律设为 `Lin(1)`（视作新 index）。
但实际有些 `bl` 返回的是**字节长度**、**指针**或**其它值**，
不是 index。需要区分「取第 i 项」和「取长度/指针」。

### 原因 B：函数入口前的参数传递

很多站点的 index 来自函数参数（`r0` 传进来），
而我从窗口中间开始模拟，看不到调用方设的参数。
**应该从函数入口开始模拟，而不是固定回退 64 字节。**

### 原因 C：`ldr` 后还有计算

部分站点的 stride 乘法在 ldr **之后**（如道具名 0x0A53AC），
我的前向窗口只有 24 字节，可能不够。

### 原因 D：`mov sb, r1` 这类高寄存器

高寄存器 mov（0x46xx）我解码成 `movs` 但没处理 `sb/fp/ip` 等 r8-r12，
导致值丢失。

**这条路是对的，但要把符号执行器做完整，还需要**：
1. 从函数入口（而不是固定窗口）开始模拟

3. 支持 r8-r12 高寄存器
4. 前向窗口放宽到整个函数

这大概还需要 2~3 轮迭代。**但方向确定，不再靠猜。**
