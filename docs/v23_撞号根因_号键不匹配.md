## 1. 决定性实测数据

### 1.1 窗口实例（CHS_TRACE 冷启动 dump，队伍页 `t_sum2`）

| # | win | tpl | TILE_DATA | TILEMAP | TB | CUR_X/Y | tm | 记录数 |
|---|---|---|---|---|---|---|---|---|
| 0 | `0x0202E658` | `0x081BB46C` | **`0x06008000`** | `0x0600F800` | 1 | 2 / 1 | **3** | 58 |
| 1 | `0x03004170` | `0x081BB43C` | **`0x06004000`** | `0x0600F000` | 1 | 5 / 4 | **1** | 22 |

> 🔴 **推翻上一轮的推论「两个窗口共用同一 charBase 号段」**：
> `0x06004000` 与 `0x06008000` 是**两个不同的 charBlock**，索引空间相同但**绝对地址不同**，
> 两者**互不相撞**。真正撞的是「我们的号」与「引擎自己在同一 block 里的号」。

### 1.2 `t_bag` BG0（charBase `0x06008000`）

```
原盘 BG0 引用号 118 个；其中被 >=2 格共享 36 个
我们改过内容的「原盘引用号」24 个:
  [93,94,117,118,165,166,169,170,173,174,175,176,177,178,181,182,185,186,229,230,231,232,313,314]
⚠ 其中「原盘被 >=2 格共享」的 6 个: [93, 94, 175, 176, 313, 314]
   号 93 ← 原盘被 (r6,c16)、(r10,c16)、(r15,c4) **三格**引用
```

⇒ **光标一动 → 列表项内容变 → 我们重画号 93 的内容 → 远处 (r15,c4) 的内容同时变。**
这就是用户说的**「固定位置被替换」**，不是「我们没画」，而是**我们把号 93 这台「公共电视台」换了信号**。

### 1.3 `t_party` BG0

```
原盘 BG0 引用号 41 个；其中被 >=2 格共享 23 个
我们改过内容的「原盘引用号」2 个: [34, 38]
⚠ 其中共享的 1 个: 号 38 ← 原盘被 (r2,c16)、(r2,c18) 引用
```
⇒ `Lv` 的字母 `v`（引擎给的号）被我们覆盖 ⇒ 屏幕上只剩半个记号。

### 1.4 `t_party` BG2（消息框，charBase `0x06008000`）

```
map 差异格 30/600
仅 A 引用号 [521,522,523,524,525,526]
同号但内容不同的 tile 4 个: [517,518,519,520]
```
⇒ 号段 `512..526` 是**消息框框体**（`512/513/515/518/519/520` 两版逐字节一致）。
原盘在该号域写的是**逐字内容号**；我们把它当成**自己的画布号**去写 ⇒ 框体被撕。

### 1.5 `t_sum2` BG0 的关键 4 格

```
r6  c25:180>116      r8  c6:206>116
r9  c25:310>116      r12 c25:374>116
```
原盘这 4 格都指向**同一个号 `116`**（引擎给该字符的图集号），我们指向 4 个不同的号。

### 1.6 引擎预取 worker `0x080029E0` 逐指令（本轮反汇编）

```
80029e0: push {r4,lr}
80029e2: r0 = *(0x03000328)      ; → 模板指针
80029e6: r0 = [r0,#9]
80029e8: if r0==0 return 1 ; if r0==1 继续
80029f8: r4 = *(u16*)0x0300032E  ; 全局进度游标
8002a08: (循环体) r0 = *(0x03000328)
8002a0e: r1 = *(u16*)0x0300032C
8002a10: r2 = r4 & 0xFF
8002a14: bl 0x08002A50           ; InitWindowTileData(tpl, r1, idx)
8002a18: r4 += 1
8002a1e: r0 = *(u16*)0x0300032E + 16 ; 每批 16 个
8002a22: if r4 < r0 继续
8002a24: *(u16*)0x0300032E = cursor + 16
8002a30: if cursor == 0x1000 → return 1
```

⇒ 它是**全局把日文 8×8 字体逐批 4bpp 化、写进「模板的 TILE_DATA」低号段**的 worker，
游标按 16 递增直至 `0x1000`。与观测一致：

| 页面 | 原盘 BG0 引擎自用号最大值 |
|---|---|
| 队伍页 (`o_party`) | 116 |
| 背包页 (`o_bag`) | 197 |
| 汇总页 | 213 |

**全部 < 256** ⇒ 引擎自绘图集落在**本 charBlock 的低 256 号**。

## 2. 唯一根因

> **我们按「位置」定号（`(CUR_Y>>1)*64 + CUR_X*2 + TILE_OFFSET`），
> 引擎按「字符」定号（同一字符全屏共用一个图集槽）。**
> 两套键在**同一个号域**里必然互相踩：
> ① 我们改的号可能正被引擎的**其它格子**引用 ⇒ 串改（问题 1、3）；
> ② 我们的号可能落在引擎的**框体/图标号段**里 ⇒ 撕 UI（问题 2）。
>
> 号域本身不是瓶颈 —— **「键」错了才是。**

## 3. 修法方向（已被红线圈定）

用户红线：**禁抬水位 / 禁设不可用区 / 禁静态避让带 / 禁账本** ⇒ 「另开一段号避开引擎」**出局**
（`[256,512)` 只有 256 格，而队伍页光展开就要 ~400 格，一涨就崩 —— 正是用户预言的失败模式）。

⇒ **唯一出路：把我们的号也改成「字符键」**，即
`T(X) = 引擎给字符 X 的那个图集号`，让同一字符全屏共用同一批 tile：

| | 引擎现状 | 我们改为 |
|---|---|---|
| 键 | 字符 | **字符**（与引擎同） |
| 号 | 引擎图集槽 | **引擎图集槽**（接管） |
| 同字符多格 | 共用 1 槽 | 共用 1 槽 ⇒ **天然不串改** |
| 容量 | 只依赖「当前屏上有几个不同字符」 | 同 ⇒ **无容量上限** |

**唯一未决的几何问题**：引擎一个槽 = 8 宽×16 高 = 2 tile；我们要 **11 宽×11 高**，
横跨 2 列 ⇒ 需要 2 个相邻列，会压到**相邻字符的槽**。

## 4. 待用户裁定的分叉

| 方案 | 做法 | 代价 |
|---|---|---|
| **J1 接管全块** | 保留 P32 停用（引擎预取照跑，给数字用），我们按**字符键**在自己的子域里编号，并把该子域**按字符去重**（同字符只占一处） | 需先确定「引擎图集槽 → 字符」的可计算公式（再做一步 `0x08002A50` 三个分支的逆向） |
| **J2 接管图集槽** | 直接把字符 X 的 11×11 写进 `X` 的槽 + 下一列，并让**被挤掉的那个字符**也改用同一批 tile | 会让「相邻字符」也变宽，需要串行重排，实现复杂但容量无限 |

我的建议：**J1**（先把「号 = 字符的函数」落地，几何用「同字符复用 + 相邻字符尾列共享」解决）。
