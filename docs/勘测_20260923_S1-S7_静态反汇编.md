## S1. TLWT（tm1 图集分配入口 0x08002950）全调用点

- BL 直调 **2 处**；字面量池引用 **0 处**（无人经函数指针表进它）：
  - `0x080685CA`：任务式流程——`bl 0x08002C28(全局窗对象,3)` → `bl TLWT(窗对象,1)` → 轮询 Multistep → 完成置 `[全局+0x264]=1`（0x080685E0~0x080685F4）。
  - `0x0806F006`：文本泵状态机内（见 S2）。
- 36 个 tm1 模板的 r0 全部经寄存器传入（无 `ldr r0,=模板` 直绑）⇒ **模板→调用流绑定属 G3**（gdb 半区）。
- **意义**：日版图集开启面收敛为 2 条流。B 迁移中「tm1 窗不再开图集、改走画布认领」只需在这 2 处语义上替换（或 TLWT 本体改画布契约返回 `2+w×h`，即 C1——但其下游 seam 见 S2）。

## S2. Continue(0x0806F00A) 与 e6f0(0x0202E6F0) 全 xref

- **勘误**：`0x0806F00A` 无任何 BL/字面量指向——它**不是函数入口**，是文本泵状态机里
  `0x0806F006 bl TLWT` 之后的落点。0923 分析文档 §4 S2 行的写法据此修正。
- 文本泵 = `0x0806EFC0` 起 5 态跳表状态机（跳表 @0x0806EFD8，`mov pc,r0` 分派）：
  - 轮询态 `0x0806F01C: bl Multistep` → `cmp r0,#0`；
  - 三个兄弟完成态各做 `SetBase(*0x0202E6E8)`（直调 0x0806F02A/09A/0EA + 中段 0x0806F04C/0A4/0F4/14A）并读 `*0x0202E6F0` 决定「下一窗起点」。
- e6f0 记录（0x0202E6E8/6EE/6F0 = win/tileOffset/容量）字面量消费：**6E8×26、6EC×3、6EE×13、6F0×4、6F2×5 = 51 处**，
  集中于 0x0806E8xx~0x0806F4xx 高层 API 簇；离群在 0x0804E9xx×3、0x08061Cxx/0x08061DBx（场景侧直读）。
- **意义**：C1（改 TLWT 返回值）的影响面首次被完整枚举 = 3 兄弟态 + 51 字面量。在逐处对齐方案写出前，**C1 冻结维持**——这正是两次事故（09-08/09-23）死亡的那条缝，现在有了全图。

## S3. SetBase(0x08062080) 全调用点

- 直调 14 处：`0x0800AC7C 0x0800AC8C 0x0803FFDC 0x08045076 0x08045826 0x080487DE 0x08048B3E 0x0804B7D8 0x0804BDD8 0x0804C2E6 0x0806F02A 0x0806F09A 0x0806F0EA 0x0810CE90`
- **中段入口 0x08062094 另有 13 处**（绕过序言的尾调约定）：`0x0803FFEA 0x08045086 0x08045836 0x080487EC 0x08048B4C 0x0804BDE8 0x0804C2F6 0x0806F04C 0x0806F0A4 0x0806F0F4 0x0806F14A 0x0810CE8A 0x0810CE9E`
- 合计 **27 处**。泵内 3+4 处负责框带 charBase 翻转；其余为场景侧（战斗/菜单/图鉴等）。
- **意义**：画布替换图集后，框带落点重算的面 = 这 27 处 + 泵 3 兄弟态，全部静态可枚举，无隐藏入口（BL/字面量两路都扫尽）。

## S4. Multistep(0x080029E0) 本体语义与 stub 等价性

- xref：BL 2 处（0x080685E0 任务流、0x0806F01C 泵态）；字面量 0 处。
- 本体（反汇编定案）：
  1. 读 `[*ptr+9]`（textMode）：0 → 返 1；2/3 → 返 1（不做图集）；其余进渲染。
  2. 渲染循环：以 IWRAM 计数器为游标，**每次调用渲 16 个字形**（`0x08002A14 bl 0x08002A50` = InitWindowTileData 单字形+写 tilemap 引用），计数器 +0x10。
  3. 计数达 0x100（256 字形全渲完）→ 返 1（完成）；否则返 0（未完）。
  4. 邻接函数 `0x08002AF4` = 一次性 256 字形循环变体（mode0 线性初始化用）。
- 两个轮询方语义均为「返 1 = 完成」：任务流置完成标志；泵态走出图集分支。
- **stub（`mov r0,#1; bx lr`）等价性（静态）**：返 1 ⇒ 双方都走「立即完成」分支，无死循环、无状态饥饿；
  唯一行为差 = 图集 tile 永不渲染 —— 即停图集的本意。**静态证明成立**；实机回归仍按四步法走一次截图。

## S5. WriteGlyphTilemap_FontX 家族（0x080034D4~0x080035E0）

- 表结构（反汇编重证）：
  - FontFuncTable@0x081BB3AC 7 项：[0]0x08003569(tm0) [1]0x0800360D(tm1) [2]0x0800338D(tm2) [3]0x08003495(tm3) **[4]0x08003585 [5]0x080035A1 [6]0x080035C9**
  - FontSubTable@0x081BB3BC：font0/3→0x08003584、font1/4→0x080035A0、font2/5→0x080035C8、font6→0x080035E4
- 三函数行为：
  - `0x08003584`（Font0/3）：upper = tileBase+2·glyph，lower = upper+1（**N1 修正在此再次实证**），`bl 0x080036DC`(UpdateTilemap)；
  - `0x080035A0`（Font1）：经 2 字节小表查 upper/lower 偏移再 UpdateTilemap；
  - `0x080035C8`（Font2）：upper = tileBase+0xD4、lower = tileBase+glyph。
- **三函数全 ROM 零 BL 直调、零字面量引用** ⇒ 静态假名写 tilemap 引用的唯一入口就是这两张表。
- 辅助面：`0x080034E0`（win[0x1A/1B/1C/1D] → tilemap 指针）7 个调用方 = 各 mode 的「按游标画一格」函数群（0x08003B10/0x08003B44/0x08003B64/0x08003C7E/0x08003EB6…）。
- **意义**：B/C1 中「静态假名引用改指画布格」= 改 FontFuncTable[4..6]（或 FontSubTable）**4 个表项**即可全覆盖，无需找调用点。armips 改表与现行 hooks_origin.s 同机制。

## S6. Text_ClearWindow 日版孪生（定案）

- **日版 Text_ClearWindow = 0x08003BA8**。证据三重：
  1. 美版 0x08004318 编译码相似 72%（96B 窗口，同区最优）；
  2. 结构逐位吻合 pret `Text_ClearWindow`：`push {r4,lr}; switch(win[0xA])` → mode0 走行清助手并 `win[0x18]=4`，mode1/2/3 分派；
  3. **4 个 BL 调用方**：`0x08002F56`、`0x08002F8E`（InitTextPrinter 邻域，打印前清）、`0x080032EA`（PrintNextChar 链，FA 清行控制码≈ExtCtrlCode_ClearWindowTextLines）、`0x0806F3D2`（高层 API）。
- 行清助手 **0x08003C00**（=ClearWindowTextLines_TextMode0_TextMode1 孪生）：复位 win[0x1B]/[0x1D]/[8]，
  fill = palette<<12 | blank tile（经 0x08003708/0x08003728/0x080041BC 组合），**4 行 × lineLength 个 u16 表项、行步进 32**。
- 与美版差异点：美版 mode0 清后 `tileDataOffset=2`，**日版 = 4**【画布接线时按日版值保真】。
- **意义**：B 四件套的 Text_ClearWindow 不需要从零发明——日版已有等价物，画布化后只需让它按画布语义填窗私有区。

## S7. 美版模板表复现 + 与日版 tm1 家族交叉验证

- 复现（US 1.0 ROM @0x081E6C3C，28B/项 ×58）：**58 项全可解析；50 项标准 30×20；特例 7 项**
  —— 26×20 (0x081E6C58 tm0) / 8×60 (0x081E6CAC) / 8×64 (0x081E6D38) / 16×32 ×3 (0x081E7048/0x081E7278/0x081E7294) / 32×32 (0x081E70F0)。
  **与 `调研_20260909_tm1菜单窗wh映射.md` 完全一致**（首轮脚本报 2 特例是其校验器误杀，见下）。
- **新证（术语修正）**：特例里的 tm2 窗 `tileData=0x02039360(EWRAM)、tilemap=0` ⇒ **美版 mode2 是 EWRAM 像素缓冲窗**（渲染写缓冲、后处理刷 VRAM），不是 VRAM 画布；`0x081E6C74`（30×20 font4 tm0）的 tileData 在 0x06010000（cb4/OBJ 区）——战斗 HP 专用窗佐证「专用窗逐个 hook，美版同样躲不掉」。
