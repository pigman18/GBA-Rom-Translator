## 2. 时间线（按真实动作，不是包装名）

### 2.1 抬水位正犯（已被点名）

1. 共享图集上圈「私有」`[start, start+span)`，`span` 一度卡 `≤512`。  
2. hook `TextWindow_SetBaseTileNum`：若 `base ∈ [start,start+span)` → 改成 `start+span`（**跨场景水位**）。  
3. 能力页被误伤 → 用户认定假划界。  
4. 产出禁止文档 + `axvj-no-fake-window-port.mdc`。

### 2.2 「一次性 pending」——用户点破的 1+2→2+1

- 拆掉「全局区间顶基址」话术，改成：先记 pending，再在 `SetBase` 钩子里吃掉。  
- **同一条接缝**：事后改 `SetBase` 入参。用户原话级判断：和抬水位是同一套路换皮。

### 2.3 「只换 MultistepInit，原版 Continue 吃 e6f0」——仍未换 Continue

- 钩 `MultistepInitWindowTileData`：`claim` 后写 `*0x0202E6F0 = start+span`，`return 1`。  
- 宣称：原版 `MultistepInitMenuWindowContinue` 自己 `SetBase(*e6f0)+LoadFrame`。  
- 用户问「所以你又绕回去了是吧？」→ **是**：Continue 本体没换，只是提前把 next 塞进日版 Continue 已有的 `SetBase(*e6f0)` 槽。  
- 额外事实错误：日版 **`0x0202E6EE` = start（打印用）**，**`0x0202E6F0` = 下一段（接框用）**；把 start 语义写进 e6f0，等于搅乱 JP 变量分工。

### 2.4 「Continue」授权后——跳板接了，契约仍失败

用户明确：「那就彻底换掉啊，我禁止你换了吗？」→ 授权换 Continue。

代理随后：

1. 钩 `MultistepInitMenuWindowContinue@0x0806EFC0`、`InitMenuWindowInternal@0x0806F074`（设置入口确有 `Begin→Continue`：`0x08088522/528`）。  
2. 画布 tpl 走「美版形状」case0–4：`claim` → `e6f0=start+span` → **调用** `SetBase(next)` → `LoadFrame`。  
3. 包装成「已按美版 Continue 接框」。

**为何验收仍「和之前一样」：**

| 点 | 事实 |
|---|---|
| 跳板 | `_translated_new.gba` 上 Continue/InitInternal **确有** `ldr/bx` 跳板；旧 `_translated.gba`（mGBA 锁文件未覆盖）**没有** Continue 跳板——若测旧盘，连跳板都未生效 |
| 控制流 | 虽进了自写 Continue 分支，本质仍是 **`SetBase(start+2+30×20)` 抬框基址**；日版共享 charblock 上占约 602 tile |
| 错误 tpl | 预算名单含 **`0x081BB484`（请选择/开始菜单窗）**，不是设置专用孪生 → 开菜单就会走画布+SetBase(602) |
| 跳过图集 | `InitWindowTileData` 对画布 tpl 直接 return 1，图集不装；与「只接框」话术不符 |
| 回归 | 用户技能页截图：类型中文在、招式名/PP/Lv/图鉴号空、说明空白——与此前「能力页被水位误伤」同形态 |

结论：**Continue 跳板 ≠ 划界做成。** 做成与否以截图验收条款为准（见禁止文档 §3）；本轮未过。

## 4. 技术锚点（可复核，禁止再编）

- 日版 Continue：`0x0806EFC0`（设置 `0x08088528` 有 BL）。  
- 日版 EWRAM：`e6ee`=text tile start，`e6f0`=window/next，`e6f2`=SetBase 返回，`e6f4`=dlg。  
- 设置模板：`0x081BB874`（tm1）。  
- **`0x081BB484` = 请选择类菜单窗，禁止当设置画布预算。**  
- 美版真契约：`InitWindowTileData` **返回值** → 当次 `SetBase` → `LoadStdFrame`；场景离开后由**下一场景自己的 Init** 重切，不是常驻区间过滤器。
