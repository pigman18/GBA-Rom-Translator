# 复盘 2026-09-09：把美日两套 textMode 枚举当成同一个东西（最基础前提漏检）

> 一句话：美版 Ruby(AXVE) 的 `textMode` 只有 **3 个值**（0/1/2），日版 Ruby(AXVJ) 有 **4 个值**（0/1/2/3），
> 语义完全不同、不一一对应。这个一眼可见的差异，在**已经采集美日双方 gdb 日志、已经大量反汇编双方函数**的前提下，
> 被漏检了约 10 小时（一个通宵），导致整晚「移植美版引擎」的工作全部建立在错误地基上，最终作废。

---

## 一、错误本身

### 美版（AXVE）textMode —— 只有 3 个值

`tools/pokeruby/src/text.c:26-31`：

```c
enum
{
    TEXT_MODE_UNKNOWN0,     // = 0
    TEXT_MODE_MONOSPACE,    // = 1 等宽
    TEXT_MODE_UNKNOWN2,     // = 2 变宽画布 (variable width?)
};
```

值域 **{0, 1, 2}**。`UNKNOWN2` 是变宽画布（`InitVariableWidthFontTileData` 那一套）。

### 日版（AXVJ）textMode —— 4 个值，语义完全不同

| 值 | 语义 | 落址方式 |
|----|------|----------|
| 0 | 线性 | `tile` 线性递增 |
| 1 | 图集寻址 | `win[0x0B]` 查表 + `bl 0x81B12DC`（读预渲染图集） |
| 2 | 缓冲直绘 | `win[0x20]` 缓冲直绘 |
| 3 | 网格 | `tile = base + cur_x + 2 + cursorTileX + 30*(cur_y + cursorTileY)`，步长 30 写死 |

值域 **{0, 1, 2, 3}**。

### 致命的三点

1. **值域不同**：美版 3 个值，日版 4 个值。
2. **语义不一一对应**：两边同样叫 `textMode`，但含义各是一套。
3. **日版 tm3 在美版枚举里根本不存在**（美版最大到 2）。

## 四、根因（不是能力边界，是工作方法）

1. **没做「差异基线」**：动手前应先建一张表——美日双方的枚举、结构体布局、函数清单、BG 初始化，逐项并排对照。这一步被跳过。
2. **单边深入、全局失明**：反汇编日版看日版语义、反汇编美版看美版语义，各自看得很细，却从没把两边并排。
3. **默认「同名即同物」**：两边都叫 `textMode`，就默认是同一套，没验证——而这恰恰是「两套不同版本的游戏引擎」最不该默认的地方。
4. **把「移植」降格成「改 hook」**：注意力全在「怎么接线让日版窗口走美版画布分配器」，而不是「先对齐两套系统、再重写」。
5. **数据在眼前，只做了单边统计，没做双边对照**：日志里 textMode 的值域差异一眼可见，我却只做了「日版内部按 textMode 计数」，从没做过「美版值域 vs 日版值域」这一行对比。

---

## 五、教训（写进流程，防止重犯）

1. **移植 / 对齐两套系统的第一步永远是「差异基线表」**：枚举、结构体、函数签名、寄存器布局，逐项并排，确认前提成立才允许写代码。
2. **「同名」是最大的陷阱**：跨版本/跨语言/跨引擎时，同名字段、同名函数、同名枚举，必须先证同义，默认「不同」。
3. **日志/数据一旦到手，第一动作是做「横向对照」**（美 vs 日），而不是「单边深挖」（日内部）。
4. **通宵产出的前提没验证，全部作废**：进度 ≠ 正确。半成品纪要写得越满，越容易自我强化错误方向。

## 六、遗留结论（给接手者）

- 完整移植美版引擎 = 把日版 **4 种** textMode 语义重构为美版 **3 种**，牵动整个文本引擎
  （`InitTextPrinter` / `PrintNextChar` / `AddToCursorX` / `GetCursorTilemapPointer` / `ClearWindow` /
  `UpdateBGRegs` / 图集装载 / UI 窗接管 全套），**不是 hook 两个函数能覆盖**。
- 已钉死的关键事实见 `.workbuddy/memory/MEMORY.md`：
  - 美日 textMode 枚举差异（本复盘主题）
  - `UpdateBGRegs`（text.c:1740）是「BG 层读哪个 cb」的动态重排命根，日版是开机静态写死
  - 美版四件套（画布分配器 / BGxCNT 动态重排 / 图集装载接管 / UI 窗接管）必须一次做全，零敲碎打必坏
