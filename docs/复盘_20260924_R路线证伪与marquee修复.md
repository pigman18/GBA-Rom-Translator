# 复盘 2026-09-24 — R 路线证伪 + marquee 真触发点修复

## 一、R 路线（表级替换）实测证伪：用户截图「空白前出现奇怪的文字」

三个结构性缺陷（全部静态可证，非猜测）：

### 缺陷 1：win[0x16] 改写破坏官方图集管线（R 版「怪字」主因）
- R 版 ITP hook 把 `win[0x16]` 从官方 tileBase 改写为画布基址（entry.s 写回 r2 参数槽）。
- 官方 tm1 管线 = **表项 + 图集像素配套**：官方写表项函数（FontSubTable 三函数）写
  `win[0x16]+偏移` 的表项，官方渐染（Multistep @0x080029E0，**基线 ROM 该地址=原版、
  是活的**，0924 字节比对）往图集写像素。两者都锚定 win[0x16]。
- 改写后：官方渐染往「画布」写日文字形像素、官方表项指进画布白格 → 文字区显示
  日文字形碎片/白格 = 「奇怪的文字」+「空白」。
- **T1~T4 为何「正常」**：它们从不动 win[0x16]（官方管线完好），画布只给自己渲染用
  ——所以「没区别」；R 版动了 win[0x16] 才炸。

### 缺陷 2：R4 劫持了一条本来正常的路径（前提过时）
- hooks_origin.s 注释称官方三函数「像素靠官方渐染=已停」——这是 v8 早期停图集 hook
  时代的过时记载；0924 实证渐染活着，官方表项+官方渐染 = 配套正常。
- `FontSub_Canvas` 双重错误：①强制 `win[0x1B]=tx0+1` 后官方调用方（0x08003620 实证）
  再 `+=1` → **每字双推进**；②把官方「固定位置」模型偷换成「游标定位」模型。
- R4 前提（假名路径休眠）本身也错：PrintGlyphTM1 是 tm1 一切官方字形打印的入口。

### 缺陷 3：602 格画布几何在日版 VRAM 布局下不成立
- v8 arena = [0x100, hi)，cb0 窗 hi=1024 → 602 连续可领成，base ≤ 0x1A5。
- 表项 10 bit（≤0x3FF）：base+2+599 最大 0x40A **越界**，尾部表项回卷+翻转位污染。
- 画布像素写 `TPL_TILE_DATA + base*32`（=cb0 起算）跨进 cb1；领断时「VRAM 非空」
  校验避开的是**当时已填充**区——ITP 时刻渐染未完成/UI 图形未解压的空区会被领走，
  官方随后写入 = 二次污染源。这与外挂模型「猜占用」同病：**官方像素写入者不认任何
  我们的账**。

## 二、marquee「118号道路 118号道路」真根因与修复

### 真根因（0924 反汇编定案）
- 官方换串重打入口 **0x08002E38**（独立 26B 函数；全 ROM 唯一调用链
  0x0807A80 列表控制 → 0x0806F388 包装 → bl 0x08002E38）只做：
  `win[4]=2; win[0x10]=新文本指针; win[0x14]=0; win[6]=0; win[8]=0; win[9]=0`。
- **不复位 win[0x1B]（表项列游标）与 px（像素相位）**。官方不需要：固定位置模型
  重打幂等。我们游标定位模型不复位 ⇒ 新串从旧列尾续打 + 旧表项残留 = 重复打印。
- T2b/c/d 三连败根因：修在 PrintNextChar 处、守卫 `idx==0 && px!=0` 依赖全局相位
  非零——相位是全体打印器共享单全局，随时被其他窗 v8_alloc_begin 清零 ⇒ 守卫失效。

### 修复（b4799ef + 一个桩）
1. `git stash`「R路线存档(2026-09-24证伪)」→ 回到 T3+T4 验收基线。
2. 桩 @0x08002E38（8B：ldr r3/bx r3/pool；r3 入口即死——原函数立即 movs r3,#0；
   r1=文本指针存活；覆盖区 39..47 跳转目标全 ROM 扫描 0 hits）。
3. 跳板 ReprintReset_Hook（entry.s）：push{r0,r1,r4,lr} → bl ReprintReset_hook_C
   （**无条件** v8_phase_reset + win[0x1B]=0，与官方换行状态机 0x08002E5E 清 0x1B
   语义一致）→ pop{r0,r1} → **内联重放原函数全函数体** → pop{r4}/pop{r0}/bx r0
   原样返回。不跳回 0x08002E40 的原因：跳回需不占 r0-r4 的临时寄存器装续跑地址，
   r5+ 是 callee-saved（存它必破坏 [r4][lr] 栈形）——内联是唯一安全形态。
4. 构建 12056B（基线 12004 + 52B）；ReprintReset_Hook@0x0880005c、C@0x08800b7c；
   armips 桩字节/恢复区/嵌入逐项验证通过。

## 三、教训入册
- 🔴 **win[0x16] 是官方图集管线锚点，永远不许改写**（渐染+表项函数都锚它）。
- 🔴 改底层前先核对注释前提的时代（「渐染已停」是 v8 早期停图集 hook 时代的事，
  现流水线没有该 hook）。
- 🔴 修重打印类 BUG：先全 ROM 找「触发点」（谁换的串），在触发点无条件复位状态；
  不要在打印字符处放条件守卫（依赖共享全局状态 = 不可靠）。
- 画布路线在日版布局下需要「每窗真实几何 + 官方像素写入时序」两项数据才能成立，
  静态推不出 → 已整体 stash，除非 gdb 实证否则不再启动。
