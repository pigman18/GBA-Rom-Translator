## 3. 运行时闸门设计（继承 v9 哲学，事件从「每字形」收缩为「开窗/关窗」）

1. **开窗认领闸门**（T1）：认领 1+2+w×h（+框/对话链）区间时，逐 tile：
   - VRAM 非空校验（v8_tile_usable 同款）；
   - 活引用位图查重；
   - 通过 → ours 段表登记（v8_seg 复用）；失败 → **显性失败**：IWRAM 计数 +0x03000328 镜像置错 + 该窗边框 tile 写警戒色（实机肉眼可见），绝不静默写穿。
2. **关窗释放**（T3）：ClearWindow 路径 + 窗对象销毁点释放段表项；位图清位。
3. **切换检测**（保留但简化）：画布语义下窗身份=画布段，(win,模板) 双键退化为单键 assert（v8q_is_switch 逻辑保留 ~10 行）。
4. **Arena 论证兜底**：静态论证（§4）+ 开窗当帧校验。谁在当帧真实占着 tile，校验就发现谁——不靠事前断言。

## 4. Arena 回收论证（静态 + 数据在手）

- **空间来源**：图集停用后，cb0(0x06000000)/cb1(0x06004000)/cb2(0x06008000)/cb3(0x0600C000)
  的 tm1 图集区即画布 Arena。普查实证 36 tm1 模板的 tileData 全部落在这 4 个 cb
  （cb0×16 / cb2×14 / cb3×2 / cb1×1，见勘测文档 S7 家族表）。
- **既有实机证据**：v8/v9 时代中文已实际写这些区域并实机通过（三闸门+设置页 S1）——
  「Arena 可写」不是推论，是既成事实。
- **谁还会写这些 cb（风险清单）**：日版原生只剩——①SetBase 27 处（翻 charBase，本身不写 tile 数据）；
  ②其他 BG 图形装载子系统（LZ77/DMA，目标地址由各场景决定）。②的静态全枚举成本高，
  **交给开窗当帧 VRAM 非空校验兜底**：真撞了会被闸门拦下并显性失败，而不是渲染错字。
- **容量数学**（分析_20260923 §3）：画布模型行耗=行像素÷8；最大窗 30×20=602 tile 需跨 cb，
  但高频窗（对话/菜单）≤510 单 cb 可容；跨段窗是否出现由实测清单验收（§6）。

## 9. T3+T4 实施记录（2026-09-23 晚，代码落地 + 汇编验证，待实机）

**T3 关窗释放闸门**（canvas.c，无新 ROM hook，纯记账侧）：
- **陈旧记录主动释放**：canvas_on_begin 一进门（在 tm 过滤之前）扫记录——
  win == v8q owner_win 且 tpl != owner_tpl ⇒ 记录必死（日志实证：同一
  TextPrinter 挂过不同模板），当场清槽。owner 换成非 tm1 窗时也能释放。
- **淘汰智能化**：无空槽时按「陈旧(同win异tpl) > rec0 最老」淘汰，
  不再盲目摘 rec0——修复「第三窗认领打断正在渲染的对话画布」。
- **释放语义勘误（相对本单 §3.2 原文）**：ours 段表**不删**——它是
  「我们写过、可回收」的白名单（v8_tile_usable 非空+ours→可重用），
  删段 = 该区永不可回收 = 泄漏；释放只清记录槽（保护随下次位图重建消失），
  位图本会话内保守多保一段，不显式清位。
- **回落显性计数** canvas_note_fallback：chs_emit 在 tm1 画布不命中转
  v8 回落前 +1（ADDR_CANVAS_FB_CNT=0x0203FF77，饱和 255，冷启动清零）。
  gdb 读数>0 ⇒ 有 tm1 窗没进画布 → 结合 flag bit0 定位窗 → 填 kCvDims。
