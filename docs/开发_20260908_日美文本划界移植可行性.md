# 开发文档：日版 AXVJ 文本引擎 vs 美版 AXVE — 划界层移植可行性

> 日期：2026-09-08  
> 性质：**开发决策文档**（检索 + 源码 + 日美 ROM 反汇编对照），不是已完成移植的验收纪要。  
> 范围：GBA Gen3 Ruby 文本 tile 管理（IWTD / GCTN / 清窗 / 汉化先例）。  
> ROM：`roms/origin/POKEMON_RUBY_AXVJ00.gba`（AXVJ）· `roms/origin/Pokemon Ruby Version(US).gba`（AXVE 1.0）。  
> 源码权威：pret/pokeruby `src/text.c` / `include/text.h`；先例 Wokann/Pokemon_GBA_Font_Patch（pokeRS）。

---

## 0. 一句话结论

| 问题 | 答案 |
|---|---|
| GBA 硬件层日美是否不同？ | **否**。VRAM / charblock / tilemap / 4bpp 规则相同。 |
| 能否「原样粘贴」美版 `text.c`（~4400 行）进日版？ | **否**。Window / WindowTemplate ABI 全错位；投入≈重写，语义增量≈0（见 §4）。 |
| 能否移植美版「划界 + 落址」**模型**？ | **能**，且这才是成熟汉化能干净显示的真正地基；工作量是「模块 + 日版接线」，**不是** 9000 行墙。 |
| 当前项目卡在哪？ | **开窗预算接线**（日版模板无 `w×h`、IWTD 不返回下一窗起点、菜单走 tm1 共享图集），不是「看不懂美版源码」。 |
| 禁止再走的假路 | 未划界时对共享图集套 `row×W`；吞掉 IWTD 后用屏宽假预算冒充；freelist / 抬水位当地基；把日版 `textMode` 改成 2 冒充美版画布。 |

## 1. 全网检索结论（外部先例）

### 1.1 成熟 Gen3 汉化全部站在美版（或同构）引擎上

| 工程 | 底版 | 形态 | 与 tile 管理的关系 |
|---|---|---|---|
| [Wokann/Pokemon_GBA_Font_Patch](https://github.com/Wokann/Pokemon_GBA_Font_Patch) pokeRS | 美版 Ruby | armips，hook `DrawGlyphTiles` / `GetGlyphWidth` / `GetStringWidth` | **零自建分配器**；直接调官方 `GetCursorTileNum` → `DrawGlyphTile_ShadowedFont` → `UpdateTilemap` |
| pokeE / pokeFRLG（同仓库系） | 美版 E / FR | armips，hook `RenderText` | 复用官方窗私有区 + `CopyGlyphToWindow` |
| CHPLUS 等旧美版汉化 | 美版 | 同上思路 | 同上 |

**公开先例没有一家在「日版共享图集 + 运行时领号」上做成全作级干净中文。**  
仓库旧结论（`调研_20260827_美版布局代码移植评估与全网成熟实现.md`）：「日版 RS 无宽度函数怎么补」全网无公开解 — 本项目是孤例，风险本就更高。

### 1.2 pokeRS 源码实证（GitHub 原始汇编）

`DrawGlyphTilesChinese.s` 关键路径（摘录语义）：

1. 判定双字节中文码区 → 取字模；  
2. `bl GetCursorTileNum`（官方）算 VRAM tile 号；  
3. `bl DrawGlyphTile_ShadowedFont`（官方 mask）；  
4. `bl UpdateTilemap`；  
5. `cursorX += 8`；仅当 `textMode != 2` 时 `tileDataOffset += 2`。

⇒ 汉化只换「画什么字」，**不换「字落在哪块私有预算」**。私有预算由美版开窗链已经划好。

### 1.3 pret 源码（美版机制出处）

权威文件：[pret/pokeruby `src/text.c`](https://github.com/pret/pokeruby/blob/master/src/text.c)、[`include/text.h`](https://github.com/pret/pokeruby/blob/master/include/text.h)。

与划界直接相关的函数（行号随 upstream 浮动，以符号为准）：

- `InitWindowTileData` → `InitVariableWidthFontTileData` / `LoadFixedWidthFont`  
- `GetCursorTileNum`  
- `AddToCursorX`（**仅 `TEXT_MODE_UNKNOWN0` 推进 `tileDataOffset`**；`UNKNOWN2` 只加像素游标）  
- `Text_ClearWindow`（清 **tilemap 引用**，不是 GC VRAM）

### 1.4 非目标噪声（检索时易混）

- GBA PPU「窗口」寄存器（WIN0/WIN1）= 硬件裁剪，**不是** 文本 Window 私有 tile。  
- NDS 四五代字库扩容（Xzonn 等）= 另一代架构，可借「懒加载字库」思路，**不可**照搬地址。  
- Bulbapedia Gen3 码表差异 = 编码层，不解释 tile 撞 UI。

## 2. 硬件层 vs 软件层（回答「美版改没改 GBA 底层」）

```
┌─────────────────────────────────────────┐
│ GBA 硬件：VRAM / BG / charblock / 4bpp  │  ← 日美相同
└─────────────────────────────────────────┘
                    ↑
┌─────────────────────────────────────────┐
│ 场景切段 + 窗框/UI 硬编码章              │  ← 地址不同，模型同构
└─────────────────────────────────────────┘
                    ↑
┌─────────────────────────────────────────┐
│ 文本引擎：开窗划界 / 落址 / 绘制 / 清窗   │  ← 日美分叉在这里
└─────────────────────────────────────────┘
```

**移植对象 = 最上一层软件契约，不是硬件。**  
「搬不了」若指硬件 → 假命题。  
「搬不了」若指把美版 `text.c` 原样链接进日版 ROM → 真，见 §4。  
「搬得了」若指按日版 ABI 重建划界+落址模型 → 真，见 §6。

## 3. 日美 ROM 反汇编 / 模板对照（本轮实测）

### 3.1 文件头

| | 日版 AXVJ | 美版 AXVE 1.0 |
|---|---|---|
| 游戏码 | `AXVJ` | `AXVE` |
| 体积 | 8 MiB | 16 MiB |

### 3.2 `InitWindowTileData` 同址不同实现

两边入口都在 **`0x08002A50`**（低地址基础库对齐常见），但首条指令已分叉：

| | 机器码开头 | 语义 |
|---|---|---|
| **JP** | `70 B5 82 B0 04 1C … 20 7A` | `push{r4-r6,lr}`；`r0=模板`；按 **`tpl[8]=fontNum`** 分路；分帧 `glyph` 写入 `tileData+(start<<5)+(glyph<<6)` → **共享图集预渲** |
| **US** | `10 B5 02 1C 09 04 … 41 7A` | `push{r4,lr}`；`r0=Window*`；按 **`template->textMode`** 分路；`UNKNOWN2` → `InitVariableWidthFontTileData` |

日版 gdb 已证：IWTD **返回 void**（出口 r0 无预算意义）。  
美版返回值 = **下一窗可用 tile 起点**（调用方链式拨号，见 `menu.c` `gMenuTextTileOffset`）。

美版 `InitVariableWidthFontTileData`（ROM `0x08002AD8` 一带）源码语义：

```c
win->tileDataStartOffset = startOffset;
win->tileDataOffset = 2;
CpuFastFill(0, buffer, 32);                    // blank @ base
ApplyColors...(blank+1, ...);                  // blank @ base+1
return startOffset + 2 + win->width * win->height;
```

### 3.3 WindowTemplate：差在「有没有面积字段」

**美版**（`0x1C` 字节）示例 `0x081E6CC8`（设置/菜单类，与日版同 tileData/tilemap 对照）：

```
raw: 02 02 0F 00 0F 01 0F 08 03 02 00 00 00 1E 14 00 00 80 00 06 00 78 00 06 ...
                              │  │           │  │
                           font tm=2      w=30 h=20
tileData=0x06008000  tilemap=0x06007800
预算 = 2 + 30×20 = 602 tile   ← 与 AXVE gdb「span=602」一致
```

**日版**（`0x14` 字节）对应菜单窗 `0x081BB484`：

```
raw: 02 02 0F 00 0F 01 0F 08 03 01 00 00 00 80 00 06 00 78 00 06
                              │  │
                           font tm=1   ← 无 w/h；0x0C 起直接是 tileData
tileData=0x06008000  tilemap=0x06007800
```

同屏资源指针几乎一样，**契约不同**：美版 tm2 + 面积；日版 tm1 + 图集。

### 3.4 日版菜单模板 textMode 分布（`0x081BB400..900`，tileData∈VRAM 的条目）

实测命中以 **`tm=1`（等宽图集）** 为主；对话主窗等为 **`tm=3`（网格直绘）**；**不是** 美版菜单主力的 tm2。

日版 `FontFuncTable@0x081BB3AC`：

| 槽 | 地址 | 日版语义（反汇编定案） |
|---|---|---|
| 0 | `0x08003569` | 无阴影像素直绘 |
| 1 | `0x0800360D` | 等宽 SubTable 写 tilemap（菜单主力） |
| 2 | `0x0800338D` | `win[0x20]` 缓冲直绘（血条等；**≠美版 tm2 画布**） |
| 3 | `0x08003495` | 阴影网格（对话等） |

⚠ **禁止**把日版模板 `textMode` 改成 2「对齐美版」——日版 tm2 已是另一条路（gdb 证伪项，见 `.cursor/rules/axvj-gdb-killed-conclusions.mdc`）。

### 3.5 `GetCursorTileNum`（美版源码，移植目标公式）

```c
if (win->textMode == TEXT_MODE_UNKNOWN2)
    index = start + offset
          + (((top + cursorY) >> 3) + yOff) * width
          + (((left + cursorX) >> 3) + xOff);
else
    index = start + offset + 2 * xOff + yOff;
```

`AddToCursorX`：**只有 UNKNOWN0** 在跨 8px 列时 `tileDataOffset += 2`；  
UNKNOWN2 **只增加像素 `cursorX`**，OFFSET 保持开窗时的 2。

### 3.6 清窗（美版）

`Text_ClearWindow`：按 textMode 填 tilemap 为 `GetBlankTileNum | palette`，游标归零；UNKNOWN0/2 还会把 `tileDataOffset` 置回 2。  
**清的是引用，不是「回收分配器」。**

## 4. ABI：为什么不能整文件粘贴美版 text.c

（沿用并强化 `调研_20260828_日版AXVJ文本引擎分发表与美版桥接评估.md`）

| 项 | 美版 | 日版 AXVJ |
|---|---|---|
| `struct Window` 字段顺序 | textMode@0、width@9、height@0xA、cursor 像素、left/top… | template@0、textMode@0xA、TILE_BASE@0x16、cursor **tile** @0x1A/0x1C… |
| `WindowTemplate` | `0x1C`，含 `width/height` | `0x14`，**无面积**；且被 bg/窗框代码共用 |
| IWTD 参数 | `(Window*, startOffset)` → 返回下一 offset | `(Template*, startOffset, glyphIdx)` 分帧装库，**void** |
| 链接 | 有 `.data/.bss`（`sGlyphBuffer` 等） | hook `game.ld` 仅 ROM 窗，无标准 BSS |
| 数据资产 | `sFonts[]`、美版模板表 | 地址全不对 |

结论：**方案 A「接入美版 text.c」否决。**  
可行形态 = **按日版 ABI 重建「划界 + GCTN + mask + 清窗」模块**，或「美版 Window 在 hook 内自治 + 日版薄翻译层」（`引擎移植方案_20260908.md` P2）——二者都不是粘贴 9000 行。

## 5. 模型对照表（开发时用）

| 维度 | 美版菜单主力（UNKNOWN2） | 日版菜单主力（tm1） | 对本项目的含义 |
|---|---|---|---|
| 开窗 | 划 `2+w×h` 私有网格，链式返回 | 预渲 256×2 进共享图集 | 汉化必须**替换或旁路**图集装载，并**补预算** |
| tile 号语义 | **位置**（行×宽+列） | **内容**（base+2×字模号） | 汉字装不进 256 槽 → 内容寻址物理失效 |
| 上界 | 窗口面积（硬） | 字库槽 / 或外挂分配器（软） | 撞 UI = 软上界代偿失败 |
| 清窗 | tilemap → blank | 有官方清窗；中文路径常未对齐 | 残留的机制答案 |
| 汉化先例 | pokeRS 只 hook 绘制 | 无公开对等物 | 日版必须自建划界层 |

对话等 **日版 tm3**：已有网格公式（×30），更接近「位置寻址」，与菜单 tm1 **不是同一病**。

## 6. 可行开发路线（按优先级）

### 6.1 总原则

1. **先预算，后公式。** 没有可证伪的 `2+w×h`（或等价私有段）来源，禁止启用画布 GCTN。  
2. **画笔与划界分离。** `us_mask` / 1bpp 字形可以保留；它们不证明引擎移植完成。  
3. **textMode 号按日版语义**；移植的是美版**算法**，不是美版**枚举值**。  
4. **日版为底**（`jp-rom-base-only`）；美版 ROM 只作对照。

### 6.2 阶段 W0 — 预算勘测（阻塞项，未完成不得写假划界）

对每个要接管的 tm1 场景，静态 +（用户授权时）gdb 钉死：

| 交付物 | 内容 |
|---|---|
| 模板表 | tpl 地址、charBase、tileData、tilemap、font、tm |
| 几何 | 文本区 tile 宽×高（来源候选：窗框绘制参数、tilemap 底色矩形、美版同场景 `w×h` 对照——**对照仅参考，须日版实测**） |
| 空闲段 | 该 CB 上可私有化的连续 tile 区间（避开场景硬编码章） |
| 生命周期 | 窗打开/关闭/重入时 IWTD 是否重跑、多模板是否共 CB |

**通过标准**：能写出「窗 X → `[base, base+2+w*h)`」表，且与邻居 UI 不重叠。  
**不通过**：退回该窗 T-b（共享图集 + 严格受限路径），或暂留日文。

### 6.3 阶段 W1 — 开窗划界接线（真正的「往上一层」）

在 **IWTD 或等价场景 init** 上：

- 停止（或旁路）256 字图集预渲（中文 ROM 下图集对汉字无用）；  
- 写入 blank×2；  
- 登记私有 `[base, base+2+w*h)`；  
- 若多窗共 CB：必须有**链式或表驱动**的不重叠分配（美版靠返回值；日版须自建账本）；  
- `InitTextPrinter`：把该窗 `TILE_BASE/OFFSET` 绑到私有区（OFFSET=2）。

### 6.4 阶段 W2 — 落址 + 绘制消费

- GCTN：仅对**已划界**窗使用 `start+off+row*W+col`；  
- `AddToCursorX` 对齐美版 UNKNOWN2：**不**因跨列递增 OFFSET；  
- 绘制：`GetCursorTileNum` → mask → `UpdateTilemap`（pokeRS 同构）；  
- 未划界窗：保持线性/官方网格，禁止假画布。

### 6.5 阶段 W3 — 清窗 / 残留

- 接管或补强 `Text_ClearWindow`：tilemap 指回 blank；OFFSET=2；像素游标归零。

### 6.6 明确不在本路线内的项

- 整份 pokeruby `text.c` 链接；  
- 改日版模板布局为 `0x1C`（会级联 bg/窗框）；  
- 默认关剧情模块冒充「缩小范围」；  
- v8 freelist / 静态独占带当地基（含已证伪 `[0x2D2,0x400)`）。

## 7. 工作量量级（消除「9000 行」误解）

| 块 | 量级（数量级） | 说明 |
|---|---|---|
| mask / Shift / colors | 已有（~数百行 vendored） | 画笔，非划界 |
| GCTN + 游标 + UpdateTilemap 适配 | 小 | 公式级 |
| 清窗适配 | 小 | |
| **预算表 + IWTD/场景接线** | **中～大，但是工程主成本** | 逐场景，不是 9000 行 C |
| 完整美版状态机 + FC 表 | 中，可分期 | P2 后半 |
| 原样 text.c | 否决 | 不要估工时去干 |

**对标 pokeRS：美版上 ~3 个 hook；日版上 ≈「3 个 hook + 一整层开窗预算」。**  
多出来的不是 9000 行引擎，是日版裁掉的那一层要补回。

## 8. 失败模式台账（本轮对话已验证）

| 做法 | 结果 | 根因 |
|---|---|---|
| 共享图集上套 `row×W` + blank 覆写 `TILE_BASE` | 标题蓝洞、菜单进地图块、队伍灰条 | 无私有预算却当已划界 |
| 止血退回线性 `OFFSET+=2` | 残留/叠字仍在；看起来像「又水位」 | 线性≠美版菜单模型 |
| IWTD 吞图集 + 固定 30×17 假面积 | 用户回滚 | 面积未勘测；共 CB 多窗未真正链式隔离 |
| 只宣称「mask=引擎移植完成」 | 验收失败 | 画笔≠划界 |

## 9. 验收标准（写代码前先写预期截图）

某一窗宣称「划界完成」须同时满足：

1. 开窗后 VRAM 上存在该窗独占的 `[base, base+2+w*h)`（gdb 或静态推演可复核）；  
2. 中文 GCTN 号全部落在该区间；  
3. 同屏 UI 章（图标/框）tile 号不被该区间覆盖；  
4. 短句覆盖长句后无残留（清窗或重绘路径有效）；  
5. 未授权不改用户基线 ROM；打包仅在用户下令时按根 `build.bat`。
