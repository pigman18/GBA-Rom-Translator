## 1. 日版引擎硬事实（反汇编实测）

### 1.1 `InitWindowTileData` @0x08002A50

```
0x08002A5E  ldrb r0,[r4,#8]      ; 按 tpl[8]=fontNum 分路（不是 textMode）
0x08002A8C  lsls r1, r3, #5      ; startOffset * 32
0x08002A8E  ldr  r0,[r4,#0xC]    ; tpl[0x0C] = tileData
0x08002A92  lsls r1, r6, #6      ; glyphIdx * 64
0x08002A94  adds r5, r0, r1      ; dst = tileData + (start + 2*glyph)*32
0x08002AA6  bl   0x08003630      ; LoadFixedWidthGlyph
0x08002AE8  add sp,#8 / pop / bx  ; ★ 无返回值
```

**【实测】** 每个字形 **2 个 tile**，写在 `tileData + (start + 2*glyphIdx)*32`。

### 1.2 `LoadFixedWidthFont`（一次性版）@0x08002AF4

```
0x08002AFC  movs r5, #0
0x08002B1C  cmp  r5, #0xFF       ; glyph 0..255
0x08002B20  lsls r0, r5, #0x11 ; lsrs r0, r0, #0x10   ; 返回 256*2 = 512
```

**【实测】** tm1 图集 = **256 字形 × 2 tile = 512 tile**，从 `start` 起。
配 gdb `W0` 实测 `start=0x0001` ⇒ **图集占 CB2 `[1, 513)`**。

> 同类变体：font1/2 版 @0x08002B2C 步长 0x20（1 tile/字，返回 256）。

### 1.3 tm3 落址 @0x080034E0 → 0x08003500

```
0x080034E2  ldrb r1,[r0,#0x1A]   ; left  (tile)
0x080034E4  ldrb r2,[r0,#0x1B]   ; cursorTileX
0x080034E8  ldrb r2,[r0,#0x1C]   ; top   (tile)
0x080034EA  ldrb r3,[r0,#0x1D]   ; cursorTileY
0x0800350A  adds r1, #2
0x0800350C  ldrh r0,[r0,#0x16]   ; TILE_BASE
0x08003510  lsls r0, r2, #4 ; subs r0, r0, r2 ; lsls r0, r0, #1   ; y*30
0x08003516  adds r1, r1, r0
```

**【实测】** `tile = TILE_BASE + 2 + (win[0x1A]+win[0x1B]) + 30*(win[0x1C]+win[0x1D])`

⇒ **日版 tm3 就是美版 UNKNOWN2 网格模型**，只是：
- 步长写死 30（美版取 `win->width`）；
- 游标是 **tile 级**（美版是像素级 `cursorX`，跨 8px 才进列）。

配 gdb `W0-SPAN-JP`（base=1, +0x25A, span=602，11 次一致）：
**【推论·算术】** `w=30`, `h=(602-2)/30=20` —— 两条实测交叉，无第三来源，仍标推论。

### 1.4 `InitTextPrinter` @0x08002C68 写入字段

```
[0x04]=1  [0x06]=0  [0x08]=0  [0x09]=0
[0x0A]=tpl[9] (textMode)   [0x0B]=tpl[8] (fontNum)
[0x0C..0x0F]=tpl[5..4]（fg/bg/shadow/palette）
[0x10]=text  [0x14]=0  [0x16]=r2(tile_base)  [0x18]=0
[0x1A]=r3(cur_x)  [0x1B]=0  [0x1C]=sb(cur_y)  [0x1D]=0
```

**【实测】** `win[0x1E..0x1F]` **未被 InitTextPrinter 初始化**（疑为 0x20 指针对齐填充）。
⚠ 不排除别处有 u32 写 0x1C 波及 ⇒ **不用来挂账本**，改走 EWRAM。

### 1.5 窗框装载 @0x08062080 / 0x08062095

```
0x08062086  strh r0,[r1]         ; 存 base
0x08062088  adds r0, #9          ; 返回 base + 9
...
0x080620A0  lsls r0, r0, #5      ; base*32
0x080620A2  adds r1, r1, r0      ; dest = charblock + base*32
```

**【实测】** 框占 **9 tile**（与美版一致）；顺序 = 先设 base 再装框。
⇒ 布局：`[文字 start .. start+span) → [框 start+span .. +9)`。

## 2. 窗口模板表（`tools/scan_axvj_templates.py`）

扫描区间 `0x081BB000..0x081BBFFF`，命中 **52 条** 20B 模板。

全部条目的 `+0x0A`、`+0x0B` 均为 **0** ⇒ **日版模板确实无 width/height**（美版 `0x1C` 模板有）。
代表性条目：

| 模板 | bg | charBase | font | tm | tileData | CB | tilemap | SB |
|---|---|---|---|---|---|---|---|---|
| `0x081BB43C` | 0 | 1 | 4 | 1 | `0x06004000` | 1 | `0x0600F000` | 30 |
| `0x081BB454` | 0 | 2 | 3 | **3** | `0x06008000` | 2 | `0x0600F800` | 31 |
| `0x081BB46C` | 0 | 2 | 3 | **3** | `0x06008000` | 2 | `0x0600F800` | 31 |
| `0x081BB484` | 2 | 2 | 3 | 1 | `0x06008000` | 2 | `0x06007800` | 15 |
| `0x081BB5BC` | 0 | 2 | 3 | 1 | `0x06008000` | 2 | `0x0600F000` | 30 |
| `0x081BB874` | 0 | 2 | 3 | 1 | `0x06008000` | 2 | `0x06007800` | 15 |

（完整 52 条：`python tools/scan_axvj_templates.py`）

## 3. 框几何：161 个调用点（`tools/scan_frame_calls.py`）

`MenuDrawStdWindowFrame(left,top,right,bottom)` @0x0806F224，全 ROM 静态扫到 **161 处 BL**，
其中多数调用点把四参以 `movs rX,#imm` 直给 ⇒ **可静态读出 w×h**。

### 与 gdb 实测交叉验证（方法有效性证据）

| 调用点 | 静态读出 | gdb W0-FRAME (r2) | 一致 |
|---|---|---|---|
| `0x0806D632` | 20,10,29,19 → **10×10** | 10×10 | ✅ |
| `0x0806A7C6` | 0,16,23,19 → **24×4** | 24×4 | ✅ |
| `0x0806A7D6` | 0,16,19,19 → **20×4** | 20×4 | ✅ |
| `0x0806E51E` | 22,0,29,? → **8×?** | 8×20 | ✅ |

⇒ 静态扫描与 gdb 同源，可作为 w×h 的**可证伪来源**。

### 常见几何（静态）

26×6 / 28×4 / 30×7 / 22×16 / 18×14 / 23×4 / 21×11 / 10×10 / 19×8 / 6×6 / 7×9 …

**未解决**：调用点 → 具体窗口/模板的映射尚未建立（需一次 gdb 带 LR 采集，或按调用点所在函数反推场景）。
这是 tm1 私有化的**唯一剩余阻塞**。

## 4. EWRAM 空闲段（`tools/scan_ewram_free.py`）

字面量池扫描 `0x0203E000..0x02040000`，最大无引用段：

| 起始 | 长度 |
|---|---|
| `0x0203E477` | 2936 B |
| `0x0203F1EF` | 2580 B |
| `0x0203FC04` | 500 B |

方法自校验：项目已在用的 `0x0203FEB0/FEB8/FEC0` 落在扫描报出的空闲段内 ⇒ 方法与既有结论自洽。

**本轮取 `0x0203F800`（160B，8 槽 × 20B）** 作美版窗账本。

## 5. 已落地的美版引擎核心

`configs/POKEMON_RUBY_AXVJ00/hook/src/text/us_text.c` + `include/us_text.h`

| 函数 | 对美版 | 语义 |
|---|---|---|
| `us_win_open` | `InitWindowTileData` + `InitVariableWidthFontTileData` | 写 blank×2、登记 `[start,start+2+w*h)`、绑 TILE_BASE/OFFSET=2、**返回下一窗起点** |
| `us_gctn` | `GetCursorTileNum` | `start+2+row*W+col`，**越界返回 0**（绝不写出私有段） |
| `us_add_cursor_x` | `AddToCursorX` (UNKNOWN2) | 只推像素游标，**不动 tileDataOffset** |
| `us_clear_window` | `Text_ClearWindow` | tilemap 填 blank + 游标归零 + OFFSET=2 |
| `us_win_close` | — | 用完清除，不污染其它场景 |

与禁止项的距离：
- 预算挂 `win` 指针（不是全局带）；
- **不 hook `SetBaseTileNum`**、不事后顶基址、不跨场景常驻；
- 越界即拒绝绘制（物理截断，不是靠 span 上限躲）。

### 已接线

- `InitTextPrinter_hook_C`：tm3 开窗（w=30/h=20，来源见 §1.3）。
- `PrintNextChar_hook.c`：已划界窗 → `us_gctn` 落址 + 账本像素游标 + 不推 OFFSET；
  未划界窗（tm1 菜单等）保持 v8 原路径不动。

### 未接线（等 §3 的映射）

tm1 菜单窗：需「调用点→窗口」映射后逐窗登记 w×h。
计划挂点：`MenuDrawStdWindowFrame` 现场读 (left,top,right,bottom) 得真实几何（免猜）。
