# 阶段 0 —— 模板 24B→28B 对齐：枚举与落地设计

> 2026-09-09。用户拍板「都接管 + 整体按美版重排」，切入点选「阶段 0：模板 28B 对齐」。
> 本文 = 阶段 0 的**枚举结果 + 落地设计**，全部自反汇编。

## 一、日版模板精确结构（反汇编 + 扫描，52 条）

`tools/scan_axvj_templates.py` 扫出 **52 个窗口模板**（`0x081BB3DC..0x081BB8BC`）。字段布局：

```
@0  bg            @1  charBaseBlock   @2  screenBaseBlock   @3  priority
@4  paletteNum    @5  foreground      @6  background        @7  shadow
@8  fontNum       @9  textMode        @0x0A =0(恒)  @0x0B =0(恒)
@0x0C tileData(4B, 写死绝对地址)      @0x10 tilemap(4B, 写死绝对地址)
```

美版 28B 对照（`struct WindowTemplate`）：
```
@0 bg  @1 charBaseBlock  @2 screenBaseBlock  @3 priority  @4 pal  @5-7 色
@8 font  @9 textMode  @10 spacing  @11 tilemapLeft  @12 tilemapTop
@13 width  @14 height  @15 tileData(4B)  @19 tilemap(4B)
```

**差异（钉死）**：
- 日版缺 `@12 tilemapTop`、`@13 width`、`@14 height` 三字段。
- 日版 `tileData@0x0C`（美版 `@0x0F`）、`tilemap@0x10`（美版 `@0x13`），各前移 3B。
- 日版 `@0x0A/@0x0B` 恒 0（= 美版 spacing/tilemapLeft，日版不用）。

## 二、模板消费者清单（谁读哪些字段，精确到反汇编地址）

| 消费者 | 地址 | 读模板字段 |
|---|---|---|
| InitTextPrinter | `0x08002C68` | `@4 pal` `@5 fg` `@6 bg` `@7 shadow` `@8 font` `@9 tm` → 写 win[0xF/0xC/0xD/0xE/0xB/0xA] |
| InitWindowTileData | `0x08002D68` | `@8 font` 分路 + `@0x0C tileData` |
| tm 落址 ×4（FontFuncTable） | `0x0800338C/3568/360C/3494` | `@0x0C tileData` + `@0x10 tilemap` |
| UpdateTilemap | `0x080036DC` | `@0x10 tilemap` |
| **（无）** | — | **没有消费者读 `@0 bg / @1 charBase / @2 screenBase` 写 BGxCNT** |

**关键结论**：日版 BG 层 charblock 是 main 里静态设死，**没有任何窗口开窗时按模板动态设 BGxCNT**。这正是美版 `UpdateBGRegs`（text.c:1740）做的事，也是阶段 2 要补的。

## 三、落地设计：hook 层模板语义补充（非物理重排）

**物理重排 ROM 模板不可行**：把 52 个模板原地从 20B 扩到 28B 会移动后续所有 ROM 数据 + 改变所有引用地址，风险与收益不成比例（且违背「hook 注入、尽量不动 ROM 数据」的项目原则）。

**正确做法**：hook 层补齐缺失的 width/height 语义，其余字段日版模板已有（仅偏移不同）。

- width/height 来源：Task #2 已定 —— **引擎 w×h = 图集预算/行距，标准窗统一 30×20**（日版 tm3 落址 `@0x08003494` 步长 30 写死 = width；h=20 来自美版孪生 `gMenuTextWindowTemplate@0x081E6CE4`）。7 个美版特例（26×20 / 8×60 / 8×64 / 16×32×3 / 32×32）不在标准框路径，实测时按表补。
- 落地形式：编译期静态表 + 查询函数，**默认 30×20**，特例字典覆盖。

### 阶段 0 产出物
1. `tpl_w(tpl) / tpl_h(tpl)`：从模板查 w/h（默认 30×20，特例字典）。
2. `tpl_tiledata(tpl) / tpl_tilemap(tpl)`：屏蔽日版偏移（@0x0C/@0x10），后续统一走美版语义。
3. 后续阶段 1 分配器用 `InitVariableWidthFontTileData` 时从模板读 w/h，**不再硬编码 TM3_W/TM3_H**。

无视觉变化（纯语义层补齐，未改渲染路径）。
