# 阶段 1 —— 链式游标分配器落地（反汇编定案）

> 2026-09-09。阶段 1 = 重新实现美版链式游标分配器，取代 v8「找空闲」模型。
> 全部结论来自自己反汇编（tools/disasm_rom.py + 手写 thumb BL 解码器），不接受记忆漂白。

## 一、美版分配器完整契约（源码 + 反汇编双证）

来源：`tools/pokeruby/src/text.c` + `menu.c` + `text_window.c`。

### 1. 链式游标的核心 = 两个 static 全局 u16 + 返回值串联

`text_window.c:21-22`：
```c
static u16 sTextWindowBaseTileNum;      /* 框基址（LoadStdFrameGraphics 读它） */
static u16 sDialogueFrameBaseTileNum;   /* 对话框框基址（LoadDialogueFrameTiles 读它） */
```

### 2. 开窗链（menu.c InitMenuWindowInternal）

```
InitMenuWindow(winTemplate) → InitMenuWindowInternal(winTemplate, tileOffset=1)
  gMenuWindowPtr = &gMenuWindow
  Text_InitWindowWithTemplate(&gMenuWindow, winTemplate)   // 拷模板字段到 win
  gMenuTextWindowTileOffset = InitWindowTileData(win, 1)         // 画布，返 1+2+w*h
  gMenuTextWindowContentTileOffset = TextWindow_SetBaseTileNum(↑) // 框，返 +9
  TextWindow_LoadStdFrameGraphics(win)                            // 装框到 sTextWindowBaseTileNum
  gMenuMessageBoxContentTileOffset = TextWindow_SetDlgFrameBaseTileNum(↑) // 对话框框，返 +14
```

### 3. InitWindowTileData 按 textMode 分发（text.c:1763）

- `TEXT_MODE_UNKNOWN2` → `InitVariableWidthFontTileData`：写 blank×2，**返 `startOffset + 2 + width*height`**（链式游标推进）。
- `TEXT_MODE_MONOSPACE` → `LoadFixedWidthFont`：载 256/512 字形，返 256 或 512（font 0/3 ×2）。

### 4. SetBaseTileNum / SetDlgFrameBaseTileNum（text_window.c:101/200）

```c
u16 TextWindow_SetBaseTileNum(u16 baseTileNum) {
    sTextWindowBaseTileNum = baseTileNum; return baseTileNum + 9;   // 框占 9 tile
}
u16 TextWindow_SetDlgFrameBaseTileNum(u16 baseTileNum) {
    sDialogueFrameBaseTileNum = baseTileNum; return baseTileNum + 14; // 对话框框占 14 tile
}
```

**本质**：窗口内「画布 → 框 → 对话框框」三段连续，开窗复位、关窗作废。**从不问哪里空。**

## 二、日版现状（反汇编铁证：链式游标被压扁）

1. **日版符号表高地址区（0x0806xxxx）全部失效**：`InitMenuWindow @0x0806F338` 反汇编是转发函数但 0 个 BL 调用点（手写 thumb BL 解码器全 ROM 扫），`InitWindowTileData @0x08002D68` 反汇编第一句是 `ldr r1,[r3,#0xc]`（无函数序言 push）——它只是 `0x08002D1C` 函数体内的一段。

2. **日版真实开窗入口 = `0x08002D1C`**（60 个 BL 调用点，遍布 0x0802B8FE~0x080A900E）：
   ```
   0x08002D1C: push{r4-r7,lr}+r8; sub sp,#4
     r7=r0(win); r5=[sp,#0x1c](top)
     写 gMenu 全局(gMenuMultistepInitState=3 等)
     bl 0x08002C68  ← InitTextPrinter（已 hook）
     textMode==0 时才装 blank×2（bl 0x8003830 CopyGlyph1bppTo4bpp）
   ```
   签名 `(win, text, tileDataStartOffset, left, top)`，**等价美版 Text_InitWindow 的加料版**。

3. **`InitTextPrinter @0x08002C68` 只有 4 个 BL 调用点**（0x08002CDE/D10/D52/30FA），全在低地址区。它 = 美版 `Text_InitWindow`（符号表 `Text_InitWindow @0x08002C68 VERIFIED US=0x08002DC0`），只拷模板 [4..9] 到 win + 写 tileDataStartOffset，**不分配**。

4. **结论**：日版移植时把美版「InitMenuWindowInternal 链式游标」删了，tile base 变成调用方写死传入；没有独立的 InitWindowTileData/SetBaseTileNum/SetDlgFrame 原生函数可 hook。

## 三、hook 层现状（阶段 0 已就位）

- 唯一 hook 点：`PrintNextChar @0x080032F8`（渲染）+ `InitTextPrinter @0x08002C68`（开窗必经点）。
- 字形合成已统一「字体 ROM 重合成」：`DrawGlyph → jp_glyph_to_g128`、`chs_print → GetGlyph`，无读图集路径。
- `us_text.c` 已有：`us_win_open`（= 美版 InitVariableWidthFontTileData，返 start+2+w*h）、`us_gctn`（位置寻址）、`us_add_cursor_x`、`us_clear_window`。tm3 已接 `us_win_open_tpl`。
- `PrintNextChar_hook.c` 的 `chs_claim_tile`：`us_mode(win)`（账本有槽）→ `us_gctn` 网格落址；tm1 目前走 `v8_alloc_tile`（找空闲）。

## 四、阶段 1 落地方案（本轮执行）

**目标**：在 hook 层实现美版链式游标分配器，让 tm1/tm3 的文本画布都走它，取代 v8 找空闲。框（+9）/对话框框（+14）的**接口**本轮做出，装载接管留阶段 3（UI 全面接管，需另 hook 框装载函数）。

1. `us_text.h/.c` 增链式游标全局状态（EWRAM 账本后）：
   - `us_set_base_tile_num(base)` → 返 base+9，存 `sTextWindowBaseTileNum`。
   - `us_set_dlg_frame_base_tile_num(base)` → 返 base+14，存 `sDialogueFrameBaseTileNum`。
2. `InitTextPrinter_hook.c`：tm1 也接 `us_win_open_tpl`（替代 `v8_alloc_begin`），并把画布返回值串进游标（画布→框→对话框框）。
3. 编译 + 链接验证，entry 符号地址不变。

**截图预期**：开始菜单/队伍/背包/图鉴等 tm1 菜单窗、以及对话窗 tm3，文本正常渲染、字形来自字体 ROM 重合成；无花屏、无叠字。框/对话框框仍走日版原生（阶段 3 接管）。
