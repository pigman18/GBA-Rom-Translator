## 0. 结论速览

| # | 结论 | 影响 |
|---|---|---|
| 1 | 全 ROM **236 处** `bl → LZ77UnCompVram` 调用，其中 **58 处目的地落在 cb2/cb3**（cb2 **11** / cb3 **47**） | S1 的「41 处装载」偏保守；真实面更大 |
| 2 | 🔴 **cb2/cb3 的字符区几乎全区间都有官方装载落点**：cb2 摸到 `t0..t448`、cb3 摸到 `t0` 与 `t128..t511` | **v10 §2.6 的池子选址（BG0→cb2[32,512)、BG3→cb3[128,512)）静态上不成立** |
| 3 | 🔴 **cb3 的 `t384..t511`（`0x0600F000..0x06010000`）同时是 screenblock 30/31 的 tilemap 区**（12 处装载以它为目的地） | 这一段**绝对不能用**（会与 BG3 自己的 tilemap 打架）。它正是实测里 `B7E4.tilemap=0x0600F000` 的物理同体 |
| 4 | 但**实测**领航员场景 cb2 非空仅 **114/512**、cb3 **361/512** ⇒ 那 58 处装载**绝大多数在该场景没触发** | ⇒ 池子可行性**取决于场景时序**，不能静态判定；这正是 `--preset cb-load` 要测的 |
| 5 | 好消息：58 处里绝大多数走 **LZ77UnCompVram**（含经 `0x0800A770` 包装的） | ⇒ S5.5「改道」的 hook 面**仍是 `0x081B1298` 一个蹦床 + DMA 封装**，与 S1 §3.4 一致，**没有扩大** |

一句话：**S1.5 把「池子够不够」这个问题，从「够（864 tile）」改判为「静态上没有一块完整的无主地」**——
所以 v10 要么靠实测证明「领航员场景内官方不碰我们的区间」（方案 a），要么就必须做 S5.5 改道（方案 b）。
**它同时给 (b) 提供了精确的拦截清单**。

## 1. 方法

`scripts/preview_cb_loads.py`：

1. 扫全 ROM（手工解码 Thumb BL/BLX，与 `find_callers.py` 同款已验证解码器）找 `bl 0x0800A770` / `bl 0x081B1298`；
2. 对每个调用点**向前回溯 40 条指令**，解析 `r0`/`r1` 的最近一次赋值（支持 `ldr rX,[pc,#imm]` / `adds rX,rY,#imm` / `movs rX,#imm`，遇 `push/pop` 停）；
3. 从源地址读 **LZ77 头**（`0x10` + 24bit 小端）得**解压后字节数**；
4. 目的地址 + 大小 → 覆盖到哪些 tile（`t0..t1`）。

局限（已知，不影响结论）：
- `?` = 源地址无法静态解析（寄存器来自运行时计算）⇒ 大小按 1 tile 计，**低估**；
- 不含 DMA / CpuSet 路线（S1 已记 6+1 处）；
- 各装载**是否同时发生**未知（这是 §0 第 4 条，交给运行时埋点）。

## 3. 对 v10 的三条修正

### 3.1 池子选址（推翻了 §2.6）

原文假设「cb2/cb3 是官方占用最少的地盘」。S1.5 证明：

- **cb2** 的官方装载落点覆盖 `t0..t55 / t128..t191 / t256..t319 / t384..t448` ⇒
  计划池 `[32,512)` 中**只有 `t56..t127`（72）、`t192..t255`（64）、`t320..t383`（64）是碎片空档**，合计 200 tile；
- **cb3** 的落点覆盖 `t0 / t128..t255 / t256..t319 / t384..t511` ⇒
  计划池 `[128,512)` **全部落在被摸过的区间里**；唯一较干净的是 `t1..t127`（127 tile）。

⇒ **静态上找不到一块 480+384 的连续无主地**。原「864 tile」结论**作废**。

### 3.2 但「静态被摸过」≠「运行时被占用」

实测（v92 `[VRAM cbN]`）：cb2 非空 **114/512**、cb3 非空 **361/512**。
若 cb2 的 256-tile 大装载真在领航员场景跑过，非空应 ≥ 256 ⇒ **它在该场景没触发**。

⇒ 所以第二版池子选址必须**由实测驱动**：
先跑 `--preset cb-load`，拿到「领航员场景内**真正发生**的 cb2/cb3 装载区间」，再在其**补集**里选址。

### 3.3 S5.5 改道面确认（好消息）

58 处里绝大多数经 **LZ77UnCompVram** ⇒ 拦 `0x081B1298` 一处即可覆盖大部分，
再加 DMA 封装 ⇒ **hook 面没有扩大**，S1 §3.4 的结论继续有效。

⇒ v10 的 (b) 方案从「要不要做」变成「**按这份清单做**」：清单里每一条都是必须改道的对象。

## 4. 与铁律的一致性

- ✅ **不抬水位**：本报告只是把池子候选区间重算，没有动 v8/v9 的水位机制；
- ✅ **不逐场景补丁**：正相反——S1.5 的意义正是**否决**「给每个场景挑一个空档」的做法（那就是逐场景补丁）；
- ✅ **彻底接管**：58 处装载清单 = 改道对象清单，支撑「4 cb 全接管」的字面含义。
