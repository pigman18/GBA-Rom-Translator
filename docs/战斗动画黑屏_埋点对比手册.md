# 放技能偶发黑屏：埋点对比手册

面向 `POKEMON_RUBY_AXVJ00`（日版红宝石）。目标：定位「放技能偶发黑屏」，
方法是**原版 ROM 与汉化 ROM 各跑一次同一存档的同一技能，diff 两份日志**。

---

## 一、先说结论：静态勘验已排除的嫌疑（2026-08-30）

在动手抓运行时之前，先做了原盘 vs 汉化盘的逐字节比对，**以下三处均完全一致**，
即黑屏**不是静态数据被汉化改坏**，而是运行时行为差异 —— 所以必须走埋点对比。

| 对象 | 地址 | 结论 |
|---|---|---|
| `gBattleAnims_Moves`（技能动画指针表） | `0x081D997C`（412 项） | 原版/汉化逐项一致 |
| 动画脚本本体 | `0x081D36DC`–`0x081D5900`（8.5 KB） | **0 字节差异** |
| battle_anim 代码段（`DoMoveAnim` 等） | `0x08071D98` 起 | 一致 |

汉化对 ROM 的实际改动只有两类（全盘 159 处差异块 / 527 KB）：

1. **hook 跳转注入** —— 形如 `00 4b 18 47` + `0x08800019`（跳进 hook 代码区）。
2. **数据指针重定向** —— `0x083xxxxx` → `0x092xxxxx`（1369 处），把文本/数据搬到
   8 MB 以外的扩展区。

> 排查时若看到「0x08xx→0x08xx」的指针改动，多半是**文本字节被识别成指针的误报**
> （如 `gPokedexEntries`、剧情文本翻译后字节变化），不是真改动。

## 二、埋点清单

### A. 技能入口与脚本流（本次新增）

| 埋点名 | 地址 | 抓什么 |
|---|---|---|
| `MoveAnimEntry` | `0x08071D98` | `DoMoveAnim` 入口，r0=技能 id |
| `LaunchAnim` | `0x08071DCC` | `LaunchBattleAnimation`，r0=动画表基址 r1=move r2=isMoveAnim；**算出脚本指针=[r0+r1*4]** |
| `AnimScriptCmd` | `0x08072048` | **核心**：`RunAnimScriptCommand`，每条脚本命令命中一次 |
| `AnimLoadSpriteGfx` | `0x080720C8` | 加载 sprite 图形（tileTag 在脚本流里，不在寄存器） |
| `AnimFadeToBg` | `0x0807327C` | 背景淡出/切换 |
| `AnimRestoreBg` | `0x080735BC` | 背景恢复（淡出不恢复＝黑屏） |
| `AnimChangeBg` | `0x080735EC` | 换背景 |
| `AnimSetBldCnt` | `0x080730EC` | 改写 BLDCNT 混合寄存器 |
| `AnimCreateSprite` | `0x0807214C` | 创建动画精灵 |
| `AnimMonBg` | `0x08072488` | 宝可梦精灵搬到 BG 层 |
| `AnimWaitFrame` | `0x08072030` | 等待帧（已去重，只看状态变化） |

### B. tile / 调色板写入（已有埋点，本次叠加了动画上下文）

`LoadSpriteSheet`、`LoadSpritePalette`、`LoadCompressedObjectPic`、
`LoadCompressedObjectPalette`、`LoadCompressedPalette`、`LoadPalette`、
`LZDecompressVram`、`CreateSprite`。

这些点原本只打自身参数，现在**每次命中额外追加一行动画上下文**：
```
  └ 动画中: move=#33 cmd[0]=loadspritegfx bgfade=3 脚本@0x081D36DC: 00 34 12 02 11 22
```
即 **「哪个技能的第几条脚本命令触发了这次写入」** —— 这是本方案的关键。

> 只在 `gAnimScriptActive` 为真时才追加，所以平时日志不受影响。

## 三、怎么跑

### 1) 原版 ROM（基准）

```powershell
$env:PYTHONPATH = "$PWD\src"
C:\Python314\python.exe -m util.gdb_patcher log --game POKEMON_RUBY_AXVJ00 `
  --functions MoveAnimEntry,LaunchAnim,AnimScriptCmd,AnimLoadSpriteGfx,AnimFadeToBg,AnimRestoreBg,AnimChangeBg,AnimSetBldCnt,AnimCreateSprite,AnimMonBg,LoadSpriteSheet,LZDecompressVram,LoadPalette,CreateSprite `
  --log work\gdb\origin_move.log --no-tiles
```

### 2) 汉化 ROM（对照）

同一条命令，只换 `--log work\gdb\han_move.log`，mGBA 里加载汉化 ROM。

### 3) 操作要求（两次必须一致）

- 加载**同一个存档**（`POKEMON_RUBY_AXVJ00_translated.sav`）
- 进同一场战斗，用**同一个技能**（建议先固定一个必现/高发的技能）
- 出招前后各留几秒，Ctrl-C 停止

### 4) 对比

```bash
diff <(grep -E '^\[(MVA|LNA|ASC|ALG|ABG|AWF)' work/gdb/origin_move.log) \
     <(grep -E '^\[(MVA|LNA|ASC|ALG|ABG|AWF)' work/gdb/han_move.log)
```

Windows 下可用 `git diff --no-index` 或直接看两份日志。

## 四、判读要点

| 现象 | 含义 |
|---|---|
| `LNA` 的表基址不是 `0x081D997C` | 动画表指针在运行时被改坏 |
| `LNA` 算出的脚本指针落在非 ROM 区 | 查表越界 → 脚本乱跑 |
| `ASC` 出现 `!!! 脚本指针越界` | 脚本流已跑飞，黑屏就在附近几条命令 |
| 两版 `ASC` 命令序列**一致**但汉化仍黑屏 | 问题在命令的**执行效果**（tile/调色板写入目标），看 B 组日志 |
| 两版 `ASC` 序列**不一致** | 上游分叉，回看 `MVA` 的 LR 与 move id |
| `LZDecompressVram` 的 dest 落在 `BG-cb0/1` | 背景 tile 被覆盖 —— 黑屏直接原因 |
| `LoadPalette` 且 `size>=0x100` 或 offset=0 | 大范围调色板改写 → 全屏变黑 |
| `fadetobg` 后没有 `restorebg` | 背景淡出未恢复 |

## 五、地址是怎么定出来的（下次加埋点照做）

`configs/POKEMON_RUBY_AXVJ00/symbols/pokeruby_jp.sym` 对这批符号标了
**UNVERIFIED**，实测其地址**普遍偏小**（前面带着上个函数的 literal pool），
且**每个函数偏移量都不同**：

```
DoMoveAnim              +0x24     ScriptCmd_loadspritegfx  +0x44
LaunchBattleAnimation   +0x20     ScriptCmd_restorebg      +0x7c
RunAnimScriptCommand    +0x4      其余多为 +0
```

**修正方法：从符号表地址向后扫，找第一个 `push` 指令（Thumb `0xB4xx`/`0xB5xx`）作为真函数头**，
再校验原版与汉化 ROM 在该点代码一致（一致才能两版共用同一断点）。

更可靠的抓手是 **EWRAM 变量**（符号表标 `KEEP-US`，日美一致，可直读）：

| 变量 | 地址 |
|---|---|
| `sBattleAnimScriptPtr` | `0x0202F7A4` |
| `gAnimScriptActive` | `0x0202F7B1` |
| `gAnimVisualTaskCount` | `0x0202F7B2` |
| `sAnimBackgroundFadeState` | `0x0202F7C5` |
| `sAnimMoveIndex`（当前技能） | `0x0202F7C6` |
| `gBattleAnimAttacker` / `Target` | `0x0202F7C8` / `C9` |
