## 1. 需求 1：cb 下标互转（唯一坐标系）

```
全局下标   g = cb*512 + t          （cb ∈ [0,3]，t = 窗内相对号）
反解       cb = g >> 9             t = g & 511
```

| 输入 | 结果 |
|---|---|
| cb0, t=0 | **0** |
| cb1, t=5 | **517** |
| cb2, t=1 | 1025 |
| cb3, t=511 | 2047 |

**窗可寻址区间（全局）**：`[cb*512, cb*512 + h_rel)`，`h_rel = min(1024, (4-cb)*512)`

| 窗 charBase | 可寻址（全局） | 宽 |
|---|---|---|
| cb0 | `[0, 1024)` | 1024 |
| cb1 | `[512, 1536)` | 1024 |
| cb2 | `[1024, 2048)` | 1024 |
| cb3 | `[1536, 2048)` | **512** |

**物理天花板 2048**：`0x06010000` 起是 OBJ 区（cb4/cb5），写进去必花屏，永不分配。

> **「0 - 2560」的口径**：2560 = `3*512 + 1024`，即 cb3 窗在 10bit tile 域下的**名义**上界；
> 物理上被 OBJ 边界截断到 2048。**本方案按 2048 实现**——真按 2560 会写进 OBJ 区。

## 2. 需求 2：`tpl + win` 维护一张动态避让带表

**归属键沿用 v9 队列游标那一把**：`(win, tpl)`（`ADDR_V8Q_WIN` / `ADDR_V8Q_TPL`）。
不新增键，避免两套生命周期打架。

### EWRAM 布局（全段整份 ROM 零字面量引用，已实证）

| 地址 | 内容 | 备注 |
|---|---|---|
| `0x0203FF50` / `FF52` | 空 | 预留 |
| `0x0203FF54` | `magic`（u16 `0xB9C1`） | 冷启动校验 |
| `0x0203FF56` | `count`（u16） | 已用条目 |
| `0x0203FF58` | — | 既有 `ADDR_V8Q_TPL`，不动 |
| `0x0203FF5C` | `bands[8] = {u16 start_g; u16 len}` | 32B，至 `FF7B` |
| `0x0203FF7C` | 空 | 预留 |
| `0x0203FF80` | — | 既有 ours 段表，不动 |

### API

```c
void     chs_band_add(uint16_t start_g, uint16_t len);   /* 登记（含去重/合并） */
void     chs_band_clear(void);                           /* 整表清空 */
uint16_t chs_band_count(void);                           /* 调试 */
/* 分配器用：[g, g+n) 相交带的最大右端点；无相交 → hit=0 */
uint16_t chs_band_end_hit(uint16_t g, uint16_t n, int *hit);
```

### 两条铁律（上一版构造推演抓到的致命缺陷，不可回退）

1. **只在同一 charBlock 内合并**（`(a >> 9) != (b >> 9)` 则跳过）。
   四个 cb 的图集带 `[1,513)[513,1025)[1025,1537)[1537,2049)` 两两相接，
   「相邻即合并」会串成 `[1,2048)` 巨型包络 ⇒ 分配恒返 0 ⇒ **全白**。
2. **换主才重置，不是每窗无脑重置**。
   窗口装载（登记带）**先于**文本块（`v8_alloc_begin`），所以 begin 里不能无条件 clear，
   否则刚登记的带被自己擦掉。触发条件：`(win,tpl)` 与记录不符才 `chs_band_clear()`。
   表满时优先回收**异 charBlock** 条目，同 cb 全满才并到最近的同 cb 条目。

## 4. 需求 4：分配空间配置 + 跳过 + 尽头回卷

```
可分配空间（全局）  [cb*512, chs_g_hi(cb))      chs_g_hi(cb) = cb*512 + min(1024,(4-cb)*512)
游标起点            换主时置为 cb*512            （v8 的 lo=0x100 取消，交给避让带声明）
```

**单次分配算法**（`v8_alloc_n` 重写为全局下标）：

```
for pass in 0..1:
    g = (pass==0) ? 游标 : cb*512              # 第二遍 = 回卷到开头
    while g + n <= hi_g:
        if 相交任一避让带: g = 带右端点; continue   # 跳过该小区间末尾
        if 每个 tile 都可用(位图/VRAM非空/ours): 领号并返回 g
        g += 1
return 0                                           # 宁缺不砸 UI
```

- **扩大**：起点由 `0x100` 改为 `cb*512`，上限吃满 `min(1024,(4-cb)*512)` —— cb0 窗由 `[256,1024)`(768)
  扩到 `[0,1024)`(1024)；cb2 窗由 768 扩到 1024。
- **尽头回卷**：第二遍从 `cb*512` 重扫（v8 原有行为，保留）。
- **分配器保留层不动**：位图 + VRAM 非空 + ours 段表（v8 原算法）继续做兜底；
  避让带是**新增的第一道**过滤，不是替代。`0x100` 起点被带表取代。

**cap 规则**（ROM 跳表 + pokeruby 源码双证一致）：

```
textMode != 1                 → 0      （tm0/tm2/tm3 不铺图集）
fontNum 0 或 3                → 512    （LoadFixedWidthFont）
fontNum 1/2/4/5/6             → 256    （Font1Latin / Font4Latin / Braille）
fontNum > 6                   → 0
```

### 跳板设计（Thumb-1 安全）

**ROM 桩 8B，不碰栈、不占 callee-saved**：

```asm
.org InitWindowTileData            ; 0x08002950 (覆盖 4 条原指令共 8B)
    ldr  r3, =(ChsAtlasWin_Entry | 1)
    bx   r3
    nop
.pool
```

**跳板**：`push {r4,r5,r6,lr}` 保参 → `bl` C 登记 → 复原被桩覆盖的原指令 →
`ldr r6,[sp,#12]; add sp,#16; push {r6}` 把栈还原成「原生 `push {lr}`」的形状 →
`bx` 到**奇数**续跑地址。这样原函数尾部的 `pop {r1}; bx r1` 能原样返回。

- #3/#4 是**叶函数**（无 `bl`、无栈帧），跳板直接**整函数重放**后 `pop {r4, pc}` 返回，无需续跑地址。
- 续跑地址：#1 → `0x08002961`；#2 → `0x080028C5`（均为奇数）。

### #3/#4 的 cb 来源（已知取舍）

`SetBaseTileNum(base)` 签名里**没有 win**，取不到模板。方案：用 #1/#2 维护的「当前窗口」记录
（win → tpl → cb）来定 cb。极端调用顺序下该记录可能还是上一个窗口 ⇒ 该带落在上一个 cb，
对当前窗**无效但无害**，且下次换主即清。**接受这一取舍**（记入待办，不阻塞）。

### 9.4 tm 分派与 cap 的确切规则（本轮反汇编实证，纠正两处）

`0x08002950` 跳表 @`0x080029B0` + `0x08002BD0` 常量 @`0x08002C20`：

| textMode | 分支 | 返回值 |
|---|---|---|
| 0 / 2 / >3 | `0x080029D8` | **0**（不铺图集） |
| 3 | `bl 0x08002BD0` | **`startOffset + 602`**（常量 `0x25A`）—— **不登记**，理由见下 |
| 1，fontNum 0/3 | `0x080029CC` | 512 |
| 1，fontNum 1/2/4/5 | `0x080029D2` | 256 |
| 1，fontNum > 5 | `0x080029D8` | **0**（跳表只有 6 项） |

**两条订正**（相对本文件早前的表述）：
1. ✅ **fontNum = 6 也是 0** —— 跳表 `cmp r0,#5; bhi → 0`，只有 0..5 有效。

   tm3 **有自己的分配方式**：静态网格 `tile = TILE_BASE + 2 + (win[1A]+win[1B]) + 30*(win[1C]+win[1D])`。
   那个 602 是**下一窗的游标推进量**，不是它占用的 tile 数；把它登记成避让带 =
   **白吃 tm1 的空间（489 → 398）**。
   🔴 规则：**只有 tm1 需要分配**（它有图集预留、且没有动态分配器）。tm0 线性 /
   tm2 血条(OBJ 区) / tm3 网格，三者各有**官方私有区**，一律**不登记、不夺主、不重置游标**。
   「有分配函数」≠「需要分配」—— 历史裁定见 `.workbuddy/memory/2026-09-09.md` 17:00 / 18:55 / 20:20。

**每轮可分配量（推演输出）**：

| 窗型 | 引擎自留 | 中文可用 | 折合字数（每字 2 tile） |
|---|---|---|---|
| cb0 / cb2 + tm1（cap 512） | `[1,535)` | **489 tile** | 244 字 |
| cb2 + tm3（cap 602） | `[1,625)` | **399 tile** | 199 字 |

### 9.6 与方案的两处实现偏差（均为主动决策，非妥协）

1. **起点用 `cb*512 + 1`（相对号 1），不是 `cb*512`（相对 0）**。
   相对 0 是 tilemap 的**空白槽**，占它会让所有空白格显示我们的字（全屏花）。
   引擎自留区实测从 1 起（图集 `startOffset` 恒 1），所以 1 是「引擎自己也没用」的第一个号。
2. **`v8_unmark_ours` 是本轮新增**（方案 §4 未预见）—— 见 9.5 ③。

### 9.7 已知风险 / 待实机确认

1. **「图集钩子 = 整窗重画」是本策略的前提**。若某个路径只局部重画（图集钩子后并不重画全部文字），
   `v8_unmark_ours` 会让上一轮的字被回收 ⇒ 砸字。目前由「每轮重画都有图集钩子」的实测支撑
   （17 次开窗 / 58 条 ITP），但**未逐场景验证**。
2. **框钩子 cb 缓存滞后**：反向链（先框后图集）或纯框路径下，`ADDR_CHS_CUR_CB_G` 可能是上一个窗的值，
   带会记到错误 cb。跨窗时换主会清掉（无害）；同窗则值正确。**最坏情况是误封 9/14 tile**。
3. **`v8_alloc_n` 返回 0 时** `print_glyph_px` 直接放弃该字（不画）—— 症状是**缺字**而非乱码，
   这是刻意的（宁缺不砸）。
