### 2.1 手段分层（沿用 `调研_20260923_全网GBA汉化字库路线.md`，本轮新证据补强）

| 层 | 手段 | 本轮新增证据 |
|---|---|---|
| L0 不动引擎 | 码表换字模 / 子集顶槽 / 图片字 | 经典流程教学（CrystalTile 载码表→WQSG 导出→字库替换→回灌），译文卡长度是硬伤 |
| L1 改读码/宽度 | 双字节判定 / 宽度表 / 多字库 | rh-reborn 指南：VWF 与 16bit→8bit 字库转换并列为**字体类最难 hack** |
| L2 改落点 | **L2a 美版窗契约** / **L2b 软件缓冲** / L2c 按窗生命周期灌槽 / OBJ / 位图 | 公开成片主路径只有 L2a/L2b 两条；「测空闲带」无人当主架构 |

### 2.2 权威参考实现（本轮检索钉死出处）

- **Mother 3 英化（Tomato《Text Welding 102》）**：VWF 标准 = 宽度表 + 二进制移位 + OR 合并，
  「必须记住上一字符的移位值」——与本工程 `print_glyph_px` 相位两段式同源。
- **KaioShin《Dragon Quest Monsters VWF 源码》（romhacking.net/docs/337）**：GBA 平台公认
  「重注释的可用 VWF hack 源码」，学习 VWF 的标准教材。
- **gb-vwf（ISSOtm）/ untoxa gb-photo `vwf.c`**：位移机制（`vwf_print_shift_char_right/left`）、
  tile 自动换行、零像素缓冲的平台无关 VWF 参考实现。
- **美版 pokeRS 官方引擎（pret text.c 抓取复核）**：
  - **无像素缓冲**；mode0/2 = `sGlyphMasks[9][8][3]` 亚 tile 掩码混合写入 + `tileDataOffset` 跨 8px 边界推进；
  - mode1 = 开窗一次性预渲 256 字形图集（font0/3 返 512，其余 256）；
  - mode2（变宽）= `InitWindowTileData` 返 `start+2+w×h`（**窗私有网格**，位置寻址）；
  - 字宽表驱动 `GetGlyphWidth`（日版无此函数，步进硬编码在各 FontFunc）；
  - `DrawDownArrow` 同样被 `(left+cursorX)&7` 分割成残缺左半+完整右块 —— 与本工程已修的 FA/FB 箭头落列问题同构。
- **pokeE（FRLG/E）window 模型**：`FillWindowPixelBuffer` → 逐字画进**窗像素缓冲** → `CopyWindowToVram`
  整页拷 —— 这是美版设置页「不撞」的真正原因（S6 曾对标，败在落点映射）。

### 2.3 非 8/16px 字体渲染的五类技术（本轮重点）

GBA BG 硬件网格粒度 = 8×8 tile；字宽非 8 倍数 ⇒ 必然跨 tile。公开世界只有五种解法：

| # | 技术 | 机制 | 运行时状态 | 代表 |
|---|---|---|---|---|
| 1 | **亚 tile 位移混合写入（VWF 标准）** | 像素游标 mod 8 → 掩码 RMW 进当前 tile，溢出段 OR 进右邻 tile | 上一字移位值（1 个变量级） | Mother3、KaioShin、**本工程 print_glyph_px** |
| 2 | **软件像素缓冲** | 整窗画进 EWRAM 位图（任意 x/y），完成后整块拷 VRAM | 缓冲指针 | Mother2 vwf.c、pokeE window、Tonc TTE |
| 3 | **双 tile 预切分（构建期）** | 非整宽字形在**打包期**预切成左/右半 tile 两个独立码位 | **零** | rh-reborn dual-tile encoding |
| 4 | **窄字形（宽≤8）** | 字宽 8 ⇒ 整列对齐，相位恒 0 | **零** | 寒蝉 7px/美咲（本工程 09-07 调研已立项候选） |
| 5 | OBJ 精灵 / 位图模式 | 字画 OBJ VRAM / Mode3-5 刷像素 | 独立 | 教材多，Gen3 日版菜单无成片先例 |

**数学极限（已静态推演交叉验证，`调研_20260907_12px省tile方案全网检索.md`）**：
12px 步进下相位 mod 8 序列唯一固定为 0,4,0,4… ⇒ **1.5 tile 列/字是水平极限**（现状已达成）；
垂直 ⌈11/8⌉=2 行 ⇒ **11×11 墨 12px 步进 = 3 tile/字封顶**；8×12 窄字形 = 2 tile/字。
行距共享（<16px）会破坏清行语义，不可行。

**对本工程的结论**：渲染技术本身（技术 1）已与世界同步且是官方同构实现；
技术 2 是所有权问题的另一种载体（缓冲仍要落 VRAM，落点所有权没解决就还是撞）；
**技术 3/4 是真正能「消灭相位状态」的降维手段**，此前只在 09-07 文档提过，未纳入重构主线。

## 3. 根因陈述（为什么必须重构，重构什么）

1. **tm1 所有权缺失是唯一结构性难题**。日版 tm1 = 内容寻址共享图集（256 字形预渲 [1,513)），
   没有美版 mode2 那种「窗私有网格」；v8 动态分配器是三闸门安全网，不是终态
   （09-23 调研 §3：路线 A 是基线不是目标）。
2. **相位三件套（PHASE/LAST_TILE/ROW）是 12px 跨 tile 的运行时状态**。换行半字、冒号鬼影、
   缺角、跨串尾列污染等历史 BUG 全部源于「字形渲染带跨字状态」。
3. **美日引擎语义错位**：日 4 种 textMode（线性/图集/缓冲/网格）vs 美 3 种（等宽图集/变宽画布）；
   日版无 GetGlyphWidth，宽度=步进硬编码。
4. 渲染原语（blend_glyph）与字库链（BDF→1bpp 位流）已达标，**不动**。

## 4. 重构方案

### 4.0 目标架构不变量（重构后任何代码不得违反）

1. **所有权三层**：只写「官方已为该窗映射的格」（tm0 线性/tm3 网格/tm2 缓冲）
   或「经声明式登记的格」（tm1，逐窗 gdb 验证）；禁止任何运行时扫描/预测/顶占。
2. **渲染层零状态（目标态）**：字形落点 = f(像素游标)，像素游标随行复位；
   不存在跨字/跨行/跨串的全局状态。
3. 字库 ROM 常驻、索引→地址纯函数（已达成，保持）。
4. 每一步独立打包、独立实机截图验收；禁区 D1–D5 重申有效。
