# 方案_20260924 — R 路线：tm 入口表级替换（真·底层切换）

> 背景：T2b/T2c/T2d 三连败（2026-09-24 实测），外挂画布模型被用户识破——
> 「说好听是画布，说难听又是高水位区间」。用户指路：**解析 tm 入口，改掉底层，纯静态完成**。
> 本方案 = 该指路的落地设计。全部静态，零 gdb 前置。

## 0. 对三连败的根因重判（先认账）

T1~T4 外挂模型的所有权判定 = v8 位图 + VRAM 非空扫描 + ours 段表——**后台扫描猜占用**。
这与死路「避让带」（docs/禁止_避让带与抬水位_只认VRAM分配器.md）的「同源＝无所有权裸抢占」
**同构**，只是猜的手段更精细。美版画布不踩，是因为美版引擎自己排布全部窗；
我们外挂在日版引擎旁圈地，日版引擎不知道我们存在 ⇒ 互踩/多窗互挤/逐窗登记全是这个
所有权模型错误的症状，不是 bug。**继续在外挂层打补丁没有出路。**

## 1. 核心事实链（全部静态反汇编已证，见 勘测_20260923_S1-S7 + 本轮补测）

1. **TLWT（0x08002950）= 官方「窗 tile 初始化」统一入口**。本体语义：
   `TLWT(win, tileBase)` → 全局记录 0x0202E6E8=win / 容量→e6f0 记录 / `win[0x16]=tileBase`
   → 按 模板[9] textMode 分派：tm1 开图集渐染主流程、tm3 → 0x08002BD0 网格、tm2 直通。
   仅 2 个 BL 调用点（0x080685CA 任务流 / 0x0806F006 文本泵态），零字面量引用。
2. **win[0x16]（WIN_TILE_BASE）= 官方「本窗字形 tile 基址」权威字段**。全 ROM 半字访问
   25 处（本轮字节级扫描）：WriteGlyphTilemap 全家族（0x080034AE~0x080035F0）、
   清窗/行清助手（0x08003D42~）、GetBlankTileNum（0x0800420C~）、箭头（0x08003DF2~）、
   高层 API（0x08068898/0x0806B7E0/0x0806D4BC~）——**官方一切写表项的函数都从它拿基址**。
3. **S5 定案**：WriteGlyphTilemap 三函数全 ROM 零 BL 直调，唯一入口 =
   FontFuncTable@0x081BB3AC（[1]=tm1 主）+ FontSubTable@0x081BB3BC —— 表级替换一次全切 36 窗。
4. **S4 定案**：Multistep stub（mov r0,#1; bx lr，已在）⇒ 图集渐染立即完成、
   任务流/泵走「完成」分支、SetBase 框带翻转照旧 —— **e6f0 seam（3 态+51 字面量）不受扰**。
5. **S6 定案**：日版 Text_ClearWindow=0x08003BA8（桩已在）+ 行清助手 0x08003C00，
   fill = palette<<12 | blank tile（blank 号同样源自 win[0x16] 区）——画布化后天然按窗私有区填白。
6. **S7 定案**：美版模板表 58 项已复现（50 标准 30×20 + 7 特例）= w×h 参数的静态来源；
   日版 36 tm1 模板按 (cb+tileData+tilemap) 归 15 家族。

## 2. R 路线设计（六件套）

### R1. TLWT 语义替换（唯一开窗分配点）
armips 改 0x08002950 入口跳 hook（同现行 stub 机制）。新实现：
- **照抄官方序言**：e6e8=win、容量→e6f0、win[0x16]=tileBase（官方协议保真，
  下游 51 字面量继续工作，C1 seam 不碰——**不动 TLWT 返回值语义**）；
- tm1 分支：不再进图集渐染 → 按 win[0]（模板指针）查**家族→w×h 静态表**
  （15 家族，构建期从美版 58 模板表对应生成）→ 分配器一次领断 2+w×h 连续画布
  → **win[0x16] = 画布数据基址（相对号）** → 登记 (win, base, w, h) 进大记录表；
- tm3 → 照旧 bl 0x08002BD0；tm2 → 直通（EWRAM 缓冲窗，无需 VRAM 分配）。

**为何这不是抬水位**：抬水位=全局基址顶起+SetBase 改写+textMode 冒充+无生命周期；
R=**窗入口官方协议内分配**（TLWT 调用点=官方正开窗那一刻）+**官方字段承载**
（win[0x16] 全家族函数自动跟随）+**生命周期=官方窗生命周期**——美版 mode0 的忠实复刻。

### R2. 中文打印接线（改 PrintNextChar_hook.c 的 chs_emit tm1 分支）
- 画布基址来源从 canvas_lookup（2 槽）改为 **win[0x16] 直读 + 大记录表查 w/h**；
- tm1_canvas_print 位置寻址逻辑不变（base + row*w + col，下半 +w）；
- **tm1 的 v8 逐字领号路径整体退役**——tm1 窗必有画布（TLWT 替换点统一分配），
  领断失败=显性失败宁缺不砸。**回收问题整个蒸发**：画布生命周期=窗生命周期。

### R3. 记录槽 2→36
每个 tm1 窗一槽（36×12B=432B EWRAM）。登记/释放由官方调用驱动
（TLWT 替换点登记、ClearWindow 桩/关窗链释放）。canvas.c 的智能淘汰/protect/
回落计数机制随之简化删除——不再需要「保护位图重建」（没有 v8 字形领号了）。

### R4. 假名表项改道（S5）
FontFuncTable[4..6] / FontSubTable 4 表项 → 画布寻址变体
（upper/lower = 画布基址+偏移）。静态假名引用（图鉴/菜单固定字样）跟随画布，零调用点搜索。

### R5. ClearWindow 桩维持（已在）
0x08003BA8 钩 + 行清助手 0x08003C00 原生——blank tile 源自 win[0x16] 区，天然画布填白。

### R6. v8 裁定
- **退役**：v8_alloc_tile / v8_phase_last_tile / 相位尾列推导（tm1 不再有逐字领号）；
- **保留改名**：v8 分配器算法本体 = 画布 Arena 的唯一分配出口（开窗一次领断），
  开窗当场判定（位图重建+VRAM 非空）与美版 Text_InitWindow 同构。

## 4. 残余风险与静态论证清单（实施批次内完成，非逐场景工程）

1. **Arena 容量**：同屏多 tm1 窗总需求 vs cb0 0x100~768 格。按家族尺寸表静态估算
   最坏屏（领航员页/战斗屏）；超标=显性失败（宁缺不砸）。必要时 cb2/cb3 Arena 扩展
   （tm1 窗 cb=0 的表项只能指 cb0 —— 此约束下容量论证是硬前提）。
2. **非文本消费者撞 Arena**：S3 的 27 处 SetBase 清单论证框带不落 cb0 字形区；
   图形解压消费者（背景/图标）写址一轮静态扫描（谁写 cb0 0x100~）——一次性「Arena 论证」。
3. **家族→w×h 映射**：日版 15 家族 ↔ 美版 58 模板场景对应，一轮静态核对。
4. **win[0x16] 语义复核**：25 处消费者逐个确认在「画布基址」语义下行为正确
   （tm3 自写不受影响；tm2 直通；官方假名表项=画布+2·glyph 的寻址差已由 R4 吸收）。

## 5. 实施顺序（全部纯静态 → 构建期产物）

- **S-A 静态论证三件**：家族映射表 / Arena 容量估算 / 非文本消费者扫描（本方案 §4.1~4.3）
- **S-B hook 实现**：TLWT 替换函数（C）+ 家族表数据 + chs_emit 接线改造 + 记录表 36 槽
  + 假名 4 表项 armips 改表
- **S-C 构建**：hook build.bat（game.bin）→ armips → 嵌入校验 → seed-only 打包
- **S-D 验收**：用户实机（四步法第③步）——重点：领航员列表/marquee（重复打印根因场景）、
  对话/菜单/设置回归、最坏屏（战斗+对话叠加）
- 实施后一次性 gdb 抽查（非前置）：e6f0 三记录新语义核对（勘测文档 G2 缩减条款）
