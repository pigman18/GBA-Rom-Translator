# 方案总纲 v13 —— AXVJ00 汉化（2026-09-20 重整理）

> 本文件是**唯一总纲**。此前 20+ 份方案/调研/复盘**降级为取证材料**，不再作为路线依据。

## 0. 一句话

验收只有两条：**① 中文正常显示 ② 不撞 UI**。
这两条各自有一条**独立**根因，过去一年多只在第 ① 条上打转，第 ② 条一直靠「换更窄的字号」绕过去
⇒ 一旦按用户要求统一 **11×11**，第 ② 条立刻爆。

**v13 = 把两条根因各自搬到"可以静态验证"的地方：**

| 根因 | 旧做法 | v13 |
|---|---|---|
| **R1 落点撞车** | 运行时领号 + 读回 tilemap 猜「这格是不是我们写的」 | **格子定号**：号只依赖屏幕格子，不依赖账本 |
| **R2 版式溢出** | 把字号压到 9×11 / 9×9 硬塞 | **构建期行宽审计 + 重排**（脚本已落地） |

## 1. 验收标准

1. **中文正常显示** —— 11×11 完整像素落屏，不缺列 / 缺行 / 错位 / 散架 / 被邻字覆盖。
2. **不撞 UI** —— 不覆盖 UI 图形与边框，也不被覆盖。
3. **字号目标：能用 11×11 就用 11×11**（用户 2026-09-20 明确要求）。
4. 🔴 **做不到时的正确反应是改实现或改文案，不是降低判据、不是压字号。**

## 2. 关键事实（决定方案，均已实证）

| 事实 | 数字 / 依据 |
|---|---|
| 日版引擎**每字 8px** 步进 | tm1 `win[0x1B] += 1`（1 格 = 8px）；tm0 `TILE_OFFSET += 2`（单位 4px ⇒ 8px） |
| 中文大库**每字 12px** 步进 | `PrintNextChar_hook.c` `resolve_draw`：adv 12 / ink 11 |
| 11×11 字的 tile 成本 | **每格 2 个 tile**（上 8 行 + 下 3 行）⇒ 一行 240px = 30 格 = **60 tile** |
| 官方资产上界**可算** | `font0/3 → 535`，`font1/2/4/5 → 279`（v12 实证，禁硬编码/抬水位） |
| 可用池 | `[上界, 1024)` ⇒ 489 号（统一口径）/ 745 号（font1/4/5） |
| **9×11 省不下 tile** | 11 行仍要 2 个 tile 行，9 列仍要 2 个 tile 列 ⇒ **与 11×11 同为 4 tile/字**；唯一收益是一行多排 20% |
| 9×11 的字形本身失真 | `Middle.bdf` 由 `Normal.bdf` **11→9 列 OR 分组**派生（`fonts_patcher.py`）⇒ 笔画粘连 |
| 容量从来不是瓶颈 | 全游戏 2625 个不同汉字；一屏最多 20 列 × 4 行 = **80 格位** ⇒ 一屏不同的字 ≤ 80 |
| 日版 tm1 **只给格子不给号** | `FontSubTable` 四个子处理器全部只调 `UpdateTilemap`；号 = `TILE_BASE + 常量`（图集） |

> ⇒ **9×11 档位退役**（步骤 4）：同样的 tile 成本、更差的字形、只为省 20% 行宽 —— 不值得。
> 行宽问题由 K 线在构建期解决。

## 3. 根因分解

### R1 · 落点撞车（「中文显示不正常」的根）

中文要显示，必须写两样东西：**tilemap 的表项（指向哪个 tile 号）+ VRAM 里的字形**。
日版引擎只提供「格子位置」（`GetCursorTilemapPointer`），**不提供可用的 tile 号**
（tm1 的号全部指向预载日文图集）。

于是我们自建了「按字领号的全局池」，并追加了一整套**猜测机制**：
`ours 账本` → `复用闸门（竖直对自洽）` → `官方上界判据`（v10 → v10.1 → v11 → v12）。
**每一次修复都只是换一种猜法**，症状因此每轮都不同（面板串扰 → 抬水位 → font4 被覆盖 → 领航员）。

⇒ **结论：号必须是「位置」的纯函数，账本/闸门/扫描全部删掉。**

### R2 · 版式溢出（「撞 UI」的根，本次首次量化）

中文 12px vs 日文 8px ⇒ **同样内容宽 50%**。任何按日文 8px 排好的固定版式，
换成中文必然超宽，多出来的部分直接压到边框/邻窗上。

🔴 **实测（`scripts/audit_line_width.py`，见 §6）：1382 行译文比日文原版式更宽。**
其中**命名类 604 行**（宝可梦名 202 / 训练家个人名 142 / 道具名 100 / 图鉴分类名 53 /
秘密基地装饰名 35 / 招式名 33 / 树果名 17 / 特性名 8 / 训练家名 8 / 属性名 2 / 性格名 2 / 地点名 2）
—— 这些出现在**逐项列表**里，最直接的表现就是「撞 UI」。

这条根因**与落点无关**，改分配器一万遍也不会好。

## 4. 设计

### L 线 · 格子定号（消 R1）

```
tile(win, 格) = BASE(win) + 2 × 格内线性格号
格内线性格号 = dy × WMAX + dx          （dy/dx = 相对窗口左上角的格偏移）
WMAX        = 32                       （一行最多 30 格 / 240px）
BASE(win)   = 本窗口私有块基址，窗口初始化时从池 [上界,1024) 领一次，销毁归还
```

**四条性质（就是验收标准的证明）**

| # | 性质 | 对应验收 |
|---|---|---|
| ① | 同一格恒得同一个号 ⇒ 重画/翻页/滚动**零消耗**、天然幂等 | 不需要「识别这格是不是我们写的」 |
| ② | 不同格必得不同号 ⇒ 两格**结构上不可能**串扰 | 面板串扰 / 队伍页叠字消失 |
| ③ | 号物理上出不了私有块 ⇒ **结构上不可能**撞 UI / 覆盖 font4 | 不撞 UI |
| ④ | 相邻两字**共享一格是正确行为** | 12px 步进下相邻字的尾列/首列本来就落在同一格 |

> ④ 很关键：**内容定号（按字符码）在 12px 步进下是错的** ——
> 一格的内容是「上一字的尾列 + 本字的首列」的混合，不是任何单个字的字形。
> 所以号只能跟**格子**走，不能跟**字符**走。

**删除清单**：`v8_ours_has` 账本 · `chs_cell_slot` 复用闸门 · 活引用/VRAM 扫描 ·
`v8_alloc_tile` 逐字领号 · 抬水位常量。**保留**：`v8_phase_*`（12px 相位）、
`blend_glyph_4bpp` / `extract_cols` / `chs_cell_from_1bpp`（渲染链本身已达标，实测差异 0 像素）。

### K 线 · 构建期排版（消 R2）

- 在**PC 侧**把每条译文按「该窗口的可用像素宽」重排（插 `\n`），**运行时零改动**。
- 第一步只做**审计**（脚本已落地），把溢出清单变成可追踪的构建产物；
  第二步按清单改文案 / 加重排规则。
- 窗口可用宽优先取**场景表**（可证伪、可复核），勘测一次落盘 —— **不做运行时猜测**。

## 5. 容量账（把「空间不够」彻底钉死）

| 口径 | 号数 | 满窗成本（30 格 × 4 行 = 240 tile） |
|---|---|---|
| 统一池 `[535, 1024)` | 489 | **2 个**满窗 |
| font1/4/5 池 `[279, 1024)` | 745 | **3 个**满窗 |
| 常见文本窗（≤24 格 × 3 行 = 144 tile） | — | 489 号容 **3.4 个** |

⇒ **容量够。** 若真的不够，正确反应是**缩短文案**（K 线），不是压字号、不是抬水位。

## 9. 未决 / 风险（每条都给了退路）

| # | 未决点 | 退路 |
|---|---|---|
| 1 | `BASE(win)` 的**窗口生命周期钩**：窗口销毁是否有可靠钩点未证实 | 按 `win` 指针登记 + 会话边界（`InitTextPrinter`）回收；不做跨会话常驻 |
| 2 | **静态 BG 美术**（`bl 0x081B1298` LZ 到固定 VRAM 地址）是否侵入池 | 做一次**静态枚举**（118 个调用点的 src/dst），把结果当**事实表**；🔴 注意 v20 门控**当前不在树内** |
| 3 | 窗口**可用像素宽**表的来源 | 场景表（可证伪）→ 美版孪生模板 → 一次性勘测，三者择一，**不做运行时猜** |
| 4 | `WMAX = 32` 的边界行为（超宽行的兜底） | 超界即判异常并单独报告，不静默截断 |
| 5 | `build.bat` 内**明文 API key**（P0 安全） | 改环境变量读取 + 轮换 key（与汉化本身无关，但必须做） |

## 10. 禁止事项（不要再提）

- **抬水位 / 设不可用区 / 场景签名避让带**（09-08 三次被用户当面拆穿）。
- **压字**：8×16 压缩、每行 2 字节、任何丢第 9～11 列的做法。
- **借道官方 `TILE_BASE`**（B2，2026-09-20 实机 A/B 否决：设置菜单整体错乱）。
- **运行时"猜哪些 tile 空闲"**（v8→v12 五个版本的全部失败模式）。
- **用缩字号绕过排版问题**（tm2 血条缓冲除外 —— 那有物理约束）。
- 移植**美版 `text.c` 全套**（两次失败已归档：`docs/移植失败缺陷台账_rh汉语引擎_20260920.md`）。
