## 一、先把上一版方案否掉：测量是死路

上一版提出「实测同屏不重复字形数 N，再决定要不要扩容」。**用户否掉了，否得对。**

理由是形式化的：

```
需求 = 同屏不重复字形数 = f(文本量)      ← 无上界
供给 = 1024 − 512(官方图集) − 23(窗框) ≈ 489   ← 常数
```

只要左边是「字的函数」，它就会随剧情推进、随战斗轮数、随菜单层级一直涨。
测出 500 只说明**今天**是 500；明天加一段剧情就是 1000。
**任何「测量后再适配」的方案，本质都是在一个发散的数列上追一个固定值。**

⇒ 正确的目标不是把 489 做大，而是**让左边不再是「字的函数」**。

## 二、本轮实测新事实（全部可复核，命令附在文末）

### 🔴🔴 事实 1：52 个窗口模板里，**36 个走 tm1**（69%）

```
tm0 : 14 个模板
tm1 : 36 个模板     ← 我们自建分配器的唯一原因
tm3 :  2 个模板
```

**tm1 的官方语义 = 「共享图集 + 内容定号」**：官方 tm1 处理器只调 `UpdateTilemap`，
自身不碰 VRAM、不推进游标 ⇒ tile 号只能 = `TILE_BASE + 2×字形号`（内容定号）。
字形号是**字**的函数 ⇒ 需求 ∝ 字。**这就是「涨到 1000」的源头。**

**tm0 的官方语义 = 「位置定号」**。日版 tm0 处理器全文（`0x08003568..0x08003580`，**12 条指令**）：

```
0x0800356C  bl  0x08003520        ; blit 字形到 TILE_BASE + TILE_OFFSET
0x08003570  ldrh r0, [r4, #0x18]  ; TILE_OFFSET
0x08003572  adds r0, #2
0x08003574  strh r0, [r4, #0x18]  ; TILE_OFFSET += 2   ← 纯位置推进
0x08003576  ldrb r0, [r4, #0x1b]  ; CURSOR_TILE_X
0x08003578  adds r0, #1
0x0800357A  strb r0, [r4, #0x1b]  ; CURSOR_TILE_X += 1
```

**零状态、零分配、号 = 位置的函数。** 官方 14 个模板已经在这么用。

⇒ **我们要的架构，引擎里本来就有，只是没用在中文要的那 36 个窗口上。**
不是"推倒重写"，是**改走引擎已有的另一条分支**。

### 事实 2：TILE_OFFSET **是**会被复位的（否掉了我原本的"累加泄漏"猜想）

全 text 引擎区（`0x08002800..0x08004000`）只有 **3 处**写 `win[+0x18]`：

| 地址 | 指令 | 身份 |
|---|---|---|
| `0x08002CA4` | `strh r6, [r0,#0x18]`，r6=0 | **printer init 的复位点（唯一）** |
| `0x08002D90` | `strh r0, [r0,#0x18]`，r0=4 | tm0 路径自行置位 |
| `0x08003574` | `strh r0, [r4,#0x18]` | tm0 处理器的 `+= 2` |

⇒ tm0 的 `TILE_OFFSET` 每个**文本块**开始时归零。
**"战斗久了乱飞"不是 TILE_OFFSET 累加造成的**（原假设已自证否定，不进方案）。

### 事实 3：官方资产 = 512 号，且几乎所有窗口都要它

```
font3 ×49 个模板   ← 官方资产上界 = 512
font0 × 2
font4 × 1          ← 上界 256
```

### 事实 4：文本摊在 **四个 charBlock** 上，而 cb1/cb3 几乎空着

| cb | 模板数 | 其中 tm1 / tm0 |
|---|---|---|
| cb0 | 24 | 18 / 6 |
| cb2 | 20 | 15 / 3 |
| **cb1** | **4** | 1 / 3 |
| **cb3** | **4** | 2 / 2 |

**关键**：tilemap 表项只有 10 bit ⇒ **1024 是「每个 BG 层」的上限，不是全局的**，
上限由该层 `BGxCNT.charBase` 决定。GBA 有 4 个 charBlock（4×1024 号）。
**现在把 tm1 堆在 cb0/cb2，等于主动把 4096 切成碎片，还让 36 个窗口去挤官方图集那 512。**

### 事实 5：`TPL_TILE_DATA ≡ 0x06000000 + charBase×0x4000`

52 个模板逐条核对，100% 成立。⇒ 它是**派生值**，不是自由指针；
**换画布的唯一旋钮就是 charBase**。

## 三、核心：把领号的**单位**从「字」改成「窗口」

| | 现在（tm1 通路） | 目标（位置定号） |
|---|---|---|
| 领号时机 | **每印一个字**领一次 | **每个窗口开一次**领一块 |
| 号是什么的函数 | `字` ⇒ 无上界 | `格子坐标` ⇒ 常数 |
| 账本规模 | ∝ 文本量，一直涨 | = 同屏窗口数（≤10） |
| 跨窗状态 | phase / last_tile / ours / 游标 都要共享 | **一个都没有** |

**"涨到 1000 怎么办" 的标准答案：不会涨。**
因为领号的**主体**从「字」（无上界）换成了「窗口」（同屏 ≤10 个）。
一屏就那么多窗口，窗口就那么大，**需求是一个屏幕几何常数**：

```
一个窗口的号需求 = ceil(W_px/8) × ceil(H_px/8)
屏幕物理上限（240×160 满屏） = 30 × 20 = 600 号
```

**600 是硬天花板 —— 与语料无关、与游玩时长无关、与战斗打多久无关。**

## 四、容量账（把不等式两侧都钉死）

**需求侧（位置定号后）**

| 场景 | 同屏窗口 | 画布面积估算 |
|---|---|---|
| 战斗 | 主文本框 + 招式名 + HP 名 ×2 + 提示框 ≈ 5 | 主框 ~208×32 ⇒ 26×4=104；其余各 ~20~40 ⇒ **合计 ~250** |
| 领航员 | 分区标题 + 列表 + 说明 ≈ 4~6 | **~300~450** |
| 满屏极限（构造最坏情况） | 1 | **600** |

**供给侧**

| 项 | 号数 |
|---|---|
| 一个 charBlock | **1024** |
| 官方图集（font3 上界 512）**仅当与中文同 charBase 时才扣** | −512 |
| 窗框 | −23 |
| 名义池 | 489 |

**⇒ 结论：**
- 若中文与官方图集**同 charBase**：600 > 489 ⇒ **满屏仍差一点**（但不是差一倍，是差 ~110）
- 若中文**收敛到一个专属 charBase**（cb1 或 cb3，各只有 4 个模板，最空）：**1024 > 600 ⇒ 有余量**

⇒ **「位置定号」是地基，「专属 charBase」是配套的一半地。** 两者一起，账才平。
**注意这跟 v13/v14 的结论并不冲突，而是把"扩容量"从『必须做』降级为『兜底』**——
因为需求从无上界被压到了 600。

## 五、为什么这条能同时治「战斗页满」和「战斗久了乱飞」

**战斗页满**：满的是 **UI 美术**（静态 BG 层，从 0x081B1298 那类固定地址解压，**从来不申请号**）。
位置定号后，文本窗的画布是**窗口私有的**，与 UI 美术不共享号
⇒ **结构上不可能撞**（不再依赖"扫描 tilemap 猜这格是不是我们写的"）。

**战斗久了乱飞**：现在这条通路上，跨文本块**活着**的可变状态至少有四份：

1. `v8_phase` / `v8_phase_last_tile()`（后者是**单个全局**，相位键含 `tpl ^ curY ^ curTileY`）
2. `v8_ours` 账本（"我们发过号"）
3. `v8_alloc` 游标 + `V8Q_P_WIN`/`V8Q_P_TPL` 归属
4. `win[0x18]` `TILE_OFFSET` 与 `win[0x1B]` `CURSOR_TILE_X` 的联动

战斗里 **4~5 个窗口同时活着**，而这几个文本框按现有记录**共用同一个模板**（"战斗四格 BASE≈0x90 与
『怎么办』BASE≈0x190 同 tpl/同 cb"）。共用模板 ⇒ 相位键可碰撞 ⇒ 两个同时活着的窗口
**共享一个相位累加器和一个 last_tile** ⇒ 后开的窗口把字写进前一个窗口的 tile。
**战斗轮数越多，错得越远** —— 完全符合"久了才乱"。

> ⚠ **诚实交代**：这一条我**尚未逐条证实**（只证实了 TILE_OFFSET 不是它）。
> 上面 4 份状态都是"缓存模型"的**必然产物**，位置定号后**全部消失**，
> 所以它不影响方案选型；要精确定位是哪一个，是一个 5 分钟级的静态核查。

## 七、判据（L1，可自证）

1. **J1 位置性**：同一段中文，在 tm0 通路上，第 n 个字的 tile 号必须 ==
   `TILE_BASE + f(第 n 个字的格子坐标)`，**与字面内容无关**。
   验证：同一行换成完全不同的字，tile 号序列必须**逐项相同**。
2. **J2 无跨窗状态**：两个窗口交替打印同一批字，各自 tile 号序列必须
   **与单独打印时逐项相同**（现在这条必然失败 —— 这就是 J2 的价值）。
3. **J3 需求常数性**：连续打 100 个文本块后，**已发号总数不增长**
   （现在必然失败：∝ 字数）。
4. **J4 画布不越界**：任意场景下 `画布基址 + 面积 ≤ charBase + 1024`，
   且 `≥ 官方资产上界`。
5. **J5 像素真值**：沿用 `scripts/verify_plan4.py`（BDF 真值 → 重建屏幕 → 逐像素比对，差异必须 = 0）。
