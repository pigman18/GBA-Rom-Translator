# 禁止：假划界 / 抬水位冒充美版 Window 移植

> 日期：2026-09-08  
> 裁定：用户多次验收失败后确认——「占段 + 顶基址」≠ 美版窗划界。  
> 同步规则：`.cursor/rules/axvj-no-fake-window-port.mdc`（alwaysApply）。

---

## 1. 背景（已发生事实）

代理在「日美文本划界移植」中至少三轮口头承诺美版模型，实际交付仍是：

| 包装名 | 实质 |
|---|---|
| tm1 私有 30×20 / span 602 | 在共享 CB 上圈段 |
| `span≤512` | 限水位躲边框 |
| 同行清 12 列 | 绘制侧补丁 |
| hook `SetBaseTileNum`：落入 `[start,start+span)` → 改为 `start+span` | **全局抬水位**；能力页被误伤 |

用户原话级结论：垃圾代码对真移植无用；验不过应停；再换皮水位 = 没能力交付。

**后续仍犯（2026-09-08 夜～09）：** pending SetBase、写 `e6f0` 让原版 Continue 吃、再包装「已换 Continue」实则 Continue 内 `SetBase(start+602)`——过程见  
`docs/复盘_20260908_假接Continue与抬水位混验收.md`。

---

## 2. 禁止项（写进 diff 即违规）

1. 静态/半静态 **独占带**、**抬分配水位**、**span 上限卡死** 当主修法。  
2. **全局**改 `sTextWindowBaseTileNum` / `SetBaseTileNum`，使「凡进我段就顶出去」，账本跨场景不失效。  
3. 仅加 GCTN / blank×2 / mask / 清窗启发式，宣称 Window/引擎移植完成。  
4. 不改 Multistep / IWTD **开窗契约**，只在 `PrintNextChar` 侧堆补丁。  
5. 日版模板 `textMode→2` 冒充美版画布（另见 gdb 证伪黑名单）。

---

## 3. 真划界验收标准（少一条都不算做成）

1. **入口**：预算挂在当次窗对象（`TextPrinter` / `gMenuWindow`），IWTD/开窗路径以窗为中心，不是「全局带」。  
2. **预算**：`2+w×h`，w×h 来源可证伪（美版孪生模板 / W0 FRAME / 场景表）。  
3. **接框**：**同一次**开窗把「文字段结束 offset」交给框装载（语义 = 美版 IWTD 返回值）；**用后清除 pending**，其它场景 `SetBaseTileNum` 不被改写。  
4. **落址**：窗内 `start+2+row*w+col`（或官方等价）；tm1 画布路径 **无** v8 领号。  
5. **回归**：设置页边框完整 + 能力页等未开画布场景不被误伤。

---

## 4. 与「美版也是 start+span 接框」的区别

美版：`InitWindowTileData` **返回值** → 当次 `SetBaseTileNum(返回值)` → 装框。  
假划界：EWRAM 账本常驻 + **之后任意** `SetBaseTileNum(x)` 只要 `x∈[start,start+span)` 就改成 `start+span`。

前者是开窗契约；后者是跨场景水位。禁止把后者说成前者。
