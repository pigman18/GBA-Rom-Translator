移植做过**两次**，失败原因**不是搬不动代码**，而是三件事：
① **美日两套引擎虽然同源，但 ABI / 枚举 / 契约全不同构**（同名不同物）；

### 1.1 当年就发现、且**至今仍然有效**的缺陷（PLAN §附「三条布局硬事实」）

> 原文标注「勿凭印象推翻」，这三条是逐 case 对拍出来的：

1. **tm0 线性 CHS 流的溢出目标 ≠ 官方假设**
   字间 `WIN_TILE_OFFSET` 步进 `+2` ⇒ 溢出目标 = `t+2`，
   **不等于**官方假设的 `dest+32B`（`t+1`）。
   ⇒ 任何照搬 emerald/pokeruby 的跨 tile 补写逻辑，在 tm0 上都会错一列。

2. **tm1 / tm3 mode2 门控窗：`spill = map_tx + 1` → 物理相邻（+32B）是唯一吻合解**
   行首折断处 `startPixel` 归零，**天然无跨带 spill**。

3. **upstream `DrawGlyphTile` 家族的 mask/OR 数学不含「背景清扫」**
   emerald / pokeruby 都靠 `ClearTextSpan` / `FillBitmapRect4Bit` **先铺底**；
   本工程等价物是自有 `draw_tile` 的清底段。
   ⇒ 桥接时**必须补 span-clear 预填**，且 **pass2（width<8）需要 tile 序 → 高位对齐 nibble 重排**。

| 否决理由 | 证据 |

### 2.1 🔴 最致命缺陷：把美日两套 `textMode` 当成同一个东西（漏检 10 小时）

| | 美版 AXVE | 日版 AXVJ |
|---|---|---|
| 值域 | **{0, 1, 2}** | **{0, 1, 2, 3}** |
| 语义 | 0=?, 1=等宽, **2=变宽画布**（`InitVariableWidthFontTileData`） | 0=线性, 1=图集寻址, 2=`win[0x20]` 缓冲直绘（**血条，≠美版画布**）, 3=固定网格 |
| 对应 | — | **日版 tm3 在美版枚举里根本不存在** |

- 三点致命：值域不同 / 语义不一一对应 / 日版 tm3 无美版对应物。
- **当时手上明明有证据**：美日双方 gdb 日志都已采集、`textMode` 每条都打印着、
  甚至已按 textMode 做过分布计数；也分别反汇编了双方 `InitTextPrinter` /
  `InitWindowTileData` / 各 tm 落址。
- **根因不是证据不够，是没做「并排对照」这一步**（用户原话：随便把两个日志丢给没接触过的人，
  都不会觉得是同一个东西）。
- ⇒ **整晚「移植美版引擎」的产出全部作废。**
- 遗留结论：完整移植 = 把日版 **4 种** textMode 语义重构为美版 **3 种**，牵动
  `InitTextPrinter` / `PrintNextChar` / `AddToCursorX` / `GetCursorTilemapPointer` /
  `ClearWindow` / `UpdateBGRegs` / 图集装载 / UI 窗接管 **全套**，**不是 hook 两个函数能覆盖**。

### 2.2 结构性障碍清单（可行性文档 §4 / §5 定案）

| # | 障碍 | 数字 |
|---|---|---|
| 1 | `InitWindowTileData` **同址不同实现** | 双方入口都在 `0x08002A50`，但 JP 按 `tpl[8]=fontNum` 分路 + 共享图集预渲；US 按 `template->textMode` 分路 + 画布。**JP 返回 void，US 返回「下一窗起点」** |
| 2 | tile 号语义相反 | 美版 = **位置**（`行×宽+列`）；日版 tm1 = **内容**（`base + 2×字模号`）。⇒ **汉字装不进 256 槽 ⇒ 内容寻址物理失效** |
| 3 | 上界性质不同 | 美版 = 窗口面积（硬约束）；日版 = 字库槽 / 外挂分配器（**软约束**）⇒ 「撞 UI」= 软上界代偿失败 |
| 4 | `GetCursorTileNum` 移植目标公式依赖 tm2 | US：`textMode==UNKNOWN2` 时 `index = start+offset + row*width + col`；否则 `start+offset+2*xOff+yOff`。只有 UNKNOWN0 在跨 8px 时 `tileDataOffset += 2`，UNKNOWN2 **只加像素游标** |
| 5 | 日版 `tm3` 步长写死 30 | `tile = base + cur_x + 2 + cursorTileX + 30*(cur_y+cursorTileY)`——更接近「位置寻址」，与菜单 tm1 **不是同一病** |

### 2.3 🔴 W1「划界」实际交付 = 抬水位换皮（用户三次当面拆穿）

| 包装说法 | 代码实质 | 用户判定 |
|---|---|---|
| 美版私有窗 / span 602 | 共享 charblock 上圈段 | 无互不伤害的场景重切证明 |
| `span≤512` / 清 12 列 | 绘制侧补丁 | 「躲边框、擦邻居」，冒充开窗契约 |
| hook `SetBaseTileNum`：落入 `[start,start+span)` → 改 `start+span` | **全局抬水位** | 能力页被误伤 → 认定假划界 |
| 「一次性 pending」再在 SetBase 钩子里吃掉 | 仍 hook `SetBase` | 「1+2 → 2+1」 |
| 写 `*0x0202E6F0 = start+span`，让原版 `MultistepInitMenuWindowContinue` 自己 `SetBase` | **Continue 本体没换** | 用户：「所以你又绕回去了是吧？」 |
| 「已换 Continue 状态机」 | Continue 内仍是 `SetBase(start+2+30×20)` | 换皮水位 |
| 「ROM 已打好请测」 | 曾交付**无 Continue 跳板的旧文件名** | mGBA 文件锁导致 `_new` 才是带跳板盘 |

**追加的事实错误**（写进复盘 §4 技术锚点，禁止再编）：
- 日版 EWRAM：`0x0202E6EE` = text tile **start（打印用）**，`0x0202E6F0` = **下一段（接框用）**。
  把 start 语义写进 `e6f0`，**搅乱了日版变量分工**。
- **`0x081BB484` = 「请选择」类菜单窗，不是设置页专用孪生模板**；
  预算名单误用它 ⇒ 一开菜单就走画布 + `SetBase(602)`。
- 日版 Continue：`0x0806EFC0`（设置 `0x08088528` 有 BL）；设置模板 = `0x081BB874`(tm1)。

## 5. 强制规则（当年因这些失败而立，至今 alwaysApply）

| 规则 | 要点 |
|---|---|
| `.cursor/rules/axvj-gdb-killed-conclusions.mdc` | 6 条禁止再当前提（见 §5.1） |
| `.cursor/rules/axvj-no-fake-window-port.mdc` | 禁止抬水位/占段顶基址冒充美版 Window 划界 |
| `docs/禁止_假划界抬水位冒充美版窗.md` | 禁令全文 + 「真划界验收标准」5 条 |

### 5.1 gdb/实机已证伪结论（禁止重推）

1. **CY2 花 = 查看器伪影 / 根因 = tile 象限序** —— 已推翻。
2. **静态「独占带」/抬水位** 当地基 —— 含已证伪的 cb0 `[0x2D2,0x400)` + 假划界。
3. **日版 `textMode=2` = 美版窗画布** —— 日版 tm2 = **血条 `win[0x20]` 缓冲**。
4. **tm1 用 `TILE_BASE+TILE_OFFSET` 冒充官方线性** —— 官方 tm1 不碰 OFFSET；
   Init 每块清 `OFFSET=0` ⇒ 多字段叠印（设置页 / Bug H）。
5. **`us_mask` / mask 进仓库 = 引擎移植完成** —— 仅换画笔；**有 `v8_alloc_*` / 位图避让 = 未完成**。
6. **「tm1 上 v8 物理必需」挡画布路线** —— 与美版 gdb（设置 tm2 画布零分配器）及用户拍板冲突。

### 5.2 「真划界」验收标准（少一条都不算做成）

1. **入口**：预算挂在**当次窗对象**（`TextPrinter` / `gMenuWindow`），不是「全局带」。
2. **预算**：`2+w×h`，且 `w×h` 来源可证伪（美版孪生模板 / W0 FRAME / 场景表）。
3. **接框**：**同一次**开窗把「文字段结束 offset」交给框装载（= 美版 IWTD 返回值语义）；
   **用后清除 pending**，其它场景 `SetBaseTileNum` 不被改写。
4. **落址**：窗内 `start+2+row*w+col`（或官方等价）；tm1 画布路径 **无** v8 领号。
5. **回归**：设置页边框完整 + 能力页等未开画布场景不被误伤。

### 5.3 区别（防混淆）

> **美版**：`InitWindowTileData` **返回值** → 当次 `SetBaseTileNum(返回值)` → 装框。
> **假划界**：EWRAM 账本常驻 + **之后任意** `SetBaseTileNum(x)` 只要 `x∈[start,start+span)` 就改。
> 前者是**开窗契约**；后者是**跨场景水位**。禁止把后者说成前者。

## 6. 给这次路线选择的三条硬约束（从失败中提炼）

1. **日版窗口结构没有 `width/height`**（`0x18` 后直接是 `0x1A`）⇒ 官方 `tile = baseBlock + y*w + x`
   的 `w` 必须**从模板取或勘测**，不能凭空设。
2. **日版 `UpdateTilemap` 只写 2 个纵向表项**，无美版 `if(tilesWidth==2)` 写右列分支
   ⇒ **日版结构性不支持「一字占 2 列」**（这才是「必须 8 宽」的真正来源，
   **不是** blit 的 `cmp r7,#7`）。Wokann 的 16×16 直接搬来会**右半丢失**。
3. **`reference/` 是测试硬依赖**（`memory/2026-08-31.md:130`）——
