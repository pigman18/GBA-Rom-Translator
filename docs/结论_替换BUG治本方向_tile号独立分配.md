# 结论：替换 BUG 的治本方向 —— tile 号独立分配，而非绕过 tilemap

> 一份可直接转发给其他 AI / 协作者阅读的定论文档。综合了本项目（GBA 红宝石
> 日版 AXVJ00 汉化）对官方文本引擎的反汇编实证与 v6 渲染层现状。

---

## 1. 一句话结论

**替换 BUG 的病灶不在 `UpdateTilemap`（写屏幕位置那条腿），而在 tile 号从哪来
（写像素那条腿）。** 治本的办法不是"绕过 tilemap 直接画到屏幕"（硬件上做不到，
方向也偏了），而是**把 tile 号从官方每行清零的游标里摘出来，自己维护一个
高水位分配器，让每个字领到唯一的 tile 号**。tile 号一旦独立，每个字独享自己
的 tile，替换与叠加都不再发生。

---

## 2. 背景：GBA 上"画一个字"永远是两步，缺一不可

GBA 是 tile 模式（mode 0），屏幕上的每个 8×8 像素块，都是靠 tilemap 表项去
引用 VRAM 里某块 tile data 才显示出来的。所以"画一个字"恒等于两件事：

1. **写 tile data**：把字模像素存进 VRAM 的某块（charBlock 内某个 tile 号）。
2. **写 tilemap**：把"这块 tile 号"登记到屏幕对应的格子。

所谓"直接绘制到屏幕、绕过 tilemap"，唯一技术上可行的等价做法是切到 GBA 位图
模式（mode 3/4/5，直接写 framebuffer）。但宝可梦整屏的 BG 分层、OBJ、窗口都
建立在 tile 模式上，切过去等于毁掉全屏。**这条路在硬件上走不通，可以排除。**

---

## 3. 两条腿各自需要什么，哪条会出错

| | 需要什么 | 谁在管 | 现状评价 |
|---|---|---|---|
| 写 tile data | **tile 号** | 官方 `TILE_OFFSET` 游标 | ❌ 每行清零 → 复用 → 替换 |
| 写 tilemap | **屏幕位置** | 官方屏幕光标 `cursorX/Y/TileX/TileY` | ✅ 管得对，保留 |

- `UpdateTilemap`（官方 @0x080036DC）内部做的事是**忠实的**：拿官方屏幕光标算
  出"当前这格该写进 tilemap 的哪个位置"，然后把喂给它的 `tile` 号写进去。
  它管的是"字显示在屏幕哪"，这条腿官方管得**对**。
- 真正的病灶在第一条腿：`tile = base + TILE_OFFSET`。`TILE_OFFSET` 是官方维护
  的线性游标，**每行 `AddTextPrinter` 都会清零**。于是每一行都从 `base+0` 开始
  分配 tile 号，所有行复用同一批 tile——行 2 的字写进 `base+0` 就把行 1 的字
  盖掉了。**这才是替换。**

> 关键推论：就算绕过 `UpdateTilemap`、换成自己写 tilemap 表项，只要喂进去的
> tile 号还是 `base + TILE_OFFSET` 这套复用号，**替换照旧**——因为被盖的是
> tile data，不是表项。

---

## 4. 正解：tile 号独立 + 屏幕位置继续交官方

两条腿解耦：

- **tile 号**：从"官方每行清零的 `TILE_OFFSET`"换成"自己的高水位分配器"，
  每画一个字领一个递增的唯一 tile 号，写进 tile data。
- **屏幕位置**：继续交给官方光标（也就是继续调 `UpdateTilemap`）。

效果：tile 号独立 → 每字独享 tile → 既不替换、也不叠加，直接正确。

> 这对应本项目"v6 拍板"的设计目标（固定区间 + 高水位分配器）。注意：当前
> `chs_place` 的实际实现是"照抄官方定位模型"（`tile = base + TILE_OFFSET`），
> **并未真正落下这个分配器**，所以替换仍在。这是下一步要做的改动。

---

## 5. 关于"叠起来比替换好接受"

现状里 `blend_glyph` 混写原语被以 `startPixel=0, width=8` 调用（整列 8 像素
全重写），RMW 退化成"整块覆盖"。所以 tile 号一冲突，表现是**替换**而非叠加。

想让冲突时退化成"叠加"，需要改成**部分宽度 RMW**（一个 tile 里只写自己那几列、
留出别的字占的列）。但注意两点：

1. **这是兜底，不是正解。** "叠加"意味着两个字像素混在同一个 tile，屏幕上是
   两个字的墨迹糊在一起，看也看不懂。
2. **优先级**：先让 tile 号唯一（治本，替换直接消失）；"叠加"只作为"tile 空间
   不够用"时最后的降级手段。

## 6. 术语速查（供协作者对齐）

| 术语 | 含义 |
|---|---|
| tile data | VRAM 里存字形像素的块（charBlock），每 tile 32 字节（4bpp） |
| tilemap | 屏幕格子 → tile 号的映射表 |
| `UpdateTilemap` | 官方函数 @0x080036DC：写 tilemap 表项（管屏幕位置） |
| `TILE_OFFSET` | 官方线性游标（win 偏移 0x18），每行清零 |
| `TILE_BASE` | 窗口 tile 基准（win 偏移 0x16） |
| RMW / blend | 逐像素读改写混合写入；`blend_glyph_4bpp` 是复刻官方语义的像素原语 |
| 高水位分配器 | 自己维护、只增不减、随进程（不随每行）存续的 tile 号游标 |
