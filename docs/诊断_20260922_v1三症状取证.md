## 1. 引擎侧真值（本轮逐指令复核，可核）

`scripts/jp_dis.py` 对原盘 AXVJ00 逐指令读出：

### 1.1 一个字符 = 上下两个 map 格（8 宽 × 16 高）

`FontSubTable[0] @0x08003584`（tm1 的共享处理器）：
```
8003584: b500   push {lr}
8003586: 004a   lsls r2, r1, #1        ; r2 = glyph*2
8003588: 8ac1   ldrh r1, [r0, #22]     ; r1 = win[0x16] = TILE_BASE
800358a: 1852   adds r2, r2, r1        ; upper = TILE_BASE + 2*glyph  ← 恒偶
800358c: 0412   lsls r2, r2, #16
800358e: 0c11   lsrs r1, r2, #16
         …（后续 r2 += 0x10000 → lower = upper + 1；bl 0x080036DC）
```
`UpdateTilemap @0x080036DC`：
```
80036ec: bl 0x8003708                  ; GetCursorTilemapPointer(win)
80036f6: strh r4, [r0, #0]             ; map[(x,y)]   = arg1（| pal<<12）
80036f8: adds r0, #64                  ; +64B = +32 格 = 下一 map 行
8003700: strh r5, [r0, #0]             ; map[(x,y+1)] = arg2
```
→ **不推进任何游标**；引擎自己的字符恒占两行 map。

### 1.2 字号由 `win[0x0B]` 决定（不是 `win[0x0A]`）

`tm1 分派器 @0x0800360C`：
```
8003610: ldr r2, [pc,#24] @ (0x800362c) → 0x081BB3BC   ; = FontSubTable
8003612: ldrb r0, [r4, #11]            ; ★ win[0x0B] = fontNum
8003614: lsls r0, r0, #2               ; ×4 = 表项指针宽度
8003616: adds r0, r0, r2
8003618: ldr r2, [r0, #0]              ; FontSubTable[fontNum]
800361c: bl 0x81b12dc                  ; CallViaR2
8003620: ldrb r0, [r4, #27]; adds r0,#1; strb r0,[r4,#27]   ; cursorTileX += 1
```
⇒ **fontNum 是「字号档」的唯一键**，且**所有 fontNum 的步进都是 1 格 = 8px**。
⇒ v1 之前 `(void)fontSize` + 恒用 Middle，等于**把所有窗口都按 Middle 档排版**，
   这正是用户处方「fn=4 统一用 small」要修的东西。

### 1.3 `win` 字段（日版，≠ 美版；勿照抄 Wokann 汇编）

`+0A textMode / +0B fontNum / +0C COLOR_C / +0D COLOR_D / +0F PALETTE /
 +16 TILE_BASE / +18 TILE_OFFSET / +1A CUR_X / +1B CUR_TILE_X / +1C CUR_Y /
 +1D CUR_TILE_Y / +20 TILE_DATA`

## 2. 编译产物是「忠实 v1」（可核）

`hook/out/game.bin` 反汇编（`--adjust-vma=0x08800000`）：

* `chs_print @0x088000b0`：
  * `lsls r1,#19 / lsrs r1,#19` = `code & 0x1FFF`；`movs r3,#224; lsls r3,#5` = `7168` → 越界直接返回 ✓
  * `tpl[+0x0C]` 取 4 字节 = `TPL_TILE_DATA` ✓；越界回落 `0x06000000 | (tpl[+1]<<14)` ✓
  * 字库地址被编译器编成 **`movs r2,#0x94; lsls r2,r2,#13` (=0x128000) 再 `lsls r3,#7`** ⇒ `0x09400000 + gid*128`。
    **⚠ 所以「字面量池里搜不到 0x09400000」是正常的，不要据此判"没用到字库"。**
  * map 号被编成 `(521<<16) + (i<<17)` → `lsrs #16` = `521+2i`、`lsrs #11` = `(521+2i)*32` ✓
  * 64B remap 循环 = `v1_remap_byte`（高 nibble 取 `win[0x0C]`、低 nibble 取 `win[0x0D]`）✓
  * 收尾：`ldrb r6,[r4,#26]; bl UpdateTilemap; strb r6,[r4,#26]` + `win[0x1B] += 1` ✓
* `MapNamePopup_CalcLeftPx @0x088009f4`：`((80-w)>>1 + 4) >> 3`，`1≤w≤78` 外返回 0 ✓ 与源码一致。

⇒ **渲染层代码本身没有发现逻辑错**，字库/地址/map 几何/索引推进全部对得上。

  「无效」的只有长文本模块（道具说明/图鉴说明/剧情）——它们本就不走短语表。

## 4. 像素侧：屏幕上的字形**对不上任何字库**（可核，但成因未证）

脚本 `.tmp/an/m3.py`：把三张图游戏视口（左上 `(1,47)`，240×160）里每个 8×16 格
二值化后，与成品 ROM 的 `CHS_NORMAL/CHS_SMALL/CHS_MIDDLE` 三库 7168 字全搜
（Hamming 距离，128 位）：

| 图 | 有墨格数 | 最佳距离 |
|---|---|---|
| 背包列表 | 449 | d=4（且都是"墨量 4"的近似空格，匹配到空字形 gid=247） |
| 队伍对话框 | 760 | d=8 |
| 地图名牌 | 4503 | d=4（唯一 d=3 是 NORMAL 库的巧合） |

* **没有任何一格 d≤2**；把 8×8 图案正/反相拿去原盘与成品 ROM 全搜也是**零命中**。
* 背包列表逐行统计：**只有第 1 行有字，其余 6 行在面板内完全零墨**（不是颜色太浅，是真没画）。
* 字图呈「逐行累积错位」的斜向撕裂 + 孤立点。

⇒ 结论只能写到这一步：**屏幕上的字形既不是我们字库的直拷，也不是引擎日文字库的直拷**。
   要么是我们写进去之后被别的东西覆盖了，要么 map 指到了别处，要么大量汉字根本没进 `chs_print`。
   **这三种都需要运行期现场（窗口 tpl / TILE_BASE / map 内容 / 池砖内容）才能区分。**

## 5. 本轮已做修改（v1 + fontNum 分档）

`configs/POKEMON_RUBY_AXVJ00/hook/src/text/chs_render.c`：

1. 新增 `v1_pick_lib(win)`：`win[WIN_FONTNUM_REAL] == 4` ⇒ `ADDR_FONT_CHS_SMALL (0x09100000)`，
   否则 `ADDR_FONT_CHS_MIDDLE (0x09400000)`。**落实用户处方。**
2. `V1_KEY_CHS(gid, cb)` → `V1_KEY_CHS(gid, cb, small)`，用**空闲的 bit15** 区分字库档
   ⇒ 同一 gid 在 Middle 窗口与 Small 窗口**不会共用同一槽砖**（否则小档窗口的字会被大档覆盖）。
3. 64B 直拷几何、步进（恒 8px/格）、池、粘性表全部**不动**。

编译产物核对：`cmp win[0x0B], #4` → 相等走 `movs r3,#0x91; lsls r3,#20` + `orrs r7,#0x8000`；
不等走 `movs r3,#0x94; lsls r3,#20`。**与设计逐指令一致。**

## 6. 未证 / 下一步（需要现场）

用户诉求 ①「字体发虚」②「撞 UI 和自己」**成因未证**。静态已排除：
代码逻辑、字库地址、map 几何、索引推进、翻译数据、短语表、名牌 hook。

剩余可证伪假设（按优先级）：

1. **窗口参数在运行期与静态假设不符** —— 我们拿 `tpl[TILE_DATA]` 当写址、拿 `521+` 当 map 号。
   若该窗口实际用的 BG charBase ≠ `tpl[+1]`，写进去的砖与显示的砖就是两处 ⇒ 全屏碎片。
   *取证*：冷启动走到背包页，dump VRAM+EWRAM+I/O，读该窗口 `tpl / TILE_BASE / WIN_*`，
   再读该层 BGxCNT，比对 charBase。
2. **池与引擎字形缓存重叠** —— `0x08002950` 按模板 `[+8]` 返回槽数（fn 1/4 → 512、fn 2/3/5 → 256），
   即引擎缓存 = `[TILE_BASE, TILE_BASE + 2*slots)`。fn=1/4 的窗口若 `TILE_BASE=1` ⇒ `[1,1025)`，
   **整块包含我方池 `[521,1024)`**。本轮只捞到两个静态 TextPrinter（均为 **tm1 fn=3 TB=1**，
   `[1,257)`，不重叠），**背包列表窗与队伍名窗未捞到（应为栈上局部变量）**。
   *取证*：扫描 IWRAM + 更深扫 EWRAM，把这几个窗口的 fontNum 捞出来。
3. **大量汉字根本没走到 `chs_print`** —— 若 `TranslateHandleChar` 对某些字节返回 0，
   原版会用**引擎自己的字形缓存**画（`TILE_BASE + 2*glyph`），
   而该缓存在换串时被重新预取 ⇒ 旧字符变新字形 = "撞自己"；
   缓存里没有的 ⇒ 空白 = 第 2~7 行整行没字。
   *取证*：在 `PrintNextChar_Hook` 加一支**只计数**的探针（不改行为），
   统计"进 hook 的字节数 / 被消费数 / 落回原版数"。

> 取证一律走项目既有自测链路（见 `MEMORY.md`「自测链路」）：
> Qt mGBA 冷启动 + `.sav` + `arm-none-eabi-gdb -nx -batch` 的 `dump binary memory`。
> **不启动模拟器就无法区分 1/2/3**，故已请用户授权。
