# 6. 【第二轮】tm1 / tm2 / tm3 落址协议实证

> 用户决策：P2（保留 12px advance）+ 先验证 tm1/tm2/tm3。本节为验证结果，
> **并修正第 4 节的设计**。

## 6.1 tm1 @0x0800360D —— 纯查表，无分配器

`FontFunc_tm1`：`FontSubTable[win[0xB]](win, glyph)` 后 `win[0x1B] += 1`。
四个 sub 实现（`0x08003584` / `0x080035A0` / `0x080035C8` / `0x080035E4`）**全部只调
UpdateTilemap，零 VRAM 写入、零 `win[0x18]` 读写**：

```c
void FontSub_f0f3(win, glyph) {                    /* font 0/3 */
    UpdateTilemap(win, win[0x16] + glyph*2, win[0x16] + glyph*2 + 1);
}
void FontSub_f1f4(win, glyph) {                    /* font 1/4 */
    p = &FontType1Map[glyph*4];                    /* 0x081B34A8 */
    UpdateTilemap(win, win[0x16] + p[0], win[0x16] + p[1]);
}
void FontSub_f2f5(win, glyph) {                    /* font 2/5 */
    UpdateTilemap(win, win[0x16] + 0xD4, win[0x16] + glyph);
}
void FontSub_f6(win, glyph) {                      /* font 6 盲文 */
    p = &BrailleMap[glyph*4];                      /* 0x081B3884 */
    UpdateTilemap(win, win[0x16] + p[0], win[0x16] + p[1]);
}
```

**字模是 ROM 里预渲染好的 tile**，直接查表得到 tile 索引，不消耗窗口动态 tile 池。

## 6.2 tm2 @0x0800338C —— 缓冲区直绘指针

```c
void FontFunc_tm2(win, glyph) {
    sub_8003630(glyph, win[0x20], win[0xB], win[0xC], win[0xD], win[0xE]);
    win[0x20] += 0x40;          /* 2 tile；无 UpdateTilemap、无 win[0x1B] 推进 */
}
```
对应 `TPL_TILEMAP == 0`（无 tilemap，直写缓冲）。

## 6.3 tm3 @0x08003494 —— **grid 二维布局**

`FontFunc_tm3`：`sub_8003464(win, glyph)` 后 `win[0x1B] += 1`。
紧随其后的 `0x080034A8` 给出落址公式：

```asm
080034AA: ldrb r1, [r0, #0x1a]   ; win[0x1A]
080034AC: adds r1, #2
080034AE: ldrh r2, [r0, #0x16]   ; win[0x16]
080034B0: adds r1, r1, r2        ; r1 = base + (win[0x1A]+2)
080034B2: ldrb r2, [r0, #0x1b]   ; win[0x1B] cursorTileX
080034B4: adds r2, r2, r1        ; r2 = r1 + cursorTileX
080034B6: ldrb r4, [r0, #0x1c]   ; win[0x1C] cursorY
080034B8: ldrb r1, [r0, #0x1d]   ; win[0x1D] cursorTileY
080034BA: adds r4, r4, r1        ; rowY
080034BC: lsls r1, r4, #4        ; r1 = rowY*16
080034BE: subs r1, r1, r4        ; r1 = rowY*15
080034C0: lsls r1, r1, #1        ; r1 = rowY*30   ★ CHS_TILE_GRID_W
080034C2: adds r1, r2, r1        ; upper
080034C8: adds r4, #1
...                              ; lower = 同上 rowY+1
080034D6: bl  UpdateTilemap
```

```c
idx = win[0x16] + (win[0x1A] + 2) + win[0x1B] + (win[0x1C]+win[0x1D]) * 30;
UpdateTilemap(win, idx, idx + 30);
```

**与 `CHS_TILE_GRID_W = 30`（game.h:231）、`CHS_MODE2_ORIGIN_SHOP = 2`（game.h:244）
逐项吻合。** → **`scene_gctn_mode2` 的 grid 公式不是我们发明的，它就是在复现原生
`0x080034A8`。** 上一节"回归单一线性协议"的设想**不成立**。

## 6.4 四种协议汇总

| tm | 入口 | 落址公式 | 分配器 | 状态推进 |
|---|---|---|---|---|
| **tm0** | 0x08003569 | `win[0x16] + win[0x18]` | 线性追加游标 | `win[0x18]+=2; win[0x1B]+=1` |
| **tm1** | 0x0800360D | `win[0x16] + f(glyph)`（ROM 查表） | **无**（预渲染 tile） | `win[0x1B]+=1` |
| **tm2** | 0x0800338C | `win[0x20]`（缓冲指针） | 指针追加 | `win[0x20]+=0x40` |
| **tm3** | 0x08003494 | `win[0x16]+(win[0x1A]+2)+win[0x1B]+rowY*30` | **grid 二维** | `win[0x1B]+=1` |

# 7. 修正后的设计：按 textMode 分派，而非按场景猜

## 7.1 关键洞察

**`win[0x0A]`（textMode）已经直接编码了"用哪套落址协议"。**

`text_scene.c` 靠 template 地址、cursorY 数值、tileBase 区间去识别
summary / battle / shop / party / menu —— **本质上是在反推 textMode 和 grid 参数，
而这些信息本来就在 `win` 结构里**。

→ **不需要场景识别，只需要按 `win[0x0A]` 分派到 4 个已实证的桥接函数。**

## 7.2 四个桥接函数（各严格复现原生公式，只替换"绘制"一步）

```c
static void br_tm0(TextPrinter *win, u16 glyph)          /* 线性追加 */
{
    u16 t = win[0x16] + win[0x18];
    u8 *dst = tpl(win)->tileData + (t << 5);
    chs_or_native(glyph, dst, win);
    UpdateTilemap_PreserveCursorX(win, t, t + 1);
    win[0x18] += 2;  win[0x1B] += 1;
}

static void br_tm1(TextPrinter *win, u16 glyph)          /* 查表；中文无预渲染 tile */
{
    if (!is_chs(glyph)) { FontSubTable[win[0xB]](win, glyph); win[0x1B] += 1; return; }
    /* 中文：借用线性分配（原生 tm1 从不读写 win[0x18]，借用安全） */
    br_tm0(win, glyph);
}

static void br_tm2(TextPrinter *win, u16 glyph)          /* 缓冲直绘 */
{
    chs_or_native(glyph, (u8 *)win_u32(win, 0x20), win);
    win_set_u32(win, 0x20, win_u32(win, 0x20) + 0x40);
}

static void br_tm3(TextPrinter *win, u16 glyph)          /* grid */
{
    u16 t = win[0x16] + (win_u8(win, 0x1A) + 2) + win_u8(win, 0x1B)
          + (u16)(win_u8(win, 0x1C) + win_u8(win, 0x1D)) * 30;
    u8 *dst = tpl(win)->tileData + (t << 5);
    chs_or_native(glyph, dst, win);
    UpdateTilemap_PreserveCursorX(win, t, t + 30);
    win[0x1B] += 1;
}
```

其中 `chs_or_native(glyph, dst, win)` = 汉字 `chs_blit` / 其余
`sub_8003630(glyph, dst, win[0xB], win[0xC], win[0xD], win[0xE])`。

## 7.3 可删除项与保留项

**可删（scene 门控的全部启发式）**：`screen_summary` / `screen_battle` /
`screen_party_footer` / `screen_shop_desc` / `screen_shop_bag` / `screen_menu_mode2`
及其常量；`scene_should_use_linear`；`scene_apply_linear_floor`；
`scene_remap_tile` 需**先确认其规避的 tile 冲突是否仍存在**（见 7.4）。

**保留**：P2 方案下的半列相位（advance 12px），但只用于
**写 tilemap 表项时的列位置**，不再参与 tile 分配。

## 7.4 残余风险（必须实测）

1. **`scene_remap_tile` 防的是什么**：它把 `CHS_UI_ICON_TILE_LO..HI`、
   `CHS_PSS_B_VRAM_LO..HI`、`CHS_MENU_CURSOR_TILE` 重映射到 ALT 区。
   若这是"我们的 tile 写串了 UI 图标/光标"，回归原生公式后**可能不再需要**；
   若这是"原生 grid 本身就与 UI 图标区重叠"，则**必须保留**。需实测判定。
2. **tm3 下中文的 tile 来源**：grid 公式给出的是**屏幕位置索引**，
   它同时被当作 VRAM tile 索引（`dst = tileData + t<<5`）。
   中文若按 12px 步进，`win[0x1B]` 只能 +1，列位置与像素步进会脱节
   → **tm3 场景的 12px 相位如何表达，是 P2 最大的未决项**。
3. **tm1 借用 `win[0x18]` 的安全性**：同一窗口若混用 tm0/tm1 需验证。
