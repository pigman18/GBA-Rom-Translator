## 二、关键发现（四条硬事实）

### 1. 602-tile 画布物理上必然跨 charblock
`2 + 30×20 = 602 > 512`（单 charblock 容量）。日志里**每一条**预算行都带 `⚠跨charblock`：
- `tile[1,603) → 绝对VRAM=0x06008020..0x0600CB60 → cb2→cb3`
- 尾巴 91 tile 落在 cb3 `[0x000-0x05A]`。

这不是「找不找得到连续空闲」的问题，是 602 天生装不进单个 16KB charblock。

### 2. cb2 是分时复用的 scratch buffer（图集/网格都按场景重载）
cb2 `0x06008000` 占用随时间在三种状态间切换：
- **全空 / `[0x002-0x002]`**：无文本（大地图/纯战斗）。
- **`[0x003-0x15A]…[0x1FE]`（≈510 tile，近满）**：tm1 菜单图集 或 tm3 对话网格已加载。
- **`[0x001-0x062]`（≈98 tile）**：某局部文本态。

⇒ **图集不是常驻的**，菜单开→载图集，关→释放。cb2 本质是块按场景重载的文本 scratch 区。

### 3. tm1 与 tm3 时序严格互斥
textMode 游程序列（相邻相同合并）：
```
tm3×88 → tm1×237 → tm3×20 → tm1×104 → tm3×34 → tm1×85 → tm3×22
→ tm0/tm2×若干 → tm1×31 → tm2×12 → tm0×72 → tm2×34 → tm0×52 → tm2×34 → tm0×8 → tm3×32
```
tm1（菜单）与 tm3（对话）**永远分块出现、绝不交错**。⇒ 可共用同一片 cb2 画布。

### 4. tm1 有两个图集
- 主字体 fontNum=3 → cb2，197 窗。
- 大字体 fontNum=4（`tpl=0x081BB43C`，charBase=1 screenBase=30）→ cb1，14 窗。

## 三、tm1 落址机制（自反汇编）

`FontFuncTable[1] @0x0800360C`：
```asm
ldrb r0, [r4, #0xb]      ; win[0x0B] = 字形宽度选择器
lsls r0, r0, #2          ; ×4 索引
ldr  r2, [r0+table]      ; 取函数指针
bl   0x81b12dc           ; = bx r2 跳板（0x81B12DC 起是跳转表，mov r8,r8 是 Thumb NOP）
ldrb r0, [r4, #0x1b]; add #1; strb  ; cursorTileX+=1
```
⇒ tm1 是「图集内容寻址」：按字形宽度选合成器，把 tilemap 项指进预渲染图集，**不做逐字形重合成**。

与 tm3 的「网格重合成」（`base+cur_x+2+cursorTileX+30*(cur_y+cursorTileY)`）本质不同。美版四件套（开窗 2+w×h / 像素游标 / 位置落址 / 清窗）正是 tm3 那套**重合成**模型。

## 四、结论 / 决策

**禁止**直接 `us_win_open(win, start, 30, 20)` 给 tm1 开 602 画布——会撞：自身图集(cb2[1,513)) + tm3 网格(cb2[1,603)) + cb3 UI 图标区（正是 MEMORY 禁的「占段+抬水位」）。

**两条可行路线**：

### 路线 A（与 tm3 共用 602 画布，零新增 VRAM）
tm1 复用 tm3 的 602-tile 网格区域 `cb2[1,603)`，`us_win_open(win, 1, 30, 20)`。依据：发现 3（tm1/tm3 互斥）。
- 代价：tm1 从「图集寻址」改「网格重合成」，需把 glyph 源从预渲染图集换成字体 ROM 重合成（与 tm3 同路）。
- **唯一待确认**：菜单活跃时 cb3 `[0x000-0x05A]`（602 画布尾巴）是否空闲。现有 `_survey_cb_avoid` 签名去重粒度不够（把不同菜单子场景混进同一 DISPCNT/BG 签名），日志里 cb3[0x000-0x011] 时占时空，无法定论。

### 路线 B（缩画布，避开 cb3）
菜单窗实际 4–8 行高（W0-FRAME 几何：28×8 / 28×4 / 26×6 / 30×7…）。用 `30×16=482`（<512，单 cb 内）或按窗实际尺寸，彻底不碰 cb3。
- 代价：偏离美版「统一 30×20」，需逐窗定 h；但语义更贴合菜单实际高度。

## 五、下一步（按四步法）
1. **先定路线**：A 需补一次 `cb3[0x000-0x05A]` 在菜单活跃时的占用实测；B 可直接静态推。
2. 无论 A/B，下一步都是：把 tm1 的 glyph 合成源从「预渲染图集」接到「字体 ROM 重合成」，再挂 `us_win_open` + `us_gctn` 落址。
3. 实机截图验收（菜单页 → 翻页 → 标题大字）。
