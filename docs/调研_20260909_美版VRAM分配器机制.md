# 美版 VRAM 分配器机制（研读 pokeruby 源码）

> 2026-09-09。来源：`tools/pokeruby/src/menu.c` / `text.c` / `text_window.c` + `include/text.h`。
> 目的：搞清楚「复刻美版引擎、连 UI 都接管到 window」到底要移植什么，取代「测避让带 / 抬水位」两条死路。

## 一、美版 WindowTemplate（28B = 0x1C，含 4B 填充）

```c
struct WindowTemplate {
    u8  bgNum;            // BG 号
    u8  charBaseBlock;    // ★ tile data 的 charblock（写 BGCNT bits2-3）
    u8  screenBaseBlock;  // ★ tilemap 的 charblock（写 BGCNT bits8-12）
    u8  priority;
    u8  paletteNum;
    u8  foregroundColor, backgroundColor, shadowColor;
    u8  fontNum;
    u8  textMode;
    u8  spacing;
    u8  tilemapLeft, tilemapTop;   // tilemap 内偏移
    u8  width, height;             // 0x0D/0x0E = 图集预算/行距
    u8  *tileData;                 // ★ tile data 绝对 VRAM 指针 BG_CHAR_ADDR(charBaseBlock)
    u16 *tilemap;                  // ★ tilemap 绝对 VRAM 指针 BG_SCREEN_ADDR(screenBaseBlock)
    u32 maybeUnused;               // 4B 填充 → 28B
};
```

对比日版 AXVJ 模板（24B，无 charBaseBlock/screenBaseBlock/width/height/指针）——这正是要移植的根因。

## 二、美版 Window（0x30 字节）

关键字段（`include/text.h`）：`width@0x09` `height@0x0A` `cursorX@0x10` `cursorY@0x11`
`tileDataStartOffset@0x1A` `tileDataOffset@0x1C` `tileData@0x24` `tilemap@0x28` `template@0x2C`。

## 三、核心：链式分配游标（不是测占用，不是顶基址）

全局游标（EWRAM，`menu.c:42-45`）：
`gMenuTextTileOffset`、`gMenuTextWindowTileOffset`、`gMenuTextWindowContentTileOffset`、`gMenuMessageBoxContentTileOffset`。

`InitMenuWindowInternal(winTemplate, tileOffset)`（`menu.c:115`）是一条**单调递增链**：

```
gMenuTextTileOffset = tileOffset;                                   // 1. 游标起点（InitMenuWindow 固定传 1）
gMenuTextWindowTileOffset = InitWindowTileData(win, gMenuTextTileOffset);
                                    // 2. 分配文本图集 → 返回 startOffset + span
gMenuTextWindowContentTileOffset = TextWindow_SetBaseTileNum(gMenuTextWindowTileOffset);
                                    // 3. 分配框 tile → 返回 base + 9（框占 9 tile）
TextWindow_LoadStdFrameGraphics(win);  // 4. 装框图到 tileData + 32*base
gMenuMessageBoxContentTileOffset = TextWindow_SetDlgFrameBaseTileNum(gMenuTextWindowContentTileOffset);
                                    // 5. 分配对话框 tile → 返回 base + 14（对话框占 14 tile）
```

**每个函数的返回值 = 下一个空闲 tile 号**，调用方把返回值存回游标，下一个窗口用游标继续。
`InitVariableWidthFontTileData` 返回 `startOffset + 2 + width*height`（`text.c:1809`）。

## 四、所有权与生命周期

- 每次开菜单 `InitMenuWindow` → `InitMenuWindowInternal(winTemplate, 1)`：**游标从 1 复位**。
- 窗口的 `tileData` 指针 = 模板写死的固定 charblock（如 `gMenuTextWindowTemplate` = `BG_CHAR_ADDR(2)` = cb2）。
- ⇒ 美版把整块 tile data charblock 当作**窗口独占的 scratch buffer**：每次开窗从头线性分配，
  窗口生命周期结束整体作废，下次开窗重来。**从不问「哪里空」**。

## 五、三种做法本质对比

| | 测避让带 | 抬水位 | 美版分配器 |
|---|---|---|---|
| 定位方式 | 扫描 VRAM 哪里空 | 固定顶基址占一段 | 链式游标：上一段返回值 = 下一段起点 |
| 所有权 | 无 | 无（全局常驻） | 有：挂游标 + 窗口模板 |
| 生命周期 | 无 | 常驻 | 开窗复位游标、关窗整体作废复用 |
| 大文本 | 空闲带不够放（领航员） | 占死固定段 | 整块 charblock 线性分配，天然容纳 |

## 六、对日版移植的启示（下一步研读方向）

日版 AXVJ 缺的是：模板里的 `charBaseBlock`/`tileData` 指针 + `width`/`height`，以及
「分配游标 + 返回值即下一段起点 + 开窗复位/关窗作废」的生命周期。要复刻美版，等于把
这套**窗口→tile data 的分配器**整体引入，让 UI 文本窗口都走它，而不是在共享图集里找空位。
