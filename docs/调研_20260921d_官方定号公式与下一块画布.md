## 1. 官方定号公式（逐指令，`0x08002D1C`）

主文本包装 `0x08002D1C` 里，画第一个砖的那 6 条指令是决定性的：

```
8002d5c: ldr  r0, [pc, #76]   @ (0x08002DAC)   ; r0 = 字形位图源指针(ROM)
8002d5e: ldr  r3, [r7, #0]                     ; r3 = win->template
8002d60: ldrh r2, [r7, #22]                    ; r2 = win[0x16]  = TILE_BASE
8002d62: ldrh r1, [r7, #24]                    ; r1 = win[0x18]  = TILE_OFFSET
8002d64: adds r2, r2, r1                       ; r2 = TILE_BASE + TILE_OFFSET   ◀ 号
8002d66: lsls r2, r2, #5                       ; r2 = 号 × 32  (字节)
8002d68: ldr  r1, [r3, #12]                    ; r1 = tpl->tileData             ◀ 基址
8002d6a: adds r1, r1, r2                       ; r1 = tileData + 号*32          ◀ 目标地址
8002d70: bl   0x08003830                       ; blit(源, 目标, …)
...
8002d84: adds r1, #32                          ; 第二次 blit → 下一砖
8002d8e: movs r0, #4
8002d90: strh r0, [r7, #24]                    ; win[0x18] = 4  ← 每字 TILE_OFFSET 前进 4
```

**⇒ 公式（本次逐指令实证）：**

```
dst_addr = tpl->tileData + (win[0x16] + win[0x18]) * 32
号（层内）  = win[0x16] + win[0x18]
```

- `win[0x16]` **TILE_BASE**：**每窗口私有**，由调用方在 `InitTextPrinter(win, text, tile_base, x, y)`
  时传入 —— 是**静态常量**（`game.h` 记录的值：`0x90` / `0x190` / `0x1B8` …）。
- `win[0x18]` **TILE_OFFSET**：光标前进量，引擎自己维护（每字 +4）。

**这就是「位置定号」。号随光标走，不随字符身份走。**

**⇒ 官方引擎里没有「全局号池」这个东西。** 号 = `tileData`（每模板一个）+ 窗口私有偏移。
v8~v36 修的「全局池 / 水位 / 避让带 / 段表」全部建立在「存在全局占位区」这个**错误坐标系**上。

## 2. 引擎字模缓存（逐指令，`0x08002950` + `0x080029E0`）

### 2.1 配置侧 `0x08002950`

```
800299c: ldr  r0, [r3, #0]      ; r0 = *0x03000328 (活动模板指针，单例)
800299e: ldrb r0, [r0, #8]      ; r0 = tpl[+8] = font
80029a0: cmp  r0, #5 ; bhi → 返回 0
        ; 分派表 @0x080029B0，按 font 0..5 取入口
80029cc: movs r0, #0x80 ; lsls r0, r0, #2   ; font0/3 ⇒ 返回 512
80029d2: movs r0, #0x80 ; lsls r0, r0, #1   ; font1/2/4/5 ⇒ 返回 256
```

**⇒ 返回值 = 本窗口的「号需求量」：font0/3 要 512 号，其余要 256 号。**
（与 `scripts/analyze_ui_takeover.py` 里 `tm1 = 512·256` 的历史记录一致。）

调用点实测（`0x0806F006` / `0x080685CA`）：第二参数 `r1` **恒为 1**。

### 2.2 推进侧 `0x080029E0`

```
80029fa: ldrh r4, [r0, #0]                     ; r4 = *0x0300032E  (槽计数器)
loop:
8002a0a: ldr  r0, [r0, #0]                     ; tpl = *0x03000328  (活动模板)
8002a0e: ldrh r1, [r1, #0]                     ; tileBase = *0x0300032C
8002a14: bl   0x08002A50                       ; InitWindowTileData(tpl, tileBase, 槽号, …)
8002a18: adds r4, r4, #1
8002a1e: adds r0, r0, #16 ; cmp r4, r0 ; blt loop   ; 每帧只推 16 个槽
8002a28: adds r1, r1, #16 ; strh r1, [r0, #0]       ; 计数器 += 16
8002a32: cmp  (计数器<<16), 0x01000000 ; beq done    ; 到 0x100 收工
```

**⇒ 16 帧 × 16 槽 = 256 槽；`InitWindowTileData` 每槽写 2 砖 ⇒ 512 砖。**
**⇒ 写入范围 = `tileData + (tileBase + 槽号)*32`，tileBase≡1 ⇒ `tileData + [1, 513)`（整块 + 下一块头 32B）。**

### 2.3 三条硬性质

| 性质 | 依据 |
|---|---|
| **单例** | 活动模板指针 `*0x03000328` 只有一份 ⇒ **同一时刻只有一个块在被预取写** |
| **写满整块** | 256 槽 × 2 砖 = 512 砖 = 一个 char block |
| **只写一块** | 起点 `tileBase=1` 硬编码 ⇒ 从该块头 32B 开始，直线走完 512 砖 |

## 3. 53 条窗口模板 × 「下一块」容量核算

模板表真身：`0x081BB3DC .. 0x081BB8BC`，**53 条**，步长 `0x18`（字段：`+08` font、`+09` textMode、
`+0C` tileData、`+10` tilemap）。

由 §2.3「只写一块」直接推出：

> **我们的字模只要放在 `tileData + [513,1024)*32`（= 下一块），就永不被引擎预取覆盖。**
> 剩余唯一风险 = **同一页面的静态美术**（LZ77/RL/CpuSet 直接写固定 VRAM 地址）。

静态枚举（`lz77_own.py` 97 站点 + `scan_vram_cpu_assets.py` 5 站点，均带自证闸门）：

| 「下一块」 | 模板条数 | 该块空闲砖（**所有页面并集**的补集） | 最大连续段 |
|---|---|---|---|
| cb0 | 4 | 0 | — |
| cb1 | 24 | 0 | — |
| cb2 | 4 | 16 | `[488,503)` 15 砖 |
| **cb3** | **20** | **80** | `[128,192)` **64 砖** |
| OBJ 区 | 1 | 512 | — |

**注意 cb0/cb1 的 0 是「并集」造成的假象** —— 见 §4。

## 5. 方案：定号回到官方坐标系 + 画布用「下一块」

```
号（层内） = 513 + slot              slot ∈ [0, 512)   ← 我方私有槽表
写砖地址   = tpl->tileData + (513 + slot) * 32
tilemap    = 写同一个号 (513 + slot)  ← 与写砖同口径，不需要任何换算
```

### 5.1 为什么安全

- 引擎预取是**单例**且**只写一块**（§2.3）⇒ `[513,1024)` 永不被它覆盖。
- 剩下的唯一来源是**该页面的静态美术**，可静态枚举（§4），**构建期**定案。

### 5.2 为什么可持续（「加字不涨号」）

| 结构 | 号需求 | 加场景 / 加文字 |
|---|---|---|
| 避让带 / 水位 / 段表（v8~v36） | ∑(每块字数)，**无上界** | 线性增长 ⇒ 迟早不够 |
| **下一块画布（本方案）** | **512 砖，有上界** | **不涨号**（槽位轮换） |

容量（512 砖，见 §3）：16px 步进 **128 字**｜12px 跨字共享 **约 256 字**。
这正是「加多少场景都不会撞」的结构来源 —— 冲突来自「号随字数增长」，不来自「字变多」。

### 5.3 为什么不是「避让带的 2.0」

| | 避让带族 | 本方案 |
|---|---|---|
| 分区依据 | **采样/读回** tilemap、VRAM，推断"哪些号被占" | **官方自己的公式**：引擎写 `[1,513)`，故我方写 `[513,1024)` |
| 依赖 | 对别人行为的观测 ⇒ 漏「未写入」、误收「已死残骸」 | 只依赖**我方私有槽表** |
| 决定时机 | 运行时 | **构建期**（几何是算出来的，不是试出来的） |
| 加字 | 号线性增长 | 号不变 |

「账本」与「槽表」不是一回事：账本 = **探测外部占用**；槽表 = **管理自己拥有的槽**。
官方自己的 `glyphIdx` 就是后者（FE8 的 `InitTextFont(..., VRAM+0x1000, 0x80, 0)` + bump 分配器同理）。

## 7. 与旧结论的关系

| 旧结论 | 本次处置 |
|---|---|
| 「引擎字模缓存占整块，避让带族数学上无解」 | **保持**（§2.3 再证） |
| 「挪邻块每页都赤字」 | **修正**：那是「所有页面并集」的算法错误；按页面看 cb3 对 25/38 页整块空（§4） |
| 「charBase=2 页的唯一闭合几何 `[1,513)/[514,768)/[768,1024)`」 | **方向对，落点错**：不该用「层内 [514,768)」，应该用「**下一块**」`[513,1024)`，并把它当**私有槽区**（512 槽）而非固定段 |
| 「v8~v36 池子族」 | **判死**（坐标系错误：不存在全局占位区） |
