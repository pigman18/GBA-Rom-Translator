# 逆向笔记：官方文本引擎 tile 机制 与 图鉴列表名字互覆根因（2026-08-29）

> 来源：日版红宝石 ROM 反汇编（AXVJ，文件偏移 0 = 0x08000000）。
> 触发 BUG：图鉴列表 41~44 行全显示同一个名字（臭臭花），滚动时名字随重绘顺序漂移。
> 结论先行：**官方没有动态 tile 分配器**；tm1 每字符只写 tilemap 引用，`win[0x18]`
> 是 mode0 专用草稿游标，tm1 从不使用。我们的中文字形走 win[0x16]+win[0x18] 落址，
> 而官方每次 AddTextPrinter 都把 win[0x18] 清 0 → 图鉴每行都画进 tile 1..7 → 行间互覆。

## 1. TextPrinter 字段（日版实测）

| 偏移 | 含义 |
|---|---|
| 0x04 | state (u16) |
| 0x0A | textMode |
| 0x0B | fontNum |
| 0x0F | 调色板号（tilemap 写入时 `<<12`） |
| 0x10 | text 指针 |
| 0x14 | charIndex |
| 0x16 | tileBase (u16) |
| 0x18 | tileOff（**仅 mode0 使用**：窗口内草稿 tile 游标） |
| 0x1A/0x1B | curX / curTX（列指针） |
| 0x1C/0x1D | curY / curTY（tile 行） |
| 0x20 | mode2 专用：线性 VRAM 拷贝游标（u32） |

## 2. 打印路径（日版地址）

```
每行打印（图鉴等）: 0x0806F16C → 0x080030A8 → 0x08002CFC → 0x08002C68（初始化）
慢速任务:           0x08002E8C（每帧, state 0..10 跳表 0x08002EA8）
快速路径:           0x08002DE8；子打印(FD 展开) 0x08002DB4
每字符分发:         0x080032F8 → 函数指针表 0x081BB3A8 按 textMode:
                    [0]=0x08003569(mode0) [1]=0x0800360D(mode1)
                    [2]=0x0800338D(mode2) [3]=0x08003495(mode3)
```

### 0x08002C68（AddTextPrinter 初始化）写点
`win[0x10]=text, win[0x14]=0, win[0x16]=tileBase,` **`win[0x18]=0 @0x08002CA4`**,
`win[0x1A]=x, win[0x1C]=y` —— **每次行打印都清一次 tileOff**。

### win[0x18] 全部官方写点（0x08002800–0x08004A00）
| 地址 | 函数 | 写入 | 条件 |
|---|---|---|---|
| 0x08002CA4 | 0x08002C68 初始化 | **0** | 每次创建打印任务 |
| 0x08002D90 | 0x08002D1C 带边框打印 | 4 | 画 2 边框 tile 后 |
| 0x08003574 | 0x08003568 **mode0 每字符** | +=2 | mode0 打印字符 |
| 0x080039EC/0x08003A10/0x08003A1E | 0x080039D8 mode0 滚动换行 | 全局[0x03003250]*2+4 或 4 | 换行重置 |
| 0x08003BD2 | 0x08003BA8 清窗口文本区 | 4 | mode0 清空后 |
| 0x08004976 | FD 解析器辅助 0x08004958 | 变量 | 写全局打印器 0x03003270 的 +0x18 |

**tm1（mode1）字符路径完全不碰 win[0x18]。**

## 3. 官方 mode1 渲染路径（0x0800360D）

按 fontNum 查表 0x081BB3BC：
| 字体 | 处理函数 | tilemap 索引公式 |
|---|---|---|
| 0,3,6 | 0x08003585 | `tileBase + char*2` 与 `+1`（成对） |
| 1,4 | 0x080035A1 | `tileBase + 逐字宽表 0x081B34A8[char*2]` / `+1` |
| 2,5 | 0x080035C9 | `tileBase+212`（空白）与 `tileBase + char` |

tilemap 写入 0x080036DC（内含 0x08003708 定位）：
```
col = win[0x1A]+win[0x1B]; row = win[0x1C]+win[0x1D]
addr = 模板+0x10(tilemap) + (row*32+col)*2     ← 标准 32 宽 screenblock
entry = tile | (win[0xF]<<12)                  ← 上半 tile 写 row 行
addr += 64（下一 tilemap 行）                   ← 下半 tile 写 row+1 行
返回后 win[0x1B]++（列指针+1）
```
**官方 mode1 每字符零 VRAM 拷贝**：字形 tile 在窗口创建时由 0x080028BC 预渲染
（mode1+font3 → 0x08002AF4：256 字形 × 2 tile(8×16)，从 `tileData+tileBase*32`
开始 → tileBase=1 时占 tile 1..512）。空 tile 计算 0x080041BC：mode1 font{0,3,6}
→ tileBase+1。

## 4. 官方"动态"机制（均非通用分配器）

1. **mode2 线性 VRAM 游标**：0x0800338D 每字符 `bl 0x08003630`（画字形）后
   `win[0x20] += 64`（0x080033A6）。API **0x08002CC0(destVRAM, text)** =
   建一个 mode2 打印把字符串字形流式拷进调用方指定的 VRAM 区。**起点由调用方
   静态指定，引擎不管理冲突**。
2. **全局 16 槽字形游标** [0x0300032C]（槽基址）/ [0x0300032E]（游标）：仅
   0x08002950 置位、0x080029E0 消费（对 slot=游标..+15 逐个重画字形，游标 +=16，
   回绕 0x10000 报满），只在窗口系统初始化/收尾（0x080685E0、0x0806F01C）调用。
   是 16 槽轮转缓存维护，不是按需分配。
3. **0x08002950(win, tileBase)**：登记 tileBase 并返回消耗量（mode0/1 返回
   512/256，mode3 经 0x08002BD0 返回 tileBase+602）——纯登记，无分配。

**结论：官方文本引擎无动态 tile 分配器，全靠窗口创建时静态预渲染。**

## 5. 图鉴场景（只为解释碰撞，修复不依赖图鉴代码）

- 列表窗口模板 id 31 = 0x081BB784（font3、**mode1**、tileData=0x06008000
  charblock 2、tilemap=0x06007000 screenblock 28、pal 15）；模板表 0x081BB8D0，
  查找函数 0x08004228；场景初始化 0x0808C8C2 → 0x080027DC（选模板31）→
  0x0806EF78 → 0x0806F074：AddWindow（全局窗口 0x0202E658）→ **tileBase 强制
  写 1**（0x0806F08A）→ 0x080028BC 预渲染 512 tile（0x06008020..0x0600C01F，
  占满 charblock 2 除 tile 0，末 tile 溢入 charblock 3 首块）。
- 每行 = 独立一次 AddTextPrinter：0x0808EE30 → 0x0806F16C(x=18, y=row*2+1，
  行串缓冲 0x03004A50) → **每行走一遍 0x08002C68 清 win[0x18]=0**。
- 行清屏 0x0806F1A0（FillWindowRect），滚动动画 0x0808ED7C。
- 图鉴模板簇 0x081BB4CC–0x081BB8BC 共 25 个模板全 font3；详情/统计屏 tileData
  用 0x0600C000/0x0600F800（charblock 3）。
- 列表场景空闲 VRAM：tile 0（0x06008000-1F）与 tile 513..1023
  （0x0600C020..0x0600FFFF，约 16KB-32B）——详情屏开时 charblock 3 会被占用，
  但回列表会重走初始化全行重印。

## 6. 根因链（图鉴列表名字互覆）

1. 我们的中文字形经 chs_blit 落址 `tile = win[0x16](=1) + win[0x18](=0..6)`
   + col*2 + row_delta → tile 1..7。
2. 官方每次 AddTextPrinter（每行）清 win[0x18]=0 → **所有行用同一批 tile**。
3. 整屏打印完，各行 tilemap 表项指向同一批 tile → 全部显示最后画的一行
   （クサイハナ=臭臭花）；滚动重绘顺序变化 → 名字随"最后画的行"漂移。
4. 数据层（slot 表、日文名表）全程正确，错在渲染目的地无行间隔离。

## 7. 修复方向（tile 分配器，独立文件）

- hook 点（文本引擎内，非图鉴代码）：官方 0x08002CA4 清 win[0x18]=0 处。
  处理器：执行原清零 → 若 textMode==1 且窗口未登记（scene_tm1_lookup==NULL）
  且模板在分配配置表内 → win[0x18] = 分配段基址 - win[0x16]（使 chs_tile_num
  的 `win[0x16]+win[0x18]` 恰落在分配段）。
- 分配策略：**按行位置确定性分配**（slot = (curY_total>>1)&15，段基址来自配置表
  空闲区间，段宽 ≥ 单行最大字形数×4 tile）。无需持久游标、重绘幂等（同行同位
  重印覆盖同段）。
- 图鉴列表空闲区间：tile 513..1023（0x0600C020..）按 16 slot × 24 tile = 384
  ≤ 511 可容纳；单行 ≤6 汉字 ×4 tile = 24。
- 配置表只登记已验证场景（图鉴列表模板 31），未登记窗口行为不变（零回归面）。
