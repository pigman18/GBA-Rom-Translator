# 通用工程手册

> 适用于本仓库所有 GBA 汉化工程（红宝石 AXVJ、火红 BPRE 参照、以后的绿宝石等）。
> 游戏专有的地址/模块/补丁/bug 不在这里，在各 `docs/{gameId}/` 下。

---

## 1. 四条铁律

1. **协议只许加，不许改**。`F7 00 hi lo` 编码、`F7` 自由长度、`rows/redirects/tables` 写入模型、
   各 hook 返回契约（可印=1 / `FF`=0 / `FA·FB·FD·FE`=2 / `FC`=子结果）一律不动。
   要扩展就靠 hook 叠上去，不在协议本体加字段、改分组、改长度。
2. **动手前先考察 origin**。任何显示/行为问题，第一动作是看原版同屏长什么样、走哪条路径。
   硬要求：能回答「这段字是谁打的、打在哪、宽度怎么算、占位符/后缀从哪来」四问才允许写补丁。
   > 推论：先读自家 hook——很多「ROM 里的怪现象」其实是 hook 自己从 ROM 里捡了字符串。
3. **验收必须逐字读图**。墨量、像素统计、ASCII 降采样只能证明「有东西」，证明不了「字对」。
   必须用 `bot/` 驱动 mGBA、origin vs translated 同帧对照，逐字读出内容。
4. **向前修，不回滚**。方案定了遇崩溃就继续定位，修到能验收；不提议回滚。

另：**听命令**——用户指出的路径就是路径本身（「先读源码」「直接搜字节」「用金手指跳场景」「写 bot 实测」
都不是可选建议），先复述计划再动手，不自作简化。

---

## 2. 反过度分析护栏

目标是产出可验证结果，不是把推演当产出。三选一，违反即停：

- **三连卡死即停**：同一问题连续 3 次工具调用/长推理无产出 → 改做「最小可验证步骤」或「提问」。
- **能推进就先推进，歧义记账**：不阻塞的歧义记入 `docs/` 待办并用默认值继续。
- **面向输出，不面向正确**：先跑流水线/编译等真实结果，用输出验证替代脑内推演。

## 3. 环境（实测 2026-11-23）

| 工具 | 位置 |
|---|---|
| Python | `C:\Python314\python.exe`（3.14.7） |
| arm-none-eabi-gcc | `C:\Program Files (x86)\Arm GNU Toolchain arm-none-eabi\14.2 rel1\bin`（**不在默认 PATH**） |
| armips | `tools\armips.exe`（流水线内部调用） |
| mGBA | `tools\mGBA-0.10.5-win32\mGBA.exe`（bot 自动选） |
| Python 依赖 | `work\_pylibs`（click/httpx/rapidfuzz/capstone/PyYAML/Pillow） |

```powershell
$env:PATH="C:\Windows\System32;C:\Program Files (x86)\Arm GNU Toolchain arm-none-eabi\14.2 rel1\bin;$env:PATH"
$env:PYTHONPATH="$PWD\src;$PWD\work\_pylibs"
```

- 系统 `site-packages` 无写权限、`pip install --user` 被禁用 → 一律 `pip install --target work\_pylibs <pkg>`。
- **PATH 必须含 `System32`**：否则 `build.bat` 的 `findstr` 不可用，`game_syms.asm` 只剩表头，armips 因缺符号报错。

## 4. 标准流程（改代码 → 交付）

```powershell
# ① 取证记录（可选，不再拦构建；只用于追溯改动依据）
python scripts/build/evidence_gate.py --record static --detail "objdump 0x... <结论>"
python scripts/build/evidence_gate.py --record gdb   --detail "bot <场景> run <stamp>: 两侧命中 N"
python scripts/build/evidence_gate.py --record bot   --detail "bot <场景> run <stamp>: N 帧对，读档 PASS"

# ② 编译 C 钩子
cd configs\<GAME>\hook; .\build.bat

# ③ 打包
cd C:\code\GBA-Rom-Translator
python -m meowth full "roms\origin\<ROM>.gba" --seed-only --target zh-Hans -o "roms\outputs" --work-dir work

# ④ 静态验收
python scripts/verify/verify_output_rom.py

# ⑤ 场景采集 + 逐字读图
python bot\run.py <GAME> <scene> --save bot\scenes\<GAME>\saves\<save>.sav --gdb InitTextPrinter
```

- `build.bat` 不再跑取证闸门（2026-11-23 移除），直接编译；`evidence_gate` 仅作手动记录/追溯工具。
- 流水线只嵌入**现有** `hook/out/game.bin`，不自动编译 C——改了 `hook/src/**` 必须先跑 ②。
- 打包会覆盖 `roms/outputs/`；留旧版先复制到 `work/_backup/`。
- 不要在 `hook/` 原地 `armips main.asm`：`charmap.txt`/`graphic/fonts.s` 只在 `work/{gameId}/build/` staging 里齐。

## 5. 调试工具

```powershell
# 反汇编（GBA 是 raw binary；thumb 断点必须偶数地址）
arm-none-eabi-objdump -D -b binary -m armv4t -M force-thumb `
  --adjust-vma=0x08000000 --start-address=0x080032F8 --stop-address=0x08003390 `
  roms\origin\<ROM>.gba
```

| 工具 | 用途 |
|---|---|
| `bot/run.py --gdb <watch>` | 断点探针，落 `{side}/gdb_probe.log` |
| `bot/run.py --gdb-watch 0x0400000A` | Z2 watchpoint：谁写、写成什么 |
| `scripts/verify/verify_output_rom.py` | 产物 20 项静态检查（字体区/表区/ink bbox） |
| `scripts/verify/verify_mon_crypto.py` | 宝可梦加密/校验子自检 |
| `scripts/build/evidence_gate.py --status/--verify` | 取证记录（手动，可选） |

**符号表只作参考**：标 `UNVERIFIED/DISPROVED` 的必须反汇编复核（实测见过标错，见各游戏文档）。

## 6. 通用坑

| 坑 | 现象 | 处理 |
|---|---|---|
| `git show commit:file > f` | 中文变乱码 | `git checkout <commit> -- <path>` |
| 拿诊断构建当基线 | 得出「两版帧完全相同」的错误结论 | 比对前先对 `manifest.json` 的 ROM SHA256 |
| mGBA 以 `-g` 启动但 GDB 侧崩 | 模拟器挂住不退出 | `Stop-Process` 后重跑；先装好 PyYAML |
| 旧 ROM 截图 | 结论作废 | 一律核对 SHA 后再用 |
| 函数名当事实 | 旧名与实际行为不符 | 反汇编 + RAM 实测 |
