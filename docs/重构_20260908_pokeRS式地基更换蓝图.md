# 重构蓝图：整套更换为 pokeRS/pokeE 模型（2026-09-08，用户拍板）

> 用户原话：直接整套换成 pokeE 那套，当前工程不是标准项目，该换地基就换地基，大不了回滚。
> 回滚锚点：git `5f70593`（v8 验收态 + TMx 字号改造，check_rom_hook=True 可复现）。

## 0. 为什么换（一句话）

v8 的「每字领 3~4 个 tile 号 + 独立 tile 对」在共享 cb 里密度爆炸且撞 UI；官方/pokeRS/pokeE 模型把字形写成**窗口自留网格内的亚 tile mask 合并**——每行消耗的 tile 列数 = 行像素长度÷8，与每字 advance 无关（12px 一行 18 字占 27 列 < 28 列网格），物理上撞不了别人。

## 1. 目标架构（pokeRS 红宝石先例 + pokeE FRLG 增强）

```
官方 RenderText（每字循环，零改动）
  └─ DrawGlyphTiles(win, glyph, width) ← 入口 hook
       ├─ 非 0x01~0x1E 区间（含 6/0x1B）→ 原函数照旧
       ├─ 中文：peek text[textIndex] 低位 → glyphId=(hi_adj<<8)+lo
       │   ├─ 字库选择（用户拍板 2026-09-08，pokeE 原版双档制）：
       │   │     默认全部 → 大字体 pokeE 11×11（advance 12，16B/字 1bpp）
       │   │     fontNum==4 → 强制小字体 pokeE 9×9（advance 10，11B/字 1bpp）
       │   │     测试期直接用 pokeE bin（GB2312 双字节编码，glyphId=hi_adj*247+lo）
       │   │     中文标点 0x36~0x3E → PokePunctuationChs{Normal,Small}
       │   ├─ 1bpp 位流 → Convert1bppTo2bpp（16×16+右下阴影）→ 切 4 tile
       │   │   → 官方 DecompressGlyphTile×4 → gCurGlyph / 或 4bpp 直写
       │   ├─ 第 1 列：DrawGlyphTile_ShadowedFont @ GetCursorTileNum(win,0,0/1)
       │   ├─ UpdateTilemap；cursorX += 8
       │   └─ 第 2 列：同上 @ 新 cursor 位置
       └─ 返回后官方游标按 GetGlyphWidth 返回值推进（大 12/小 10）
  ├─ GetGlyphWidth hook：中文双字节 → 12（默认）/10（fn4）
  └─ GetStringWidth hook：中文按宽计 → 换行/居中正确
```

**v8 体系整体下线**：tile_alloc.c（三层探测+回卷+ours段表）、blend_glyph 领号写像素、
chs_print 自绘路径、InitTextPrinter 相位复位、FE..FF slot 段表机制。
**scene_cfg 字号表退役**：场景级 8px/16px 规则全部废除，唯一特例 = fontNum==4 强制小字体
（与我们 resolve_draw 现有「fn4 最高优先级」触发点一致，语义换成 9×9）。

## 2.5 W1 执行结果（2026-09-08 反汇编定论，改变施工方案）

**pokeRS 目标 ROM = 美版 Ruby**（其地址表与 AXVJ00 不符；pokeRS 带 LANGUAGE_ENGLISH
分支、gFont3LatinGlyphs@0x8EA2C44 为美版多语言字形区）。
**AXVJ00（日文 Ruby）文本引擎 = 等宽 tm1 图集系统，无美版 mask 引擎**：
- 全 ROM 搜索 sGlyphMasks 特征字节（width0/width1 行 96B 模式）= **零命中**
  → DrawGlyphTiles / DrawGlyphTile_ShadowedFont / GetGlyphWidth / GetStringWidth
  在 AXVJ00 中不存在。0822「AXVJ 无 GetGlyphWidth/GetStringWidth」定论**正确**。
- AXVJ00 已钉死的锚点（BL 反查 + 逐指令比对 pokeruby 源码）：

| AXVJ00 | 身份 | 证据 |
|---|---|---|
| 0x080036DC | UpdateTilemapHelper(win, upperNum, lowerNum)：tilemap[0]/[32] 写两格 | 反汇编逐指令 |
| 0x08003708 | GetCursorTilemapPointer(win)：tilemap 基址+(left+curX)+(top+curY)*32 | 同上 |
| 0x08003730 | GetGlyphTilePointers(fontNum 0-6 七路 switch, glyph, &up, &lo) | 同上 |
| 0x080033B4 / 0x08003630 | DecompressGlyph 双胞胎（7 路 switch → DecompressGlyphTile×2 填 64B） | 同上 |
| 0x08003830 / 0x080038A0 | DecompressGlyphTile 无阴影/含阴影（2bpp→4bpp 着色） | 调用图 |
| 0x0800338C | LoadFixedWidthGlyph+推进：解字形→win[0x20]，**win[0x20]+=0x40/字** | 同上 |
| 0x080034D4~0x080035DC | WriteGlyphTilemap_FontX 家族（tileNum=tileDataStartOffset+2*glyph，tm1 图集） | 同上 |

→ AXVJ 窗口网格游标 = **win[0x20] 运行指针**（每字 +0x40=2 tile， InitTextPrinter 复位），
  与美版 tileDataStartOffset+tileDataOffset 机制等价但更简单。

## 2.6 修订后的 W3 施工方案：把美版 mask 引擎移植进 AXVJ00

不换基 ROM（日文提取链保住），把 pokeruby 反编译的 mask 引擎核心移植成我们的 hook 模块
`chinese_glyph`（C 为主，编译进 game.bin，经 P01 桩进入）：

1. **sGlyphMasks[9][8][3]**：常量表整表照搬（pokeruby text.c L251~，进 ROM const）。
2. **struct GlyphBuffer + ApplyColors_ShadowedFont**：IWRAM 分配（game.ld 现有空隙，
   具体落点构建时定）。
3. **ShiftGlyphTile_ShadowedFont_Width0~8 全家**：位移函数表照搬（这是 mask 混合核心）。
4. **DrawGlyphTile_ShadowedFont**：照搬，dest=窗口网格 tile。
5. **DrawGlyphTilesChinese（ pokeRS 逻辑 + AXVJ 字段驱动）**：
   - 字形源 = pokeE 1bpp bin → Convert1bppTo2bpp（已通读）→ DecompressGlyphTile×4
     → 16×16 4bpp（宽 12/高 15 或宽 10/高 13）；
   - 双列写网格：col1=win[0x20]+0/+0x20，col2=+0x40/+0x60（mask 按
     startPixel=(win->left+win->cursorX)&7 与相邻字共享列）；
   - tilemap 写 4 格（0x36DC 调两次或手写 +2/+0x42 列）；
   - 推进：win[0x20] += 0x80（两列 4 tile），win->cursorX += 12/10，textIndex += 2。
6. **宽度链路**：AXVJ 无 GetGlyphWidth/GetStringWidth——自动换行宽度计算需查
   InitTextPrinter 的断行逻辑并 hook；FE 注入换行覆盖大部分场景（现有机制），
   居中场景 W4 逐个实测。
7. **fn4→小字体**：与现 resolve_draw 的 fn4 最高优先级一致，字形源切 9×9 bin
   （width=10/高 13）。

## 3. 验收（四步法，逐场景）

每场景：①静态（反汇编确认 hook 落点）②gdb（采 GetCursorTileNum 返回序列，验证
全部落在 win->tileData 网格内、无越界列）③实机截图（对话框/领航员/地图名/血条/
summary/设置页/华丽大赛）④结论入档。
预计效果：所有场景文字均画在窗口自留网格内；相邻字共享 tile 列；不再出现
「越走越乱」「撞血条/B键UI」类损伤；未适配场景文字保持日文原样。

## 4. 风险登记

- 🔴 AXVJ00 与 pokeRS 目标 ROM 版本不同，所有地址/字段偏移必须重验（W1）。
- 🔴 AXVJ 无 GetGlyphWidth/GetStringWidth 的 0822 定论若属实，宽度链路要自建调用点补丁。
- 非 DrawGlyphTiles 路径的文字（血条直写 tile）新模型覆盖不到，靠 W4 逐场景处置。
- 字号体系=两档制（大 11×11/12、小 9×9/10），scene_cfg 场景规则与 Middle 8×12 退役；
  居中场景（kMapInfoScene r3=13）与旧 16px 数字列（kPokeNavScene cur_x==4）行为变化
  需实机确认——数字/拉丁走官方单字节字体，混排行宽由 GetStringWidth hook 统一计算。
