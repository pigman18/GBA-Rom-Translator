## 一、这一步在干什么（一句话）

美版 `Text_LoadWindowTemplate` 的**第一行**就是 `UpdateBGRegs(winTemplate)`；**日版没有这个函数**。
它的实现（`tools/pokeruby/src/text.c:1735`，**static**）全文只有 4 行：

```c
static void UpdateBGRegs(const struct WindowTemplate *winTemplate)
{
    u8 bgNum = winTemplate->bgNum;                    // ← 模板第 0 字节，自带层号
    *gBGHOffsetRegs[bgNum] = 0;
    *gBGVOffsetRegs[bgNum] = 0;
    *gBGControlRegs[bgNum] = winTemplate->priority
                           | (winTemplate->screenBaseBlock << 8)
                           | (winTemplate->charBaseBlock  << 2);
}
```

**v10 层 2 = 把这一步补上（照抄，不是自创）。**

> 🔴 **重写要点（2026-09-11，用户指正）**：首版做的是「读模板 `screenBase` → 在 `BG0..3CNT` 里
> 找同值的那一层」—— **那是多余的猜测**：`bgNum` 就在模板首字段，官方原语直接用它。
> 现在定位**零扫描**：`bgnum = tpl[TPL_BGNUM]`。（`screenBase` 只是层被选中后的副产品。）

**S2 只做「定位」**：用 `bgNum` 找到该层，然后**只重写 `screenBase` 位、保留该层的
现有 `charBase` / `priority`** ⇒ **写回值与现值恒等 ⇒ 零回归**。
「把号/值换成分配器给的」是 **S3** 的事（S2 只把 S3 会写什么**记进轨迹**做风险预判）。

> 而实际采集习惯是**直接关 mGBA 窗口** ⇒ `gdb.cont` 抛 `GdbError` → `break` ⇒

- `--preset ui-takeover` 里的 10 个断点全在原版地址上，**不影响本步**；它只是
  提供一条已经在用的 gdb 通道。本步要看的核心是 `[BGMAP+]` / `[BGMAP]` 段。
- 本步**不需要重编 ROM 之外的任何东西**。

## 三、判据（5 条，全绿才进 S3）

| # | 判据 | 看哪里 |
|---|---|---|
| **0** | `ROM 指纹` 行是 **`✅ 注入区 0x08800000 有 hook 代码`** | 启动时（`接管点自检` 下一行） |
| 1 | 有 `[BGMAP+]` 行（或结算 `[BGMAP]`），且 magic **不是** 0 | 全程 / 日志末 |
| **2** | **交叉验证**：`bgNum` 定位的层 == 按 `sb` 扫描的层（`✅bgNum=sb扫描`） | `[BGMAP+]` 行尾 |
| 2′ | 已知模板落到**期望的层**（见 §四） | `[BGMAP+]` 行里的 `⇒ BGx` |
| 3 | 每条命中的 `CNT 0x????→0x????` **前后相同** | 行尾（S2 恒等 ⇒ 出现 `🔴写后变了！` 就是 bug） |
| 4 | 实机截图与 **S2 之前完全一致** | 见 §五 A/B |

**`[BGMAP+]` 行的格式**（新）：

```
[BGMAP+] tpl=0x081BB7B4 bgNum=0(BG0) sb=31 模板cb=0 ⇒ BG0(层cb=0) CNT 0x1F01→0x1F01  ✅bgNum=sb扫描 ✅cb一致
```

行尾可出现的标记：

| 标记 | 含义 | S2 判读 |
|---|---|---|
| `✅bgNum=sb扫描` | 两种定位法给出**同一层** | ✅ 期望如此 |
| `⚠bgNum→BGx≠sb扫描→BGy` | 层的 sb ≠ 模板 sb | ⚠ **以 `bgNum` 为准**（官方原语）；记录 |
| `sb扫描:无同sb层` | 没有任何层的 sb 等于模板 sb | · 正常（由 `bgNum` 兜住，正是重写的价值） |
| `✅cb一致` / `⚠cb差(…)` | 层 cb 与模板 cb 是否一致 | 差的那些 = S3 工单 |
| `🔴写后变了！` | CNT 写前后不同 | 🔴 **S2 失败**（不该发生） |
| `⚠该层未使能` | 命中层在 DISPCNT 里没开 | ⚠ 值得记录（窗口层未开？） |
| `⚠UBR会写0x????(≠现值)` | 照抄完整 `UpdateBGRegs` 公式**会改变**现值 | ⚠ = **S3 风险面**（不是 S2 失败） |

> 🔴 **判据 0 的地址修正（2026-09-11 二次采集）**：旧版读 `0x08000004` 起 64B 与 origin 比，
> **那是错的** —— 那 156B 是 GBA 头部的 **Nintendo logo（BIOS 校验用，任何 ROM 都逐字节相同）**
> ⇒ 该判据**必然**误报「原版」。现改为查注入区 **`0x08800000`**（`game.bin` 落点，
> 原版 8MB ROM 边界外 ⇒ 原版此处是 0x00/0xFF 填充、注入版此处是 hook 代码）。

任一条不过 ⇒ **别往下走 S3**：

- 判据 0 失败（`🔴 注入区 … 全 0x00/全 0xFF ⇒ 跑的是原版 ROM`）⇒ **最隐蔽的假阳性**：
  hook 一行没执行，截图当然「零回归」。换 `roms/outputs/…_translated.gba` 重采。
- 判据 1 失败（`[BGMAP!] 🔴 全程未读到任何轨迹`）⇒ `bg_remap` **根本没被调用**，
  最常见原因是跑的 ROM 不是本次打包的（或 `InitTextPrinter_Hook` 跳板没生效）。
  ⚠ 早期日志里的 `[BGMAP…] 轨迹尚未初始化（magic=0x00000000）` **不算失败** ——
  那是游戏刚启动、还没进文本窗口的正常状态。
- 判据 2′ 失败（日志出现 `🔴 … 期望 BGx(sbNN)`）⇒ **`bgNum` 取错了位**（模板布局假设错），
  层 2 要重来。
- 判据 3 失败 ⇒ 有东西动了 `charBase`/`priority`（不该在 S2 发生）。

> 交叉验证：`层2复算` 行是 Python 侧用**实机寄存器**独立算出的层。
> 它与 `[BGMAP+]` 的 `⇒ BGx` **必须一致**；不一致 ⇒ 不是「规则错」，
> 而是「hook 没按预期执行」（例如 CNT 在两次读取之间被官方改了）。

## 四、期望值

### 4.0 🔴 定位依据的修正（2026-09-11）

| | 首版（已废） | **现行** |
|---|---|---|
| 定位依据 | 模板 `screenBase@2`，扫 `BG0..3CNT` 找同值层 | **模板 `bgNum@0`**（照抄 `UpdateBGRegs`） |
| 依据性质 | **猜测**（同 sb 可能对应多层） | **官方原语**（模板直接声明用哪层） |
| 失败模式 | sb 跨时刻变层 ⇒ 期望表无法固定 | 无（模板 → 层是**确定函数**） |

⇒ 期望表现在是**模板的确定函数**，不再受「同一 sb 跨时刻变层」干扰。

### 4.1 期望表（`bgNum` 口径）

| 模板 | **`bgNum`** | `screenBase` | 模板 `charBase` | **应命中的层** | 层 `BGxCNT`（实测） | 归属场景 |
|---|---|---|---|---|---|---|
| `0x081BB7B4` | **0** | 31 | 0 | **BG0** | `0x1F01`（cb0） | 领航员 · 训练家名/列表 |
| `0x081BB7E4` | **3** | 30 | 0 | **BG3** | `0x1E03`（cb0） | 领航员 · 路线名 |
| `0x081BB49C` | 0 | 31 | 0 | BG0 | `0x1F01` | 对话 · tm1/font3 |
| `0x081BB43C` | 0 | 30 | 1 | BG0 | `0x1E06`（层 cb=**1**） | 与模板一致 |
| `0x081BB46C` | 0 | 31 | 2 | BG0 | `0x1F08`（层 cb=**2**） | 与模板一致（tm3 菜单） |
| `0x081BB5BC` | 0 | 30 | 2 | BG0 | `0x1E08`（层 cb=**2**） | 与模板一致（特性/能力页） |
| `0x081BB784` | 2 | 14 | 2 | BG2 | `0x0E0A` | 图鉴列表 |

> ⚠ 上表 `bgNum` 列中除 `B7B4`/`B7E4`/`B784` 外**均为 S2 前的静态推断**，
> 需本次实机用 `[BGMAP+]` 的 `bgNum=` 字段**逐个坐实**（这正是 S2 的另一产出）。
> 判据 2′ **只对 `B7B4`/`B7E4` 两条**硬校验（本场景稳定出现的那两个）。

### 4.2 两条交叉验证线索

| 线索 | 比较 | 期望 | 若不符说明什么 |
|---|---|---|---|
| ① | `bg`（`bgNum` 定位） vs `bg_by_sb`（`sb` 扫描） | 一致 | 层的 sb ≠ 模板 sb —— **以 `bgNum` 为准**；同时否掉了首版规则 |
| ② | `expect_cnt`（照抄完整公式） vs `cnt_before`（现值） | 一致（差异 0） | 模板 `priority`/`charBase` 与层现值不符 ⇒ **S3 会改变画面**，得先解释 |

> 线索② 是**顺带白拿**的：S2 不写完整值，但把「照抄会写什么」记下来 ⇒ S3 动手前就知道风险面有多大。

### 4.3 旧结论的处置（留痕）

| 旧结论 | 现状 |
|---|---|
| 「日版把模板 `charBase` 全填 0」 | 🔴 **错**（实测 0/1/2/3 都有） |
| 「日版引擎从不执行模板 `charBase`」 | 🔴 **也错**（S2 实测层 cb == 模板 cb **14/14**） |
| 「同一 `sb` 固定落在同一层」 | 🔴 **不成立**（`sb=15` 见 BG0/2/3）—— 但**换成 `bgNum` 口径后此问题消失** |
| 「模板 `screenBase` → 层」是定位规则 | 🔴 **降级**：`screenBase` 只是**副产品**，定位依据是 `bgNum` |
| 「S3 需要改 `charBase`」 | 🔴 **不需要**：官方本来就按模板配好了 `(sb,cb)` ⇒ S3 只换**号** |
| 「同 sb 内 cb 不统一 ⇒ 全挤在一块、必然互踩」 | 🔴 **推翻**：层跟着模板走，不是挤在一起。详见设计 §2.3 第二次修正 |
| 「容纳变少」的真机制 | ✅ `tile 号 ≥ 512 会跨到下一个 cb`（设计 §2.4） |

### 7.2 🔄 S2 重写（2026-09-11，用户指正后）—— 待重采

**为什么重写**：首版「按模板 `screenBase` 扫 4 个层找同值层」**本身就是猜**，而且被 §7.1 发现 2
直接证伪（同一 sb 跨时刻变层）。用户指出：美版原语 `UpdateBGRegs` 第一行就是
`u8 bgNum = winTemplate->bgNum` —— **模板自带层号，根本不需要扫寄存器**。

**改了什么**：

| 项 | 首版 | 重写后 |
|---|---|---|
| 定位 | 扫 `BG0..3CNT` 找 `sb` 相同层 | **读 `tpl[0]` = `bgNum`** |
